## 一、编码总览

本编码簿采用**双轨编码框架**，对每一篇UGC帖子的两套数据分别编码：

| 轨道 | 编码对象 | 编码单元 | 维度编号 | 核心问题 |
|------|---------|---------|---------|---------|
| **文本轨** | 帖文主体文字 | 语义片段（句子/短段落） | V0/V1/V2/V3/V5/V6/V7 | 用什么策略？调用什么资源？对目的地的哪些属性作何种表达？ |
| **视觉轨** | 帖子配图 | 单张图片 | V11–V15 | 画面呈现了什么？如何取景？人物如何出现？ |

文本片段须在内容编码前按统一规则固定：句末标点通常形成边界；同一列表中的独立攻略项分别成段；无标点长句只在主题或言语行为发生明确转折时切分。两位编码员编码相同的`seg_id`，不得自行改变边界；边界争议在试标阶段单独记录和裁决。

### 1.1 核心设计理念

v3.0将编码对象从“形象建构效果”调整为“目的地资源调用策略”；v3.1按国标将V2重构为两级编码；v3.2将原V4并入V3。本次校订进一步区分**原子判断、可共现标签和派生字段**：编码员只判断不能由其他字段推出的原子项；“无/其他”以及跨维度重复的信息由程序计算，避免人为制造互斥和重复劳动。

### 1.2 维度编号方案

| 编号段 | 轨道 | 维度 |
|--------|------|------|
| V0–V7 | 帖子级元数据 + 文本轨 | V0/V1/V2/V3/V5/V6/V7（共7个，V4已合并入V3-Layer2） |
| V11–V15 | 视觉轨 | V11/V12/V14/V15（共4个，V13已删除） |

### 1.3 互斥、共现与派生关系

| 维度 | 编码员直接判断 | 关系 | 程序派生 |
|------|----------------|------|----------|
| V1 内容策略 | `cs_inf`、`cs_edu`、`cs_emo` | 3个0/1原子项，可共现 | `cs_int = max(is_que,is_dir,is_soc)`；`cs_oth = 1`当`cs_inf/cs_edu/cs_emo/cs_int`均为0 |
| V2 目的地资源 | 9个Layer 2资源亚类 | 9个0/1原子项，可共现 | `rs_n`、`rs_r`由各自亚类OR聚合 |
| V3 语言功能与属性指向 | `at_has_info`、`at_has_eval`、`at_has_sug`；条件性`asp_*` | 语言功能3个0/1项可共现；属性指向仅在评价/建议时多选 | `at_non = 1`当三个语言功能项均为0；属性未指向目的地时不标`asp_*` |
| V5 互动信号 | `is_que`、`is_dir`、`is_soc` | 3个0/1原子项，可共现 | `is_non = 1`当三个原子项均为0；同时派生V1的`cs_int` |
| V11 视觉主体 | `visual_subject` | 5类互斥单选 | — |
| V12 视觉呈现 | `scene_context`、`shot_scale`、`viewpoint` | 三个相互独立的单选子字段 | — |
| V14 人物呈现 | `people_count`、`human_scene_interaction` | 人数单选；互动0/1 | — |
| V15 消费符号 | 4个0/1字段 | 可共现 | — |

跨维度边界如下：`CS-INF`只指面向旅行决策的实用信息，`AT-INF`指任何可核验的命题，因此知识阐释可以同时为`CS-EDU=1`和`AT-INF=1`；`CS-EMO`指感官或氛围渲染，`AT-EVL`指明确价值判断，二者可以分别出现或共现；`CS-INT`完全由V5派生，不再重复人工判断。`CS-OTH`、`AT-NON`和`IS-NON`均为各自维度的零向量，不作为独立模型标签。

## 三、文本轨：各维度操作定义

### V1 内容策略（片段级，3个原子项 + 2个派生项）

该片段以何种方式传递信息？

| 代码 | 标签 | 定义 | 触发特征 | 记录方式 |
|------|------|------|----------|----------|
| CS-INF | 信息提供型 | 提供可用于行程决策的事实、数据、攻略、路线或步骤 | 交通方式、价格、时间节点、操作步骤 | 编码员0/1判断 |
| CS-EDU | 知识阐释型 | 解释文化、历史、地理、非遗或地方知识 | “始建于”“传说中”“列入非遗” | 编码员0/1判断 |
| CS-EMO | 情感渲染型 | 通过感官描写或氛围语言营造体验 | 色彩、声音、气味、触感、氛围描写 | 编码员0/1判断 |
| CS-INT | 互动激发型 | 以提问、号召或社交触发推动受众参与 | 问号、@呼唤、“冲”“码住”“评论区” | 由V5派生 |
| CS-OTH | 其他/未命中 | 未命中上述四种策略 | 开场白、段落衔接、纯表情 | 零向量派生 |

同一片段可同时出现多个原子策略。例如”栈桥始建于1892年，傍晚海风吹过来很舒服”可同时编码`CS-EDU=1`与`CS-EMO=1`。CS-COM不再作为片段标签；商业意图由V6在帖子级记录。

**编码决策树**（辅助编码员判断，非互斥）：

```
该片段是否包含：
├── 行程决策信息（价格/时间/路线/步骤）  → CS-INF=1
├── 文化/历史/地理/非遗知识阐释        → CS-EDU=1
├── 感官描写/氛围语言/体验渲染          → CS-EMO=1
└── 以上均不显著                        → CS-OTH=1（程序派生）
```

**编码示例**：

| 原句 | INF | EDU | EMO | INT | OTH | 编码逻辑 |
|------|-----|-----|-----|-----|-----|----------|
| “青岛三日游路线：Day1栈桥->天主教堂->信号山” | 1 | 0 | 0 | 0 | 0 | 纯攻略信息 |
| “栈桥始建于1892年，是青岛最早的军事码头” | 0 | 1 | 0 | 0 | 0 | 历史知识 |
| “当我站在崂山顶看到云海的那一刻，眼泪直接下来了” | 0 | 0 | 1 | 0 | 0 | 情感渲染 |
| “栈桥始建于1892年，傍晚海风吹过来很舒服” | 0 | 1 | 1 | 0 | 0 | 知识+氛围（**共现**） |
| “你们觉得山东哪个城市的烧烤最好吃？” | 0 | 0 | 0 | 1 | 0 | 互动（由V5派生） |
| “嘿嘿，话不多说直接上干货” | 0 | 0 | 0 | 0 | 1 | 过渡寒暄 |

### V2 目的地资源（片段级，两级编码）

该片段调用了目的地的哪类资源来建构形象？按《旅游资源分类、调查与评价》（GB/T 18972-2017）设计。

**编码员只标注Layer 2（资源亚类）及对应证据片段，Layer 1由程序自动计算。** 九个亚类可共现，但标注界面分为“自然资源4项”和“人文资源5项”两屏，每个亚类均须有可定位的文本证据。

#### Layer 1：基本大类（程序自动计算）

| 代码 | 大类 | 计算规则 |
|------|------|----------|
| RS-N | 自然旅游资源 | RS-N = RS-N-GEO OR RS-N-WAT OR RS-N-BIO OR RS-N-CLI |
| RS-R | 人文旅游资源 | RS-R = RS-R-HIS OR RS-R-ARC OR RS-R-GAS OR RS-R-FOL OR RS-R-ACT |

#### Layer 2：资源亚类（编码员标注）

**RS-N 自然旅游资源（4个亚类）**

| 代码 | 亚类 | 定义 | 语义锚点 |
|------|------|------|----------|
| RS-N-GEO | 地文景观 | 山岳、岩石、地貌、洞穴、沙滩 | 泰山、崂山、蒙山、岩石、溶洞、沙滩 |
| RS-N-WAT | 水域风光 | 海洋、河流、湖泊、瀑布、泉水 | 大海、海滨、趵突泉、大明湖、微山湖 |
| RS-N-BIO | 生物景观 | 动物、植物、森林、花海 | 海鸥、荷花、古树、花海、森林 |
| RS-N-CLI | 天象气候 | 日出、日落、星空、云海、雪景 | 泰山日出、海滨日落、星空、云海 |

**RS-R 人文旅游资源（5个亚类）**

| 代码 | 亚类 | 定义 | 语义锚点 |
|------|------|------|----------|
| RS-R-HIS | 遗址遗迹 | 以历史价值或遗产身份被提及的遗址、古建筑、文物和历史街区 | 孔庙、蓬莱阁、台儿庄古城、古桥 |
| RS-R-ARC | 建筑设施 | 以当代使用功能被提及的建筑、景区设施、住宿、交通和公共服务设施 | 酒店、民宿、高铁、缆车、景区大门 |
| RS-R-GAS | 饮食文化 | 地方美食、特色饮品、餐饮体验 | 海鲜、青岛啤酒、鲁菜、煎饼、烧烤 |
| RS-R-FOL | 民俗风情 | 非遗技艺、民俗活动、节庆、宗教文化 | 非遗、潍坊风筝、道教、庙会、民俗表演 |
| RS-R-ACT | 旅游活动 | 户外运动、休闲体验、互动参与 | 骑行、露营、赶海、潜水、喂海鸥 |

**编码示例**：

| 原句 | N-GEO | N-WAT | N-BIO | N-CLI | R-HIS | R-ARC | R-GAS | R-FOL | R-ACT | 编码逻辑 |
|------|-------|-------|-------|-------|-------|-------|-------|-------|-------|----------|
| "泰山的日出太震撼了" | 1 | 0 | 0 | 1 | 0 | 0 | 0 | 0 | 0 | 地文+天象 |
| "栈桥的海真的太蓝了" | 0 | 1 | 0 | 0 | 0 | 0 | 0 | 0 | 0 | 水域 |
| "始建于1892年，是最早的军事码头" | 0 | 0 | 0 | 0 | 1 | 0 | 0 | 0 | 0 | 历史遗存 |
| "台东夜市人均30吃到撑" | 0 | 0 | 0 | 0 | 0 | 0 | 1 | 0 | 0 | 饮食文化 |
| "崂山的道教文化太震撼了" | 1 | 0 | 0 | 0 | 0 | 0 | 0 | 1 | 0 | 地文+民俗 |
| "在栈桥喂海鸥太开心了" | 0 | 1 | 1 | 0 | 1 | 0 | 0 | 0 | 1 | 水域+生物+历史+活动 |

`RS-R-HIS`与`RS-R-ARC`的边界按**句中被调用的属性**判断：强调年代、遗产或历史意义时标HIS；强调住宿、交通、服务或当代使用功能时标ARC；同一对象若在片段中同时调用两类属性，可以共现。

### V3 语言功能、情感方向与属性指向（片段级，可共现）

原V3与V4继续合并记录，但不再把信息、评价和建议强制互斥。一个片段可同时承担多种语言功能。

#### Layer 1：语言功能（3个原子0/1项）

| 代码 | 类型 | 定义 | 操作化标准 |
|------|------|------|------------|
| AT-INF | 信息性陈述 | 包含至少一个可核验的事实命题 | 可判断真假的时间、地点、属性、数据或知识陈述 |
| AT-EVL | 评价性表达 | 对目的地、设施或体验作出明确价值判断 | “美”“值”“贵”“拥挤”“失望”等评价词或等价表达 |
| AT-SUG | 建议/推荐 | 向受众提出行动建议、推荐或回避 | “推荐”“必去”“避雷”“千万别”等 |
| AT-NON | 其他/未命中 | 未命中信息、评价和建议三种V3功能；可能仍含由V5记录的提问或互动 | 程序派生，不由编码员勾选 |

例如”门票80元，很值得去”同时编码`AT-INF=1`和`AT-EVL=1`；”人很多，建议早上去”同时编码`AT-INF=1`和`AT-SUG=1`。这类共现正是后续分析对象，不再用优先级抹去。

**AT-EVL 亚类**（基于Russell, 1980情感环状模型）：

| 亚类代码 | 情感质量 | 唤醒度 | 愉悦度 | 典型表达 |
|----------|----------|--------|--------|----------|
| AT-EVL-ADM | 赞赏/惊叹 | 高 | 正面 | “太美了””震撼””绝了” |
| AT-EVL-SAT | 满意/舒适 | 低 | 正面 | “很舒服””很满意””超值” |
| AT-EVL-EXC | 兴奋/激动 | 高 | 正面 | “太刺激了””超爽””尖叫” |
| AT-EVL-DIS | 失望/不满 | 低 | 负面 | “有点失望””不如预期””一般般” |
| AT-EVL-FRU | 沮丧/愤怒 | 高 | 负面 | “太坑了””巨坑””气死了” |
| AT-EVL-NOS | 怀旧/感慨 | 混合 | 混合 | “怀念””物是人非””故地重游” |

#### Layer 2：情感方向（片段含AT-EVL或AT-SUG时标注）

**方向（单标签，编码员标注）**：

| 代码 | 含义 | 判定标准 |
|------|------|----------|
| POS | 正面情感 | 评价/建议中的情感倾向明确为正面 |
| NEG | 负面情感 | 评价/建议中的情感倾向明确为负面 |
| MIX | 混合/矛盾情感 | 同一句中既有正面又有负面评价 |
| NEU | 中性/不适用 | 片段无评价或建议时程序置为NEU |

`sentiment_val`不再被解释为未经人工标注的“情感强度”。模型训练后按校准概率派生：`sentiment_val = P(POS) - P(NEG)`，范围为[-1,+1]。该值是**净情感方向分数**，用于连续分析前须报告校准方法和测试集误差。

**编码示例**：

| 原句 | INF | EVL | SUG | 情感方向 | 理由 |
|------|-----|-----|-----|----------|------|
| “栈桥始建于1892年” | 1 | 0 | 0 | NEU（派生） | 可核验事实 |
| “门票80元，很值得去” | 1 | 1 | 0 | POS | 事实与评价共现 |
| “人很多，建议早上去” | 1 | 0 | 1 | NEU | 事实与中性建议共现 |
| “避雷！千万别去这家海鲜店” | 0 | 0 | 1 | NEG | 负面回避建议 |
| “风景美但管理差” | 0 | 1 | 0 | MIX | 正负评价共现 |
| “你们最喜欢哪里？” | 0 | 0 | 0 | NEU（派生） | 未命中V3三项，提问由V5记录 |

#### Layer 3：目的地属性指向（片段含AT-EVL或AT-SUG时条件标注）

本层回答“评价或建议究竟指向目的地的什么”。它**不替代V2资源分类**：V2记录被调用的旅游资源，`asp_*`记录被评价、被建议或被回避的目的地属性。一个片段可同时指向多个属性；例如“景色很美，但门票贵、人又多”同时标`ASP-RES=1`、`ASP-PRI=1`和`ASP-CRO=1`。

| 代码 | 属性指向 | 定义 | 典型线索 |
|------|----------|------|----------|
| ASP-RES | 资源/吸引物品质 | 对自然、人文、美食、活动等旅游资源本身的品质、吸引力或适游性作评价/建议 | 景色美、古迹震撼、美食一般、赶海值得 |
| ASP-PRI | 价格与性价比 | 对门票、餐饮、住宿、项目等价格、收费或性价比作评价/建议 | 门票贵、免费、性价比高、花冤枉钱 |
| ASP-SER | 服务与设施 | 对接待、讲解、排队服务、住宿/餐饮设施及其服务质量作评价/建议 | 服务差、讲解专业、酒店隔音差 |
| ASP-CRO | 拥挤与管理秩序 | 对客流密度、排队、秩序、运营管理或游览承载状态作评价/建议 | 人太多、排队久、管理混乱、建议错峰 |
| ASP-ACC | 交通与可达性 | 对到达、换乘、停车、步行距离、无障碍或路线便利性作评价/建议 | 地铁直达、停车难、交通不便 |
| ASP-HYG | 卫生与安全 | 对环境卫生、食品卫生、风险、安全保障或治安感受作评价/建议 | 厕所脏、海边危险、卫生堪忧 |

**排除规则：**（1）纯事实提及“门票80元”“有地铁站”但没有评价或建议时，不标属性指向；（2）只对创作者本人、平台或无关商品作评价时，不标属性指向；（3）`RS-R-ARC`记录“酒店/交通设施被作为资源提及”，`ASP-SER/ASP-ACC`记录“其服务或可达性被评价/建议”，二者可以共现，不能互相替代。

### V5 互动信号（片段级，3个原子项 + 1个派生项）

该片段是否包含激发受众互动/参与的信号？

| 代码 | 类型 | 定义 | 触发特征 |
|------|------|------|----------|
| IS-QUE | 提问 | 句子以问句形式出现 | 句末为问号 |
| IS-DIR | 直接号召 | 句子直接号召受众采取行动 | "冲""码住""必须去""推荐给你们" |
| IS-SOC | 社交触发 | 句子触发社交分享、认同、归属 | "小众""出片""朋友圈""打卡" |
| IS-NON | 无互动信号 | 三个互动原子项均为0 | 程序派生 |

三类互动信号可共现。例如“你们觉得怎么样？喜欢的话记得码住”同时编码`IS-QUE=1`和`IS-DIR=1`。V1的`CS-INT`由这三个字段的OR结果生成。

## 六、编码规则清单

### 文本轨编码规则

| # | 规则 | 说明 |
|---|------|------|
| 1 | **先原子、后派生** | 编码员只标V1/V2/V3/V5的原子项；`CS-INT`及各维度“无/其他”项由程序生成 |
| 2 | **宁缺毋滥** | 不确定时贴confidence=1-2并写备注 |
| 3 | **贴着文本** | 编码来自句子自身传达的信息，不过度推断 |
| 4 | **V2证据先行** | 标注9个资源亚类时记录对应证据位置；Layer 1由程序计算 |
| 5 | **资源≠语言功能≠属性指向** | V2判断调用了什么旅游资源；V3-L1判断片段承担什么语言功能；V3-L3判断评价/建议指向什么目的地属性 |
| 6 | **渲染≠评价** | 感官/氛围呈现归`CS-EMO`；明确好坏、价值或满意度判断归`AT-EVL`；二者可共现 |
| 7 | **情感方向的条件标注** | 片段含`AT-EVL`或`AT-SUG`时标方向；否则程序置为NEU |
| 8 | **平台语境** | 以V1定义为主、平台校准为辅 |
| 9 | **共现不是折中** | 每个原子项分别作0/1判断，不设置“主要标签”或人为优先级 |

### 视觉轨编码规则

| # | 规则 | 说明 |
|---|------|------|
| 1 | **画面优先** | 编码依据是画面本身，而非配文描述 |
| 2 | **主体面积优先** | 仅V11视觉主体在多个元素共存时按视觉突出度和面积判定 |
| 3 | **单图独立** | 每张图片独立编码 |

### 7.3 跨维度关联指标

箭头表示条件化方向，不表示因果传导。V1与V3均为多标签，因此矩阵同一行的比例之和不要求等于1。

**SRM_L1：策略→资源大类关联（4×2）**

```
SRM_L1[CS-X][RS-Z] = COUNT(segments with CS-X AND RS-Z=1) / COUNT(segments with CS-X)
```

**SRM_L2：策略→资源亚类关联（4×9）**

**SAM_L1：资源大类→语言功能共现（2×3）**

**SAM_L2：资源亚类→语言功能共现（9×3）**

**AAM：目的地属性→情感方向关联（6×3）**

```
AAM[ASP-X][DIR-Z] = COUNT(segments with ASP-X=1 AND sentiment_dir=Z) / COUNT(segments with ASP-X=1)
```

其中`Z ∈ {POS, NEG, MIX}`。AAM仅分析含评价或建议且存在属性指向的片段；它补足资源分类无法覆盖的价格、服务、拥挤、交通和卫生等目的地形象属性，不将条件共现解释为因果传导。

**COD：共现密度**

| 指标 | 公式 | 含义 |
|------|------|------|
| COD_n_r | SUM(rs_n × rs_r) / segment_count | 自然+人文大类同片段共现密度 |
| COD_ngeo_rhis | SUM(rs_n_geo × rs_r_his) / segment_count | 地文景观+历史遗存共现密度 |
| COD_inf_evl | SUM(cs_inf × at_has_eval) / segment_count | 实用信息策略+评价功能共现密度 |
| IFD | SUM(rs_depth) / segment_count | 平均资源融合深度（0-9） |

## 八、标注方案与模型验证

本研究采用神经网络辅助编码。人工信度与模型效度分开报告：前者检验编码规则能否被稳定执行，后者检验模型能否复现经裁决的人工金标。

| 阶段 | 文本轨 | 视觉轨 | 目的 |
|------|--------|--------|------|
| 阶段1：试标与规则冻结 | 从500条文本金标中先取100条，两位编码员独立标注；修订后对试标样本重编码 | 从视觉金标中抽取试标样本 | 识别构念边界并冻结规则 |
| 阶段2：金标建立 | 共500条，两位编码员全量独立标注、分标签计算信度并裁决 | 600张，两位编码员独立标注并裁决 | 建立可追溯金标；按作者分组切分训练/开发/锁定测试集 |
| 阶段3：主动学习 | 每轮约300条；主编码员标注，第二编码员复核全部稀有类/低置信样本及随机20% | 每轮约400张，采用同类质控 | 扩展训练集；不触碰锁定测试集 |
| 阶段4：模型验证 | 在阶段2预先锁定的测试集上报告逐标签Precision/Recall/F1及校准 | 同左 | 评估模型编码质量与下游指标偏差 |

文本多标签信度对每个原子二值标签分别计算Krippendorff's alpha（名义尺度）；两位编码员时可同时报告Cohen's kappa作为敏感性结果。集合级一致性可补充报告MASI距离版本的alpha。目标为`alpha >= 0.80`；`0.667 <= alpha < 0.80`只用于暂定分析并须复查分歧；低于0.667的标签不得直接进入模型训练。类别极不平衡时同时报告阳性一致率、阴性一致率和各类样本数，避免仅凭单一系数下结论。
