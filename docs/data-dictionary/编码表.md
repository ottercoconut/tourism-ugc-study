## 一、核心设计理念

### 1.1 从"感知端"到"生产端"的理论转向

v2.0 用游客感知理论（CAC三层次模型）编码创作者生产行为，存在理论错配。v3.0 将编码对象调整为"目的地资源调用策略"。这里的“策略”仅指成品UGC中可观察、可重复编码的功能性内容呈现模式，不表示创作者主动规划或意识到某种策略，也不据此推断受众效果。自v3.4.3起，所有进入编码记录表的字段均由编码员逐字段人工判断；字段间的逻辑关系仅用于试标复核和一致性审计，不得自动改写人工记录。

### 1.2 文本主轨与视觉辅助轨

文本轨是论文主研究完成的必要路径；视觉轨仅用于辅助图文协同研究，视觉数据或模型未通过质量门不得阻塞文本主研究。AI协同是测量扩展的方法核心：在固定人工预算下比较神经网络、主动学习和选择性复核的准确度—成本表现；“少量人工编码是否足够”由学习曲线和锁定评估回答，不作为预设事实。

### 1.5 唯一方法定位：理论导向的结构化内容分析

本研究的唯一正式分析方法是**理论导向的结构化内容分析（量化取向；theory-directed structured content analysis）**。这里的“理论导向”指初始类目来自目的地形象与内容生产相关理论、GB/T 18972-2017、既有研究和预先提出的研究问题；“结构化”指使用固定分析单位、预先定义的变量和值域、证据定位、编码员训练与一致性检验，将UGC转化为可比较的结构化记录。正式结果以类目频数、比例、共现、组间差异及其不确定性为主；校准期的语境解释与分析备忘只服务于测量工具开发，不构成并列的质性分析方法。

| 方法环节 | 本研究的唯一口径 |
|----------|------------------|
| 初始类目形成 | 以理论、标准、既有研究和研究问题作演绎式定义，不把样本中的高频词或模型聚类直接升格为类目 |
| 数据反馈 | 仅在共同校准与盲试标冻结前，系统登记框架遗漏、边界案例、反例、语境依赖和切分问题；由研究团队形成书面修订决定 |
| 正式测量 | 对冻结的`seg_id`、`img_id`和帖子级字段逐项编码；以编码簿版本、证据跨度、信度和裁决轨迹保证可复核性 |
| 分析产出 | 输出结构化变量、描述统计、共现与预设组间比较；模型只扩展已冻结字段的测量范围 |
| 方法取向 | 量化取向；校准中的材料阅读、问题登记和备忘是编码簿开发步骤，不另行产出质性主题 |
| 明确排除 | **不采用主题分析法**，不生成开放代码、候选主题、主题地图或“数据饱和”结论；V0—V11是分析类目/变量，不称为“主题” |

数据反馈的作用是检验并修订测量工具，不是另开一条归纳主题轨。任何新增、合并或改写类目都必须在正式冻结前完成并升版；冻结后若发现足以改变判定边界的问题，须暂停受影响字段、启动版本评审，并按第6节规则重编码，不能在正式数据中静默增加标签。

## 二、作者层与帖子级元数据

### V0 创作者画像（作者快照级）

V0同时保留两个不可互换的轴：`creator_role`回答“该平台账号在该证据窗口内以何种创作者角色持续活动”，`reach_tier`只回答“主页快照显示的可见粉丝规模处于哪一档”。KOL/KOC不是粉丝档位的别名；粉丝量、认证、单篇写作风格或单篇互动均不得单独推出角色。

**唯一观察单位**：`author_snapshot_id = platform + author_id + evidence_window_id`。同一作者在同一证据窗口内的多个目标帖只链接一次作者快照和一次裁决，不得复制为多个“作者样本”。跨平台账号只有在受限环境中存在可审计的强证据时才可附加同一`creator_entity_id`；同名、相似头像或相似简介不得自动合并。

**T0/T1隔离**：T0是作者角色证据包，允许包含主页资料、领域身份资料、固定历史窗口内且不属于研究目标集的帖子，以及这些历史帖中去数值化的关系性社群证据；T1是进入V3—V11编码和比较的目标帖子。T0与T1不得重叠。角色编码导出须遮蔽`follower_count`、`reach_tier`、点赞/收藏/分享/浏览等原始计数、一般平台等级、T1的V3—V11标签、T1互动结果、研究假设方向及角色模型建议；内容编码员不得查看任何作者链接、作者名、主页资料、`creator_role`、`reach_tier`或角色模型建议。内容编码回收后才由受限程序附加`author_snapshot_id`。

#### V0.4 原子证据代码与证据字段

V0金标采用“**双人独立完整人工编码 → 逐字段人工裁决 → 人工金标锁定 → 离线转换与模型训练 → 人工退出 → 程序处理非金标扩展样本**”的顺序。编码员直接填写`actor_scope`、`content_vertical`、五项EA原子证据、EA总体判断、两项CE条件、CE总体判断、SC、`evidence_status`和最终`creator_role`；人工期不运行自动派生公式、不展示模型建议、不让程序补值或纠错。全部人工字段逐一填写1—5级置信度及证据来源ID；任一字段置信度1—2必须写简短说明。

本研究总体是**个人旅游UGC创作者**。机构、品牌、景区和多人编辑账号保留在抽样审计中，但不属于个人角色比较总体。“相关领域”限旅游、旅行、目的地体验及直接服务旅行决策的本地餐饮、亲子、户外和生活方式内容。

| 人工字段 | 封闭值域 | 判断规则 |
|----------|----------|----------|
| `actor_scope` | PERSONAL_CREATOR / ORGANIZATION / MULTI_AUTHOR / UNCLEAR | 只允许单一自然人进入个人角色判断；机构与多人账号人工记NA，身份不清人工记UNK |
| `expert_authority_criterion_codes` | EA_CREDENTIAL / EA_DOMAIN_OCCUPATION / EA_DOMAIN_VERIFICATION / EA_INSTITUTION_AFFILIATION / EA_SPECIALIST_HISTORY / EA_NONE / EA_UNK | 前五项任一有证据即可支持EA=1；`EA_NONE`、`EA_UNK`与阳性代码互斥。一般认证、昵称自称、单篇专业表达或高粉丝不单独成立 |
| `consumer_experience_criterion_codes` | CE_FIRSTHAND_REPEAT / CE_PEER_ORIENTATION / CE_NONE / CE_UNK | CE=1须两项同时成立：至少两个不同日期的第一手旅行/消费来源，并持续面向同伴提供经验或建议。`CE_NONE`、`CE_UNK`与阳性代码互斥 |
| `content_vertical` | TRAVEL / FOOD / LIFESTYLE / GENERAL / OTHER / UNK | 只使用V0证据包，不使用本轮文本任务 |
| `ev_expert_authority` | 1 / 0 / UNK / NA | 编码员结合五项EA原子证据作总体人工判断；原子项与总体值都保留 |
| `ev_consumer_experience` | 1 / 0 / UNK / NA | 编码员结合两项CE条件作总体人工判断；两项同时成立才可记1 |
| `ev_sustained_creation` | 1 / 0 / UNK / NA | 编码员人工核对来源日期、数量与跨度；不由程序代填 |
| `evidence_status` | SUFFICIENT / INSUFFICIENT / OUT_OF_SCOPE | 编码员人工判断关键身份、时间与覆盖材料是否足以完成角色分类 |
| `creator_role_manual` | KOL_TYPE / KOC_TYPE / HYBRID / ORDINARY / UNK / NA | 编码员直接给出整体角色；该值进入双人比较与人工裁决，不是诊断性临时响应 |

`ev_sustained_creation=1`要求至少3个不同日期的旅游相关来源且最早、最晚相隔不少于30天。只有证据包同时满足这一日期/跨度门，并含可用主页资料或等价身份材料时，才允许编码`EA_NONE/CE_NONE`；否则相关组件必须为UNK。主页URL、简介或认证原文都缺失时，显示名本身不构成等价身份材料。

CI保留为`community_relation_status=UNAVAILABLE`。当前快照没有评论、作者回复或关系材料，本轮不补抓；CI不进入`evidence_status`、角色充分性或角色矩阵，也不得把点赞、收藏、分享、浏览、粉丝量或一般平台等级替代为CI。

`role_evidence_json`只引用证据manifest，每项含`field/source_type/source_id/source_published_at/captured_at/criterion_code/observation`。来源类型为`PROFILE`、`HISTORICAL_POST`或`OTHER`；字段记0由覆盖统计支持，不伪造“反证”。

#### V0.5 组件裁决与最终人工角色

下表是人工判断和人工裁决的一致性锚点，不是表内公式或程序派生规则。编码员先完成各组件，再直接填写整体角色；第三人对分歧组件和整体角色逐项裁决。人工裁决后的`creator_role_adjudicated`是金标终值：

| `creator_role_adjudicated` | 人工判断锚点 | 排除边界 |
|------------------------|----------|----------|
| `KOL_TYPE` | PERSONAL_CREATOR + SUFFICIENT；EA=1、CE=0、SC=1 | 高粉丝、一般认证或单篇专业表达不成立 |
| `KOC_TYPE` | PERSONAL_CREATOR + SUFFICIENT；EA=0、CE=1、SC=1 | 低粉丝、未认证或单次体验不成立 |
| `HYBRID` | PERSONAL_CREATOR + SUFFICIENT；EA=1、CE=1、SC=1 | 两种取向都须满足各自证据门 |
| `ORDINARY` | PERSONAL_CREATOR + SUFFICIENT；EA=0、CE=0、SC=1 | 只表示未落入三种型别，不得解释为“普通游客” |
| `UNK` | 身份不清、关键证据不足、SC=0，或EA/CE/SC任一未决 | 不进入KOL型/KOC型主比较；高粉但长期停更且材料稀少通常在此 |
| `NA` | ORGANIZATION或MULTI_AUTHOR | 不适用个人角色分类，不得写成UNK |

人工整体角色必须与组件和证据相互解释；若不一致，先标记复核，仍由人阅读原证据后解决，程序不得静默改写。当前标签明确写作`KOL_TYPE/KOC_TYPE`，以表明这是本研究试点操作类型而非普遍有效的社会身份分类。主结果必须单列HYBRID、ORDINARY、UNK、NA的数量与平台分布。

#### V0.6 角色试点、信度门与分析边界

1. 当前共同校准固定为25名作者：15名历史丰富、5名边界和5名随机；尽量覆盖五平台，每名最多展示5篇，超过时取最早、最晚和时间分位点。同一作者只能出现一次，不计算正式信度。
2. V0与同轮25篇V1—V6文本任务作者完全互斥。身份任务不含T1内容标签或互动结果；文本任务不含作者ID、主页、粉丝或角色。两份原始编码分别保存，裁决记录只追加，映射只在两任务均锁定后由受限程序使用。
3. 共同校准期间并行完成15—25篇KOL/KOC聚焦文献矩阵，逐项标明“文献继承”或“本研究自定义”；共同校准关闭后把规则修订为`role-pilot-v0.2`并冻结，不等待导师确认。
4. 冻结后另抽50名未讨论作者双人独立盲试标，至少包含10名KOL型候选和10名KOC型候选。对`actor_scope`、`content_vertical`、每个EA/CE原子项、EA/CE总体判断、SC、证据充分性及最终人工角色分别报告作者级Krippendorff's alpha、作者级bootstrap 95%置信区间、类别支持和混淆矩阵。任一核心字段`alpha < 0.80`、变异不足或出现系统边界分歧，返回共同校准；原盲试标不得冒充正式信度。
5. 正式比较只纳入证据充分的KOL型/KOC型作者，并按作者等权汇总内容指标。若当前库无法提供至少10名证据充分的KOL型与10名KOC型作者，规则试点仍可完成，但正式比较保持阻塞，不得用粉丝高低或缺失材料强行补组。
6. V0与V1—V11使用不同导出。现有内容Excel内部模板2.5保持不变；视觉V7—V11在文本主轨和身份试点之后另行共同校准，失败或延期不阻塞文本主论文与11月预印本。

### V1 明确商业披露（帖子级）

V1只记录帖子中是否存在可直接观察的商业披露，不根据正面程度、品牌出现次数或写作风格推断真实合作关系。

| 代码 | 定义 | 识别方式 |
|------|------|----------|
| 0 | 未观察到明确商业披露 | 帖文及其可用披露区域中未出现广告、赞助、合作、受邀体验或推广声明；该值不证明不存在商业关系 |
| 1 | 观察到明确商业披露 | 出现`#广告`、`#合作`、`品牌合作`、`赞助`、`受邀体验`、`推广`或语义等价的明确声明 |

#### V3 层级一致性规则

1. 任一正向子类为1时，其父类应为1；父类为1时，至少一个对应正向子类应为1。父类和子类仍分别人工判断，程序只报告冲突。
2. 同一父类内的具名子类可以共现；各`*_oth`子类只在同组具名子类均不适用时使用。
3. `is_non=1`时，`cs_int=0`且`is_que/is_dir/is_soc/is_oth`均为0；`cs_int=1`时`is_non=0`。
4. `cs_oth=1`原则上要求`cs_inf/cs_edu/cs_emo/cs_int`均为0。该关系用于复核，不自动生成或覆盖人工记录。

CS-COM不作为片段标签；明确商业披露继续由V1在帖子级记录。V3子类描述“策略如何实现”，不得代替V4的资源类型、V5的语言功能与情感或V6的目的地属性指向。

### V4 目的地资源（片段级，三级编码）

该片段调用了目的地的哪类资源来建构形象？按《旅游资源分类、调查与评价》（GB/T 18972-2017）设计。

**编码员同时标注Layer 1基本大类、Layer 2资源亚类，以及`RS-R-EVT=1`时直接涉及的Layer 3事件子类；层级逻辑只用于复核，不得自动补写或覆盖人工值。**

#### Layer 1：基本大类（编码员标注）

| 代码 | 大类 | 复核关系 |
|------|------|----------|
| RS-N | 自然旅游资源 | 与RS-N-GEO/RS-N-WAT/RS-N-BIO/RS-N-CLI的OR关系仅供复核 |
| RS-R | 人文旅游资源 | 与RS-R-HIS/RS-R-ARC/RS-R-GAS/RS-R-FOL/RS-R-REC/RS-R-EVT的OR关系仅供复核 |

#### Layer 2：资源亚类（编码员标注）

**RS-N 自然旅游资源（4个亚类）**

| 代码 | 亚类 | 定义 | 语义锚点 |
|------|------|------|----------|
| RS-N-GEO | 地文景观 | 山岳、岩石、地貌、洞穴、沙滩 | 崂山、信号山、浮山、沙滩 |
| RS-N-WAT | 水域风光 | 海洋、河流、湖泊、瀑布、泉水 | 大海、海滨、胶州湾、青岛湾 |
| RS-N-BIO | 生物景观 | 动物、植物、森林、花海 | 海鸥、荷花、古树、花海 |
| RS-N-CLI | 天象气候 | 日出、日落、星空、云海、雪景 | 崂山日出、石老人日出、海滨日落、海上日出、星空 |

**RS-R 人文旅游资源（6个亚类）**

| 代码 | 亚类 | 定义 | 语义锚点 |
|------|------|------|----------|
| RS-R-HIS | 遗址遗迹 | 以历史价值或遗产身份被提及的遗址、古建筑、文物 | 栈桥、八大关、天主教堂、德国总督府旧址 |
| RS-R-ARC | 建筑设施 | 以当代使用功能被提及的建筑、设施、住宿、交通 | 酒店、民宿、高铁、缆车、景区大门 |
| RS-R-GAS | 饮食文化 | 地方美食、特色饮品、餐饮体验 | 海鲜、青岛啤酒、鲅鱼水饺、烧烤 |
| RS-R-FOL | 民俗风情 | 非遗技艺、民俗传统、地方礼俗、宗教文化和方言；事件本身不自动构成本标签 | 非遗、道教（崂山）、海洋民俗、地方仪式 |

| RS-R-EVT | 节事与文体事件 | 依赖特定场次、赛期、节期、展期或届次而发生的赛事、演出、节庆、展会等时限性事件 | 青岛马拉松、足球比赛、演唱会、音乐节、青岛啤酒节 |

#### Layer 3：节事与文体事件子类（编码员标注）

仅当片段直接调用节事与文体事件资源时逐项判断；四个子类可以共现。`RS-R-EVT=0`时四项均记0，`RS-R-EVT=1`时至少一项为1；层级冲突只进入复核，不自动改写。

| 代码 | 子类 | 定义 | 语义锚点 |
|------|------|------|----------|
| EVT-SPT | 体育赛事 | 具有竞赛、赛会或职业/大众体育赛事属性的时限性事件 | 马拉松、足球赛、帆船赛、自行车赛 |
| EVT-PER | 演艺活动 | 以音乐、戏剧、舞蹈、曲艺或其他现场表演为核心的时限性事件 | 演唱会、音乐演出、舞台剧、现场演艺 |
| EVT-FES | 节庆会展 | 以节庆、庆典、主题节、展览或会议会展为核心的时限性事件 | 青岛啤酒节、灯会、文化节、博览会 |
| EVT-OTH | 其他节事与文体事件 | 已满足`RS-R-EVT`，但不属于上述三个具名子类的事件 | 颁奖活动、主题公共活动等边界事件 |

**边界规则**：

1. `RS-R-REC`与`RS-R-EVT`不按“是否收费”“是否由企业组织”区分。游船、潜水等即使由经营者组织，只要不依赖特定一次赛会、演出或节庆，仍归`RS-R-REC`；是否依赖具有明确时限的事件才是核心边界。
2. 同一运动的一般体验与赛事必须分开：“来青岛体验帆船”标`RS-R-REC`；“来看青岛国际帆船赛”标`RS-R-EVT + EVT-SPT`。片段分别调用两类资源时允许`REC`与`EVT`共现。
3. 音乐节可同时满足`EVT-FES`与`EVT-PER`；啤酒节本身标`EVT-FES`，只有片段还直接调用啤酒、美食或餐饮体验时才并标`RS-R-GAS`。
4. 节庆、赛事或演出不自动标`RS-R-FOL`；只有片段直接调用民俗传统、地方仪式、非遗或宗教文化时才并标`RS-R-FOL`。
5. `RS-R-HIS`与`RS-R-ARC`按句中被调用的属性判断——强调年代、遗产或历史意义时标HIS；强调住宿、交通、服务或当代使用功能时标ARC。

**编码示例**：

| 原句 | 主要V4标签 | 事件子类 | 编码逻辑 |
|------|------------|----------|----------|
| "崂山的日出太震撼了" | `RS-N-GEO + RS-N-CLI` | — | 地文与天象共现 |
| "坐船环游胶州湾" | `RS-N-WAT + RS-R-REC` | — | 水域资源与常态观光体验 |
| "来青岛体验帆船" | `RS-N-WAT + RS-R-REC` | — | 一般参与体验，不依赖特定赛事 |
| "来看青岛国际帆船赛" | `RS-N-WAT + RS-R-EVT` | `EVT-SPT` | 明确体育赛事 |
| "去凤凰之声看演唱会" | `RS-R-ARC + RS-R-EVT` | `EVT-PER` | 场馆设施与演艺事件共现 |
| "青岛啤酒节太热闹了" | `RS-R-EVT` | `EVT-FES` | 节庆名称本身不自动触发饮食文化或民俗风情 |
| "在啤酒节喝原浆、看乐队演出" | `RS-R-GAS + RS-R-EVT` | `EVT-FES + EVT-PER` | 饮食、节庆与演艺证据同时出现 |

**分析汇总**：`RS-R-ACT/rs_r_act = rs_r_rec OR rs_r_evt`仅在分析阶段计算，用于需要“全部活动资源”总量的描述。该汇总项不是人工标签，不记录置信度或证据跨度，不作为独立模型输出，也不计入`rs_depth`。v3.9.0及以前的人工`rs_r_act`只能说明片段曾被判为宽泛旅游活动，不能无证据地拆回`REC/EVT`或事件子类。

### V5 语言功能与情感（片段级，可共现）

V5回答“片段承担什么语言功能，以及评价或建议表达什么情感方向和强度”。信息、评价和建议不强制互斥；旧编号V3-L3目的地属性指向自v3.8.0起独立为V6，不再混入V5。

#### Layer 1：语言功能（3个实质项 + 1个排除项）

| 代码 | 类型 | 定义 | 操作化标准 |
|------|------|------|-----------|
| AT-INF | 信息性陈述 | 包含至少一个可核验的事实命题 | 可判断真假的时间、地点、属性、数据或知识陈述 |
| AT-EVL | 评价性表达 | 对目的地、设施或体验作出明确价值判断 | "美""值""贵""拥挤""失望"等评价词或等价表达 |
| AT-SUG | 建议/推荐 | 向受众提出行动建议、推荐或回避 | "推荐""必去""避雷""千万别"等 |
| AT-NON | 其他/未命中 | 未命中上述三种语言功能；可能仍含V3-CS-INT子项记录的提问或互动 | 编码员0/1 |

**AT-EVL 亚类**（基于Russell, 1980情感环状模型）：

| 亚类代码 | 情感质量 | 唤醒度 | 愉悦度 | 典型表达 |
|----------|----------|--------|--------|----------|
| AT-EVL-ADM | 赞赏/惊叹 | 高 | 正面 | "太美了""震撼""绝了" |
| AT-EVL-SAT | 满意/舒适 | 低 | 正面 | "很舒服""很满意""超值" |
| AT-EVL-EXC | 兴奋/激动 | 高 | 正面 | "太刺激了""超爽""尖叫" |
| AT-EVL-DIS | 失望/不满 | 低 | 负面 | "有点失望""不如预期""一般般" |
| AT-EVL-FRU | 沮丧/愤怒 | 高 | 负面 | "太坑了""巨坑""气死了" |
| AT-EVL-NOS | 怀旧/感慨 | 混合 | 混合 | "怀念""物是人非""故地重游" |

例如"门票80元，很值得去"同时编码`AT-INF=1`和`AT-EVL=1`；"人很多，建议早上去"同时编码`AT-INF=1`和`AT-SUG=1`。

#### Layer 2：情感方向（片段含AT-EVL或AT-SUG时标注）

| 代码 | 含义 | 判定标准 |
|------|------|----------|
| POS | 正面情感 | 评价/建议中的情感倾向明确为正面 |
| NEG | 负面情感 | 评价/建议中的情感倾向明确为负面 |
| MIX | 混合/矛盾情感 | 完成评价原子切分后，同一属性仍存在不可合理拆开的正负并存或矛盾立场 |
| NEU | 中性 | 片段含评价或建议，且表达真实中性、无褒贬方向的立场 |

新增`sentiment_judgeable`（情感方向可判定，0/1）：当片段不含评价或建议，或虽含评价/建议但无法从文本判定情感方向时，记为0，`sentiment_dir`记为`NA`；当其为1时，`sentiment_dir`必须人工编码为POS、NEG、MIX或NEU之一。NEU不得再承担“不适用”或“无法判定”的含义。

以两个独立的人工强度字段记录情感，不再使用单一`sentiment_val`：

| 字段 | 取值 | 人工判定规则 |
|------|------|-------------|
| `sentiment_pos_val` | 0 / 1 / 2 / NA | 无正面表达 / 一般正面 / 强正面 / 情感不可判定 |
| `sentiment_neg_val` | 0 / 1 / 2 / NA | 无负面表达 / 一般负面 / 强负面 / 情感不可判定 |

当`sentiment_judgeable=0`时，两字段均记NA；POS对应`pos=1或2, neg=0`，NEG对应`pos=0, neg=1或2`，NEU对应`pos=0, neg=0`，MIX对应`pos=1或2, neg=1或2`。强度2仅用于明确的强烈情绪、显著强化词或极端评价；其余明确方向表达记1。后续若需净方向，仅在分析阶段计算`pos - neg`，不得覆盖这两个原始人工字段。

### V6 目的地属性指向（片段级，4个实质父类 + 12个子类 + 1个其他项 + 1个适用性状态）

V6回答“评价或建议究竟指向目的地的什么属性”。V6标签只记录属性对象，不携带正面或负面方向；方向与双向强度由同一评价原子片段的V5字段记录。V6不替代V4资源分类：V4回答“调用了什么旅游资源”，V6回答“对目的地的什么属性作出评价、建议或回避”。

#### V6适用性状态

`asp_applicable=0`时，V6父类、子类和`asp_oth`均人工记为`NA`，不得伪造为负例；`asp_applicable=1`时，这些字段逐项记录0/1，且至少一个具名子类或`asp_oth`为1。适用性本身不由V5字段自动生成，跨维度关系只用于复核。

#### V6层级与跨维度规则

1. V6父类、子类、`asp_applicable`和`asp_oth`均由编码员判断并由模型逐字段输出；程序只报告冲突，不自动生成或覆盖记录。
2. 任一V6子类为1时，对应父类应为1；父类为1时，至少一个对应子类应为1。父子关系只用于一致性审计与模型层级损失。
3. 四个父类可以共现；同一父类内的子类也可以共现，但属性或方向切换已触发切分时，应分别落在不同`seg_id`。
4. `asp_oth=1`仅表示存在框架未覆盖的目的地属性，不表示无评价、无建议或无法判断。
5. 纯事实提及“门票80元”“有地铁站”但没有评价或建议时，`asp_applicable=0`；只评价创作者本人、平台或无关商品时同样记0。
6. V6标签保持方向中立。“卫生好”和“卫生差”都编码`asp_hyg=1`，其正负方向分别由V5的`sentiment_dir`与双向强度记录，不建立`asp_hyg_pos/asp_hyg_neg`等重复标签。

#### 评价原子片段切分规则

1. **属性切换必切**：评价或建议从一个V6子类切换到另一个子类时，在连接词或标点处切分。
2. **方向切换必切**：同一属性由正面转为负面、由负面转为正面，或不同属性分别承载不同方向时切分。
3. **同属性同方向不切**：同一属性下的同方向并列、递进或补充说明保持一个片段，如“厕所干净、明亮，而且没有异味”。
4. **一般共现不触发切分**：仅因V3、V4或V5多个标签可以共现，不机械增加切分；切分只服务于保持“一个评价原子片段内的属性—方向绑定可解释”。
5. **边界先于编码冻结**：切分程序在标注前固定`seg_id`；编码员不得自行拆并片段，无法由规则唯一裁决的情况进入切分问题登记。

**切分与编码示例**：

| 原句 | 固定片段 | V5情感 | V6编码 | 理由 |
|------|----------|--------|--------|------|
| “景色很美，但厕所很脏” | “景色很美” / “厕所很脏” | POS / NEG | `asp_exp+asp_res` / `asp_wel+asp_hyg` | 属性和方向同时切换，必须切分 |
| “服务很热情，不过酒店隔音很差” | “服务很热情” / “酒店隔音很差” | POS / NEG | `asp_sup+asp_ser` / `asp_sup+asp_fac` | 子类和方向切换，必须切分 |
| “门票虽贵，但总体很值得” | “门票虽贵” / “总体很值得” | NEG / POS | `asp_sup+asp_pri` / `asp_sup+asp_pri` | 同一子类方向切换，必须切分 |
| “人太多，排队也很久” | 不切分 | NEG | `asp_ops+asp_cro` | 同一属性、同一方向的补充描述 |
| “厕所干净、明亮，而且没有异味” | 不切分 | POS | `asp_wel+asp_hyg` | 同一属性、同一方向的并列描述 |
| “栈桥始建于1892年” | 不因V6切分 | NA | `asp_applicable=0`，其余V6字段NA | 只有事实命题，没有评价或建议 |

## 四、视觉轨：各维度操作定义

视觉轨对帖子的每一张配图进行编码。编码单位：单张图片。

**编码原则**：
1. 每张图片独立编码，不因上下文图片而改变对该图本身的判断
2. 当画面包含多个元素时，选择视觉上最突出、面积占比最大的元素作为编码依据
3. 仅当品牌/标识在画面中清晰可辨时才编码消费符号

### V11 可见对象状态（图片级，10个条件性原子项）

V11回答“画面中与目的地体验有关的对象呈现出什么可直接观察的状态”，不回答“这张图片整体是正面还是负面”。编码员须分别判断以下原子项；同一状态轴的正向与负向字段彼此独立，若画面不同区域或对象同时提供充分证据，可以同时记1，以保留混合状态。

| 状态轴 | 代码 | 字段 | 标签 | 纳入规则 | 关键排除 |
|--------|------|------|------|----------|----------|
| 设施维护 | VSC-FAC-POS | `vis_fac_condition_pos` | 设施完好/维护良好 | 设施主体清晰可见，且存在完好、维护良好或功能状态正常的直接证据 | 豪华、新颖、价格高或拍摄精美本身不足以判1 |
| 设施维护 | VSC-FAC-NEG | `vis_fac_condition_neg` | 设施破损/失修 | 出现破损、严重老化、关键部件缺失或明显无法正常使用的设施证据 | 历史建筑的年代感、风化质感不自动视为失修 |
| 卫生整洁 | VSC-HYG-POS | `vis_hyg_condition_pos` | 干净整洁 | 相关区域覆盖充分且清晰，并呈现干净、整洁、无明显垃圾、污渍或霉斑的状态 | 远景中“没有看到垃圾”或因裁切未显示地面不足以判1 |
| 卫生整洁 | VSC-HYG-NEG | `vis_hyg_condition_neg` | 脏乱/不卫生 | 出现垃圾、污渍、积水、霉斑、废弃物或明显不卫生处理方式 | 单纯陈旧、色调暗或画面噪点不足以判1 |
| 现场秩序 | VSC-ORD-POS | `vis_order_condition_pos` | 秩序清晰 | 服务、排队、市场或交通空间中存在排列有序、动线清晰、通道无明显阻塞等证据 | 无人场景或人数少本身不足以判1 |
| 现场秩序 | VSC-ORD-NEG | `vis_order_condition_neg` | 杂乱/秩序混乱 | 出现杂乱堆放、通道堵塞、无序排队或明显现场混乱 | 人多、画面拥挤或热闹氛围本身不足以判1 |
| 环境维护 | VSC-ENV-POS | `vis_environment_condition_pos` | 环境维护良好 | 自然或公共环境呈现维护良好、生态完整或修复到位的直接证据 | 风景美、天气好、滤镜鲜艳或构图漂亮不足以判1 |
| 环境维护 | VSC-ENV-NEG | `vis_environment_condition_neg` | 污染/环境退化 | 出现污染、植被破坏、岸线或公共环境明显退化等直接证据 | 季节性枯黄、正常潮汐或阴天不自动判1 |
| 可见安全线索 | VSC-HAZ | `vis_hazard_present` | 可见危险源 | 出现湿滑无防护路面、破损护栏、裸露电线、明显坠落或碰撞风险等可见危险源 | 不据此推断事故概率，也不把刺激性活动自动视为危险 |
| 可见安全线索 | VSC-PRO | `vis_protection_present` | 可见防护措施 | 出现护栏、警示标志、救生设备、隔离设施或其他清晰可辨的防护措施 | 未出现防护措施不得反推场景不安全 |

**条件状态规则**：

1. 先判断该状态轴是否被画面触发。没有相关对象、相关区域未进入画面，或可见范围不足以评价该轴时，成对字段均记`NA`。
2. 状态轴适用且画面足以判断时，各原子项分别填`1`或`0`。`0`只表示本标签未成立，不代表相反标签必然成立。
3. 共同校准期若现行规则或画面证据无法支持唯一判断，填`UNRESOLVED`并登记低置信备注；正式冻结后是否允许`UNK`由V11专门裁决决定。
4. 正负字段可以同时为1，例如酒店大堂主体整洁但角落存在垃圾；不得强制抵消、择一或计算“净正负”。
5. V11不得由V7主体、V10消费符号、滤镜色彩或文本情感自动派生，也不得用于推断服务态度、食物味道、住宿舒适度、满意度或整体目的地质量。

V11当前用于视觉描述、质量审计及候选图文属性方向匹配；其正式假设、聚合方式与模型发布门在视觉人口和独立信度冻结前均为`DEFERRED`。

## 五、编码记录格式

### 5.0 V0作者表（与内容编码表分离）

### 5.4 状态、置信度与文本证据记录契约

#### 5.4.1 一般状态语义

以下语义在共同校准前统一使用，但不预先为每个字段增加专门例外。共同校准用于发现哪些字段确实需要`UNK/NA`或额外边界规则，不能把同一批经讨论材料的高一致率当作独立信度。

| 状态 | 操作定义 | 使用边界 |
|------|----------|----------|
| `1` | 字段适用，且观察到支持该标签或类别的材料证据 | 正式值 |
| `0` | 字段适用，完整判断后未观察到相应内容 | 不得用于表示未检查、无法判断或结构性不适用 |
| `UNK` | 字段适用，但材料缺失、过度模糊或证据冲突，无法形成有证据的唯一判断 | 是否纳入某字段正式值域由共同校准后的书面决定确定 |
| `NA` | 字段因条件未触发而结构性不适用 | 不参加该字段信度分母和模型损失 |
| `UNRESOLVED` | 共同校准期的临时工作状态，表示现行规则尚不能唯一裁决 | 不属于正式研究值；必须进入问题登记并在盲试标前关闭 |

规则冻结后使用新样本进行独立盲试标。字段达到`alpha >= 0.80`、类别支持足够且分歧审计未发现反复出现的系统性边界问题时，维持一般状态语义，不再为了形式完整追加字段专门规则。若修改值域、定义或适用条件，原信度失效，并须用新的未讨论样本确认。

#### 5.4.2 逐字段置信度

置信度是每次人工主观判断都必须执行的程序性审计，不是准确概率、研究结果或模型监督目标。客观导入字段不评分；结构性`NA`记为`null`。

| 等级 | 操作定义 | 处理 |
|------|----------|------|
| 5 非常高 | 有直接明确证据，与锚点高度一致，没有合理替代判断 | 正常保存 |
| 4 较高 | 证据清楚，只需少量语境理解，替代判断明显不合理 | 正常保存 |
| 3 中等 | 当前判断有依据，但接近边界、依赖语境，或存在一个合理替代判断 | 正常保存，不强制备注 |
| 2 较低 | 证据较弱、冲突或高度依赖上下文，存在两个以上合理判断 | 必须填写结构化备注并进入第二编码员重点复核 |
| 1 无法稳定判断 | 没有足够证据支持唯一判断 | 共同校准期记`UNRESOLVED`；字段正式允许时记`UNK`；必须备注和复核 |

`confidence_json`以字段名为键保存1—5，例如`{"cs_inf": 5, "at_has_eval": 2}`。`confidence_notes_json`只覆盖置信度1—2的字段，每项保存`reason_code`、`alternative_values`和`note`；`alternative_values`没有合理替代值时允许为空数组，编码员不手写JSON。人工作业表只要求从`BOUNDARY`、`CONTEXT`、`CONFLICT`、`EVIDENCE_MISSING`或`OTHER`中选择原因，并填写一句简短说明；转换工具负责生成规范JSON。试编码后应检验低置信记录是否更集中地出现编码分歧；若没有区分能力，须重新校准等级锚点，不得把该分数作为效度证据。

#### 5.4.3 统一文本证据跨度

文本轨统一使用`evidence_spans_json`，不再分别维护`resource_spans_json`和`aspect_spans_json`。每个对象包含`fields`、`start`、`end`和`quote`：

```json
[
  {"fields": ["rs_n_wat"], "start": 3, "end": 5, "quote": "海风"},
  {"fields": ["at_has_eval", "sentiment_dir"], "start": 8, "end": 11, "quote": "很舒服"}
]
```

- offset始终定位不可变的`raw_text`，按Unicode字符从0开始计数；区间采用左闭右开`[start, end)`。
- 必须满足`raw_text[start:end] == quote`；导入时校验非负、未越界且引文完全一致。
- 编码员只复制最短充分的`quote`；转换工具自动计算`start/end`。同一引文在`raw_text`中重复出现时，编码员才填写其起始位置，不要求日常手工计算offset。
- 同一字段可以有多个不连续跨度；同一跨度可以支持多个字段；跨度之间允许重叠。
- 选择能够支持判断的最短充分文本；否定、程度和转折会改变含义时必须一并纳入。
- 实质性阳性标签原则上至少有一个证据跨度。`0`、`UNK`、`NA`以及`at_non`、`is_non`、`asp_applicable=0`等整体排除或不适用判断不伪造局部跨度，其原因由状态或低置信备注承担；V3和V6的父类与子类可共享同一最短充分证据。
- 问题登记中的文本`evidence_spans_json`使用同一契约；视觉图像区域的坐标契约待视觉轨T0关闭后另行冻结。

### 5.5 校准问题与编码簿修订记录（不属于研究变量）

本节记录只在**共同校准、盲试标及版本评审**中使用，用于检验预设框架是否完整、边界是否可执行。它们不进入H1—H8检验，不作为BERT监督目标，也不得被汇总为主题分析结果。

**最低负担的人机分工**：共同校准的编码员只填写一张`calibration-coding`主表。系统预填身份、观察单位、字段、值域与版本；编码员只填写编码值、逐字段置信度、置信度1—2或`UNRESOLVED`时的一句说明、实质性阳性判断的证据原文，以及极少数框架外或切分问题。转换工具生成`labels.csv`所需JSON与文本offset，并把`UNRESOLVED`和额外问题整理为负责人问题队列。编码员不填写独立问题表或修订决策表。

## 六、编码规则清单

### 文本轨编码规则

| # | 规则 | 说明 |
|---|------|------|
| 1 | **逐字段人工编码** | 编码员对所有进入记录表的字段逐项判断；跨字段逻辑仅用于复核，不得由程序自动生成或覆写 |
| 2 | **逐字段置信度** | 每个主观判断均按第5.4.2节评分；1—2级必须写结构化备注并进入重点复核 |
| 3 | **贴着文本** | 编码来自句子自身传达的信息，不过度推断 |
| 4 | **证据先行** | V3/V4/V5/V6的实质性阳性判断均使用统一`evidence_spans_json`定位；父类与子类可以共享证据，层级和跨字段逻辑仅用于复核；`rs_r_act`分析汇总不另记证据 |
| 5 | **资源≠语言功能≠属性指向** | V4判断调用了什么旅游资源；V5判断片段承担什么语言功能并表达何种情感；V6判断评价/建议指向什么目的地属性 |
| 6 | **渲染≠评价** | 感官/氛围呈现归CS-EMO；明确好坏、价值或满意度判断归AT-EVL；二者可共现 |
| 7 | **情感方向的条件标注** | 先人工标注`sentiment_judgeable`；为1时再标POS/NEG/MIX/NEU，为0时`sentiment_dir=NA`。NEU只表示真实中性评价 |
| 8 | **平台语境** | 以V3定义为主、平台校准为辅 |
| 9 | **共现不是折中** | 每个原子项分别作0/1判断，不设置"主要标签"或人为优先级 |
| 10 | **属性—方向原子绑定** | 评价属性或情感方向切换时必须预先切分；V6保持方向中立，正负方向只由同一片段的V5情感字段记录 |

### 视觉轨编码规则

| # | 规则 | 说明 |
|---|------|------|
| 1 | **画面优先** | 编码依据是画面本身，而非配文描述 |
| 2 | **主体面积优先** | 仅V7视觉主体在多个元素共存时按视觉突出度和面积判定 |
| 3 | **单图独立** | 每张图片独立编码 |
| 4 | **宁缺毋滥** | 品牌/标识不清晰时不编码为1 |
| 5 | **分轴判断** | V8分别判断场景语境、景别和视角；V9分别判断人数和互动，不互相替代 |
| 6 | **可见证据限定** | V11只记录画面中直接可见的对象状态，不从文本、滤镜、价格、品牌或场景类别推断 |
| 7 | **适用性先行** | V11先判断状态轴是否被触发；无相关对象或可见范围不足记NA，适用且标签不成立才记0 |
| 8 | **正负独立** | V11同轴正负字段分别判断，可同时为1；不得自动互斥、抵消或汇总成整体图片情感 |
| 9 | **安全线索不对称** | 可见危险源与防护措施均须有直接证据；未见防护不等于不安全，见到防护也不等于无风险 |

### 编码簿开发与修订规则

| # | 规则 | 说明 |
|---|------|------|
| 1 | **问题登记不等于新增编码** | 编码员可登记框架遗漏、边界案例和反例，但在团队决策生效前只能按现行值域编码或依适用规则记`UNK/NA`，不得自造标签 |
| 2 | **相关性先行** | 只有与既定研究问题和分析范围直接相关、且现行字段无法有效表达的材料才能登记为`FRAMEWORK_GAP`；一般性新奇内容不扩张框架 |
| 3 | **支持证据与反例并列** | 每项实质修订必须同时检查支持材料、分歧案例和反例，不能只凭频次、单个典型例或理论期待改规则 |
| 4 | **语境单位不改观察单位** | 编码员可阅读完整帖子与必要图文语境来消歧，但文本标签仍落在固定`seg_id`，图像标签仍落在固定`img_id`；系统性切分问题另行登记 |
| 5 | **规则与备忘分离** | `issue_note`只保存问题和分析理由；只有进入新版编码表的定义、值域、纳入/排除规则与锚点例句才具有规范效力 |
| 6 | **冻结前修订，冻结后停表评审** | 共同校准和盲试标可触发修订；正式编码开始后发现判定边界改变时，须暂停受影响字段、升版并确定重编码范围 |
| 7 | **AI不能决定类目** | AI可辅助检索相似案例或提出候选问题，但须记录工具/模型版本并由研究者核验；AI不得新增类目、关闭问题或把聚类命名为正式发现 |

**重编码门**：仅修正错别字、链接或不改变任何判定结果的表述时，`recoding_scope=NONE`；增加锚点但不改变边界时至少复核试标样本；改动操作定义、纳入/排除规则、值域、分析单位，或新增/合并类目时，旧信度结果失效，至少对全部受影响字段重编码，并用未参与规则修订的新样本重新确认信度。是否达到“实质改动”必须由两名研究者共同决定并写入修订决策表。

## 七、候选帖子级聚合指标体系（`DEFERRED`）

本节保留既有公式用于未来评估，不是当前编码表冻结、文本试标或模型训练的前置条件。只有原子标签完成正式信度、模型效度和全语料发布后，才能决定是否采用SRM、SAM、AAM、COD或其他替代方法；在此之前不得将这些指标解释为因果“传导”。

### 7.1 文本轨聚合指标

| 指标 | 公式 | 取值范围 | 含义 |
|------|------|----------|------|
| segment_count | COUNT(seg_id) | 1-N | 有效文本片段总数 |
| **V4 Layer 1** | | | |
| rsd_n | SUM(rs_n) / segment_count | [0, 1] | 自然旅游资源提及密度 |
| rsd_r | SUM(rs_r) / segment_count | [0, 1] | 人文旅游资源提及密度 |
| **V4 Layer 2** | | | |
| ICB | 10个Layer 2自然+人文亚类出现数之和 | 0-10 | 总资源覆盖广度；事件Layer 3不重复计入 |
| IMP_N | [rsd_n_geo, rsd_n_wat, rsd_n_bio, rsd_n_cli] | 四维向量 | 自然资源亚类轮廓 |

### 7.2 视觉轨聚合指标

| 指标 | 公式 | 含义 |
|------|------|------|
| image_count | COUNT(img_id) | 配图数量 |
| VIC | 视觉主体覆盖广度（0-5） | 几类视觉主体被使用 |
| dominant_visual_subject | V7频次取最大值 | 主导视觉主体 |
| hpd_sin | COUNT(PC-SIN) / image_count | 单人呈现占比 |
| hpd_grp | COUNT(PC-GRP) / image_count | 群体呈现占比 |
| hpd_int | SUM(human_scene_interaction) / image_count | 人景互动占比 |
| v16_fac_pos / v16_fac_neg | SUM对应字段=1 / COUNT对应字段∈{0,1} | 设施维护状态正向/负向出现率；各自排除NA |
| v16_hyg_pos / v16_hyg_neg | SUM对应字段=1 / COUNT对应字段∈{0,1} | 卫生整洁状态正向/负向出现率；各自排除NA |
| v16_order_pos / v16_order_neg | SUM对应字段=1 / COUNT对应字段∈{0,1} | 现场秩序状态正向/负向出现率；各自排除NA |
| v16_environment_pos / v16_environment_neg | SUM对应字段=1 / COUNT对应字段∈{0,1} | 环境维护状态正向/负向出现率；各自排除NA |
| v16_hazard / v16_protection | SUM对应字段=1 / COUNT对应字段∈{0,1} | 可见危险源/防护措施出现率；各自排除NA |

V11只分别报告原子项或成对轮廓，不计算单一“视觉正负得分”。同轴正负同时为1表示混合状态，不应相互抵消。以上指标在V11完成独立信度冻结及分析预注册前均为`DEFERRED`。

### 7.3 跨维度关联指标

**SRM_L1：策略→资源大类关联（4×2）**

```
SRM_L1[CS-X][RS-Z] = COUNT(segments with CS-X AND RS-Z=1) / COUNT(segments with CS-X)
```

**SRM_L2：策略→资源亚类关联（4×10）**

**SRM_EVT：策略→事件子类关联（4×4；限`rs_r_evt=1`片段）**

**SAM_L1：资源大类→语言功能共现（2×3）**

**SAM_L2：资源亚类→语言功能共现（10×3）**

**SAM_EVT：事件子类→语言功能共现（4×3；限`rs_r_evt=1`片段）**

**AAM：V6属性子类→V5情感方向关联（12×3）**

```
AAM[ASP-X][DIR-Z] = COUNT(segments with ASP-X=1 AND sentiment_dir=Z) / COUNT(segments with ASP-X=1)
```

AAM仅分析`asp_applicable=1`且V6具名子类为1的评价原子片段。评价对象或方向切换必须预先切分，因此矩阵描述的是同一原子片段内的属性—方向关联；仍不得解释为因果传导。

**COD：共现密度**

| 指标 | 公式 | 含义 |
|------|------|------|
| COD_n_r | SUM(rs_n × rs_r) / segment_count | 自然+人文大类同片段共现密度 |
| COD_ngeo_rhis | SUM(rs_n_geo × rs_r_his) / segment_count | 地文景观+历史遗存共现密度 |
| COD_inf_evl | SUM(cs_inf × at_has_eval) / segment_count | 实用信息策略+评价功能共现密度 |
| IFD | SUM(rs_depth) / segment_count | 平均资源融合深度（0-10）；`rs_depth`只累加10个Layer 2亚类，不重复累加Layer 3事件子类或`rs_r_act`汇总项 |

## 八、标注方案与模型验证

理论导向的结构化内容分析依次完成“框架建立—数据校准—盲试标冻结—正式人工测量—模型扩展—统计分析”。神经网络是扩大已冻结测量的辅助工具，不是类目生成方法。人工信度与模型效度必须分开报告。

| 阶段 | 文本轨 | 视觉轨 | 目的 |
|------|--------|--------|------|
| 阶段0：框架与范围预定义 | 根据理论、标准、既有研究与H1—H8定义变量、一般状态语义、文本观察单位、置信度和证据规则；达到`CALIBRATION_READY`即可启动共同校准 | 在启动前另行冻结视觉人口、图片单位及边界T0 | 确认研究问题—构念—字段—分析输出的可追溯关系 |
| 阶段1：共同校准与规则修订 | 约20—30篇共同编码；编码员只填写单一主表，逐字段记录置信度，1—2级或`UNRESOLVED`填写一句备注；工具提取问题队列，研究负责人按第5.5节分类和裁决；不计算正式信度 | 暂不启动，或只做不占用文本预算的小规模规则探索并单独记账 | 决定哪些字段需要专门`UNK/NA`或边界规则，不生成主题或正式结果 |
| 阶段2：独立盲试标与冻结 | 另取约70—80篇新样本，双人独立编码且首轮完成前不交换判断；计算逐字段信度并在完成后裁决 | 视觉轨启动条件满足后采用同样流程 | 冻结编码表、锚点例句与裁决规则；实质修订后旧信度失效并用新样本确认 |
| 阶段3：评估金标与训练标注 | 锁定测试集全部双人独立编码并共识；训练池由主编码员标注，第二人复核预注册随机比例及全部稀有、低置信、冲突样本 | 文本人工证据通过后另行确定，不预设600张固定承诺 | 建立可追溯评估金标和训练标注；按作者/重复簇隔离训练、开发与测试 |
| 阶段4：主动学习 | 与同人工分钟数的随机扩样作等预算对照；主编码员标注，第二编码员承担风险复核和随机审计 | 仅在视觉标签信度与图片质量门通过后启动 | 检验而非预设主动学习是否节省人工；不触碰锁定测试集 |
| 阶段5：模型与统计验证 | 在预先锁定的测试集上报告逐标签Precision/Recall/F1、PR-AUC、校准、子群表现和置信区间；只对达到发布门的字段执行预设统计 | 同样执行锁定测试与选择性复核 | 逐标签决定可自动、AI辅助、人工专判或探索性，并回答预设研究问题 |

**冻结边界**：共同校准材料可用于修订规则，不能进入正式信度估计；盲试标首轮不得边标边改。若盲试标后仅增加不改变边界的锚点例句，可在决策日志中说明并复核试标样本；若定义、值域、单位或纳入/排除规则发生实质变化，必须升版、重编码受影响字段并用新样本重新验证。正式编码后不得以“框架外内容”为名增加临时类别。

“500篇文本”仅可作为初始人工预算锚点，不是充分性证明，也不等于500篇全部双人金标。实际训练规模由逐标签阳性数、学习曲线、区间宽度和人工分钟数共同决定。

**信度指标**：文本多标签信度对每个原子二值标签分别计算Krippendorff's alpha（名义尺度）；两位编码员时可同时报告Cohen's kappa作为敏感性结果。目标为`alpha >= 0.80`；同时检查类别样本数、阳性/阴性一致率、`UNK/NA`比例和分歧类型。达到目标且没有反复出现的系统性边界分歧时不再追加字段专门规则；`0.667 <= alpha < 0.80`只用于暂定分析并须复查，低于0.667的标签不得直接进入模型训练。任何实质修订均使原信度失效。

**AI边界**：模型只学习已冻结并通过信度门的人工金标，包括获准后的V0、V3（含旧编号V5并入的互动子项）、V4、V5、V6及后续获准的视觉字段。V0训练、锁定测试和质量门全部完成前不得对非金标样本输出正式角色；训练完成后人工退出生产编码，程序预测与派生只作用于非金标扩展样本，不得回写人工金标。V4的`rs_r_rec`、`rs_r_evt`与四个事件子类须逐字段输出，`rs_r_act`只由预测后的二值结果在分析层OR汇总，不设训练头；层级关系不得覆盖模型概率。V6适用性、父类、子类与其他项均须逐字段输出；不得以V5情感方向替代V6属性预测，也不得以父子逻辑覆盖模型概率。V11在完成视觉人口定义、专门规则冻结与独立信度验证前不得训练或发布；获准后仍须逐原子项输出，不得用一个图像情感分数替代10个字段。聚类、关键词、生成式摘要或模型建议只能作为金标锁定后的错误分析和问题检索线索；它们不能直接改变值域、关闭问题登记、替代人工裁决，也不能被命名为正式“主题”。所有模型扩展结果必须回到锁定人工金标上验证。

## 九、候选研究问题与假设

研究问题只由冻结的结构化字段及其预设聚合回答，不另设“从数据中生成主题”的研究问题。所有角色比较还必须先通过V0数据门、双人信度门与KOL/KOC组别支持门。H1、H2和H5可在文本主轨及V0角色门均通过后评估；依赖SRM/SAM/AAM、视觉轨或复杂调节分析的H3、H4、H6、H7和H8当前均为`DEFERRED`，不得在原子编码和模型验证完成前启动正式检验。

```
H1: 以V0人工金标训练且通过锁定质量门的程序所识别的KOL型与KOC型，在资源调用轮廓上存在显著差异（Layer 1: RS_profile; Layer 2: IMP）
H2: 以V0人工金标训练且通过锁定质量门的程序所识别的KOL型与KOC型，在内容策略轮廓上存在显著差异（CSP）
H3: 以V0人工金标训练且通过锁定质量门的程序所识别的KOL型与KOC型，在策略→资源关联矩阵（SRM_L1/L2）上存在结构性差异
H4: 以V0人工金标训练且通过锁定质量门的程序所识别的KOL型与KOC型，在资源→语言功能共现矩阵（SAM_L1/L2）及V6目的地属性→V5情感方向关联矩阵（AAM）上存在结构性差异
H5: 以V0人工金标训练且通过锁定质量门的程序所识别的KOL型与KOC型，在互动信号轮廓（ISP）上存在显著差异
H6: 同一帖子文字V4资源集合与视觉V7资源集合的对应程度在上述KOL型与KOC型间存在差异
H7: 明确商业披露状态（V1）调节策略→资源关联关系
H8: 平台情境与reach_tier下的KOL型/KOC型比较结果存在异质性
```
