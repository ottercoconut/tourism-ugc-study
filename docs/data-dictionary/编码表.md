## 一、核心设计理念

### 1.1 从"感知端"到"生产端"的理论转向

v2.0 用游客感知理论（CAC三层次模型）编码创作者生产行为，存在理论错配。v3.0 将编码对象调整为"目的地资源调用策略"。这里的“策略”仅指成品UGC中可观察、可重复编码的功能性内容呈现模式，不表示创作者主动规划或意识到某种策略，也不据此推断受众效果。自v3.4.3起，所有进入编码记录表的字段均由编码员逐字段人工判断；字段间的逻辑关系仅用于试标复核和一致性审计，不得自动改写人工记录。

### 1.2 文本主轨与视觉辅助轨

文本轨是论文主研究完成的必要路径；视觉轨仅用于辅助图文协同研究，视觉数据或模型未通过质量门不得阻塞文本主研究。AI协同是测量扩展的方法核心：在固定人工预算下比较神经网络、主动学习和选择性复核的准确度—成本表现；“少量人工编码是否足够”由学习曲线和锁定评估回答，不作为预设事实。

### 1.5 唯一方法定位：理论导向的结构化内容分析

本研究的唯一正式分析方法是**理论导向的结构化内容分析（量化取向；theory-directed structured content analysis）**。这里的“理论导向”指初始类目来自目的地形象与内容生产相关理论、GB/T 18972-2017、既有研究和预先提出的研究问题；“结构化”指使用固定分析单位、预先定义的变量和值域、证据定位、编码员训练与一致性检验，将UGC转化为可比较的结构化记录。正式结果以类目频数、比例、共现、组间差异及其不确定性为主；校准期的语境解释与分析备忘只服务于测量工具开发，不构成并列的质性分析方法。

| 方法环节 | 本研究的唯一口径 |
|----------|------------------|
| 初始类目形成 | 以理论、标准、既有研究和研究问题作演绎式定义，不把样本中的高频词或模型聚类直接升格为类目 |
| 数据反馈 | 仅在共同校准与盲试标冻结前，系统登记框架遗漏、边界案例、反例、语境依赖和切分问题；由研究团队形成书面修订决定 |
| 正式测量 | 对冻结的`seg_id`、`img_id`和帖子级字段逐项编码；以编码簿版本、证据跨度、信度和裁决轨迹保证可复核性 |
| 分析产出 | 输出结构化变量、描述统计、共现与预设组间比较；模型只扩展已冻结字段的测量范围 |
| 方法取向 | 量化取向；校准中的材料阅读、问题登记和备忘是编码簿开发步骤，不另行产出质性主题 |
| 明确排除 | **不采用主题分析法**，不生成开放代码、候选主题、主题地图或“数据饱和”结论；V1—V15是分析类目/变量，不称为“主题” |

数据反馈的作用是检验并修订测量工具，不是另开一条归纳主题轨。任何新增、合并或改写类目都必须在正式冻结前完成并升版；冻结后若发现足以改变判定边界的问题，须暂停受影响字段、启动版本评审，并按第6节规则重编码，不能在正式数据中静默增加标签。

## 三、文本轨：各维度操作定义

### V1 内容策略（片段级，5个人工编码项）

该片段以何种方式传递信息？编码员逐项标注5个0/1字段，可共现。

| 代码 | 标签 | 定义 | 触发特征 | 记录方式 |
|------|------|------|----------|----------|
| CS-INF | 信息提供型 | 提供可用于行程决策的事实、数据、攻略、路线或步骤 | 交通方式、价格、时间节点、操作步骤 | 编码员0/1 |
| CS-EDU | 知识阐释型 | 解释文化、历史、地理、非遗或地方知识 | "始建于""传说中""列入非遗" | 编码员0/1 |
| CS-EMO | 情感渲染型 | 通过感官描写或氛围语言营造体验 | 色彩、声音、气味、触感、氛围描写 | 编码员0/1 |
| CS-INT | 互动激发型 | 以提问、号召或社交触发推动受众参与 | 问号、@呼唤、"冲""码住""评论区" | 编码员0/1 |
| CS-OTH | 其他/未命中 | 未命中上述四种策略 | 开场白、段落衔接、纯表情 | 编码员0/1 |

同一片段可同时出现多个原子策略。例如"栈桥始建于1892年，傍晚海风吹过来很舒服"可同时编码`CS-EDU=1`与`CS-EMO=1`。CS-COM不再作为片段标签；明确商业披露由V6在帖子级记录。

**编码决策树**（辅助编码员判断，非互斥）：

```
该片段是否包含：
├── 行程决策信息（价格/时间/路线/步骤）  → CS-INF=1
├── 文化/历史/地理/非遗知识阐释        → CS-EDU=1
├── 感官描写/氛围语言/体验渲染          → CS-EMO=1
└── 以上均不显著                        → CS-OTH=1（编码员判断）
```

### V3 语言功能、情感方向与属性指向（片段级，可共现）

原V3与V4继续合并记录，但不再把信息、评价和建议强制互斥。一个片段可同时承担多种语言功能。

#### Layer 1：语言功能（3个原子0/1项）

| 代码 | 类型 | 定义 | 操作化标准 |
|------|------|------|-----------|
| AT-INF | 信息性陈述 | 包含至少一个可核验的事实命题 | 可判断真假的时间、地点、属性、数据或知识陈述 |
| AT-EVL | 评价性表达 | 对目的地、设施或体验作出明确价值判断 | "美""值""贵""拥挤""失望"等评价词或等价表达 |
| AT-SUG | 建议/推荐 | 向受众提出行动建议、推荐或回避 | "推荐""必去""避雷""千万别"等 |
| AT-NON | 其他/未命中 | 未命中上述三种语言功能；可能仍含由V5记录的提问或互动 | 编码员0/1 |

**AT-EVL 亚类**（基于Russell, 1980情感环状模型）：

| 亚类代码 | 情感质量 | 唤醒度 | 愉悦度 | 典型表达 |
|----------|----------|--------|--------|----------|
| AT-EVL-ADM | 赞赏/惊叹 | 高 | 正面 | "太美了""震撼""绝了" |
| AT-EVL-SAT | 满意/舒适 | 低 | 正面 | "很舒服""很满意""超值" |
| AT-EVL-EXC | 兴奋/激动 | 高 | 正面 | "太刺激了""超爽""尖叫" |
| AT-EVL-DIS | 失望/不满 | 低 | 负面 | "有点失望""不如预期""一般般" |
| AT-EVL-FRU | 沮丧/愤怒 | 高 | 负面 | "太坑了""巨坑""气死了" |
| AT-EVL-NOS | 怀旧/感慨 | 混合 | 混合 | "怀念""物是人非""故地重游" |

例如"门票80元，很值得去"同时编码`AT-INF=1`和`AT-EVL=1`；"人很多，建议早上去"同时编码`AT-INF=1`和`AT-SUG=1`。

#### Layer 2：情感方向（片段含AT-EVL或AT-SUG时标注）

| 代码 | 含义 | 判定标准 |
|------|------|----------|
| POS | 正面情感 | 评价/建议中的情感倾向明确为正面 |
| NEG | 负面情感 | 评价/建议中的情感倾向明确为负面 |
| MIX | 混合/矛盾情感 | 同一句中既有正面又有负面评价 |
| NEU | 中性 | 片段含评价或建议，且表达真实中性、无褒贬方向的立场 |

新增`sentiment_judgeable`（情感方向可判定，0/1）：当片段不含评价或建议，或虽含评价/建议但无法从文本判定情感方向时，记为0，`sentiment_dir`记为`NA`；当其为1时，`sentiment_dir`必须人工编码为POS、NEG、MIX或NEU之一。NEU不得再承担“不适用”或“无法判定”的含义。

以两个独立的人工强度字段记录情感，不再使用单一`sentiment_val`：

| 字段 | 取值 | 人工判定规则 |
|------|------|-------------|
| `sentiment_pos_val` | 0 / 1 / 2 / NA | 无正面表达 / 一般正面 / 强正面 / 情感不可判定 |
| `sentiment_neg_val` | 0 / 1 / 2 / NA | 无负面表达 / 一般负面 / 强负面 / 情感不可判定 |

当`sentiment_judgeable=0`时，两字段均记NA；POS对应`pos=1或2, neg=0`，NEG对应`pos=0, neg=1或2`，NEU对应`pos=0, neg=0`，MIX对应`pos=1或2, neg=1或2`。强度2仅用于明确的强烈情绪、显著强化词或极端评价；其余明确方向表达记1。后续若需净方向，仅在分析阶段计算`pos - neg`，不得覆盖这两个原始人工字段。

#### Layer 3：目的地属性指向（片段含AT-EVL或AT-SUG时条件标注）

本层回答"评价或建议究竟指向目的地的什么"。它**不替代V2资源分类**：V2记录被调用的旅游资源，`asp_*`记录被评价、被建议或被回避的目的地属性。

| 代码 | 属性指向 | 定义 | 典型线索 |
|------|----------|------|----------|
| ASP-RES | 资源/吸引物品质 | 对旅游资源本身的品质、吸引力作评价/建议 | 景色美、古迹震撼、美食一般 |
| ASP-PRI | 价格与性价比 | 对门票、餐饮、住宿等价格或性价比作评价/建议 | 门票贵、免费、性价比高 |
| ASP-SER | 服务与设施 | 对接待、讲解、住宿/餐饮设施及服务质量作评价/建议 | 服务差、讲解专业、酒店隔音差 |
| ASP-CRO | 拥挤与管理秩序 | 对客流密度、排队、秩序、运营管理作评价/建议 | 人太多、排队久、管理混乱 |
| ASP-ACC | 交通与可达性 | 对到达、换乘、停车、步行距离作评价/建议 | 地铁直达、停车难、交通不便 |
| ASP-HYG | 卫生与安全 | 对环境卫生、食品安全、风险保障作评价/建议 | 厕所脏、海边危险、卫生堪忧 |

**排除规则**：（1）纯事实提及"门票80元""有地铁站"但没有评价或建议时，所有`asp_*`记0；（2）只对创作者本人、平台或无关商品作评价时，所有`asp_*`记0；（3）`RS-R-ARC`记录"酒店/交通设施被作为资源提及"，`ASP-SER/ASP-ACC`记录"其服务或可达性被评价/建议"，二者可以共现，不能互相替代。

**编码示例**：

| 原句 | INF | EVL | SUG | 情感方向 | ASP-RES | ASP-PRI | ASP-CRO | 理由 |
|------|-----|-----|-----|----------|---------|---------|---------|------|
| "栈桥始建于1892年" | 1 | 0 | 0 | NA | 0 | 0 | 0 | 无评价或建议，情感不可判定 |
| "门票80元，很值得去" | 1 | 1 | 0 | POS | 1 | 1 | 0 | 事实+评价，指向资源和价格 |
| "避雷！千万别去这家海鲜店" | 0 | 0 | 1 | NEG | 1 | 0 | 0 | 负面回避，指向资源品质 |
| "风景美但管理差，人又多" | 0 | 1 | 0 | MIX | 1 | 0 | 1 | 正负评价，指向资源和拥挤 |
| "你们最喜欢哪里？" | 0 | 0 | 0 | NA | 0 | 0 | 0 | 提问由V5记录，情感不可判定 |

## 四、视觉轨：各维度操作定义

视觉轨对帖子的每一张配图进行编码。编码单位：单张图片。

### 5.4 状态、置信度与文本证据记录契约

#### 5.4.1 一般状态语义

以下语义在共同校准前统一使用，但不预先为每个字段增加专门例外。共同校准用于发现哪些字段确实需要`UNK/NA`或额外边界规则，不能把同一批经讨论材料的高一致率当作独立信度。

| 状态 | 操作定义 | 使用边界 |
|------|----------|----------|
| `1` | 字段适用，且观察到支持该标签或类别的材料证据 | 正式值 |
| `0` | 字段适用，完整判断后未观察到相应内容 | 不得用于表示未检查、无法判断或结构性不适用 |
| `UNK` | 字段适用，但材料缺失、过度模糊或证据冲突，无法形成有证据的唯一判断 | 是否纳入某字段正式值域由共同校准后的书面决定确定 |
| `NA` | 字段因条件未触发而结构性不适用 | 不参加该字段信度分母和模型损失 |
| `UNRESOLVED` | 共同校准期的临时工作状态，表示现行规则尚不能唯一裁决 | 不属于正式研究值；必须进入问题登记并在盲试标前关闭 |

规则冻结后使用新样本进行独立盲试标。字段达到`alpha >= 0.80`、类别支持足够且分歧审计未发现反复出现的系统性边界问题时，维持一般状态语义，不再为了形式完整追加字段专门规则。若修改值域、定义或适用条件，原信度失效，并须用新的未讨论样本确认。

#### 5.4.2 逐字段置信度

置信度是每次人工主观判断都必须执行的程序性审计，不是准确概率、研究结果或模型监督目标。客观导入字段不评分；结构性`NA`记为`null`。

| 等级 | 操作定义 | 处理 |
|------|----------|------|
| 5 非常高 | 有直接明确证据，与锚点高度一致，没有合理替代判断 | 正常保存 |
| 4 较高 | 证据清楚，只需少量语境理解，替代判断明显不合理 | 正常保存 |
| 3 中等 | 当前判断有依据，但接近边界、依赖语境，或存在一个合理替代判断 | 正常保存，不强制备注 |
| 2 较低 | 证据较弱、冲突或高度依赖上下文，存在两个以上合理判断 | 必须填写结构化备注并进入第二编码员重点复核 |
| 1 无法稳定判断 | 没有足够证据支持唯一判断 | 共同校准期记`UNRESOLVED`；字段正式允许时记`UNK`；必须备注和复核 |

`confidence_json`以字段名为键保存1—5，例如`{"cs_inf": 5, "at_has_eval": 2}`。`confidence_notes_json`只覆盖置信度1—2的字段，每项保存`reason_code`、`alternative_values`和`note`；`alternative_values`没有合理替代值时允许为空数组，编码员不手写JSON。人工作业表只要求从`BOUNDARY`、`CONTEXT`、`CONFLICT`、`EVIDENCE_MISSING`或`OTHER`中选择原因，并填写一句简短说明；转换工具负责生成规范JSON。试编码后应检验低置信记录是否更集中地出现编码分歧；若没有区分能力，须重新校准等级锚点，不得把该分数作为效度证据。

#### 5.4.3 统一文本证据跨度

文本轨统一使用`evidence_spans_json`，不再分别维护`resource_spans_json`和`aspect_spans_json`。每个对象包含`fields`、`start`、`end`和`quote`：

```json
[
  {"fields": ["rs_n_wat"], "start": 3, "end": 5, "quote": "海风"},
  {"fields": ["at_has_eval", "sentiment_dir"], "start": 8, "end": 11, "quote": "很舒服"}
]
```

- offset始终定位不可变的`raw_text`，按Unicode字符从0开始计数；区间采用左闭右开`[start, end)`。
- 必须满足`raw_text[start:end] == quote`；导入时校验非负、未越界且引文完全一致。
- 编码员只复制最短充分的`quote`；转换工具自动计算`start/end`。同一引文在`raw_text`中重复出现时，编码员才填写其起始位置，不要求日常手工计算offset。
- 同一字段可以有多个不连续跨度；同一跨度可以支持多个字段；跨度之间允许重叠。
- 选择能够支持判断的最短充分文本；否定、程度和转折会改变含义时必须一并纳入。
- 实质性阳性标签原则上至少有一个证据跨度。`0`、`UNK`、`NA`以及`cs_oth`、`at_non`、`is_non`等整体排除判断不伪造局部跨度，其原因由状态或低置信备注承担。
- 问题登记中的文本`evidence_spans_json`使用同一契约；视觉图像区域的坐标契约待视觉轨T0关闭后另行冻结。

### 5.5 校准问题与编码簿修订记录（不属于研究变量）

本节记录只在**共同校准、盲试标及版本评审**中使用，用于检验预设框架是否完整、边界是否可执行。它们不进入H1—H8检验，不作为BERT监督目标，也不得被汇总为主题分析结果。

**最低负担的人机分工**：共同校准的编码员只填写一张`calibration-coding`主表。系统预填身份、观察单位、字段、值域与版本；编码员只填写编码值、逐字段置信度、置信度1—2或`UNRESOLVED`时的一句说明、实质性阳性判断的证据原文，以及极少数框架外或切分问题。转换工具生成`labels.csv`所需JSON与文本offset，并把`UNRESOLVED`和额外问题整理为负责人问题队列。编码员不填写独立问题表或修订决策表。

### 文本轨编码规则

| # | 规则 | 说明 |
|---|------|------|
| 1 | **逐字段人工编码** | 编码员对所有进入记录表的字段逐项判断；跨字段逻辑仅用于复核，不得由程序自动生成或覆写 |
| 2 | **逐字段置信度** | 每个主观判断均按第5.4.2节评分；1—2级必须写结构化备注并进入重点复核 |
| 3 | **贴着文本** | 编码来自句子自身传达的信息，不过度推断 |
| 4 | **证据先行** | V1/V2/V3/V5的实质性阳性判断均使用统一`evidence_spans_json`定位；层级和跨字段逻辑仅用于复核 |
| 5 | **资源≠语言功能≠属性指向** | V2判断调用了什么旅游资源；V3-L1判断片段承担什么语言功能；V3-L3判断评价/建议指向什么目的地属性 |

| 7 | **情感方向的条件标注** | 先人工标注`sentiment_judgeable`；为1时再标POS/NEG/MIX/NEU，为0时`sentiment_dir=NA`。NEU只表示真实中性评价 |
| 8 | **平台语境** | 以V1定义为主、平台校准为辅 |
| 9 | **共现不是折中** | 每个原子项分别作0/1判断，不设置"主要标签"或人为优先级 |

### 视觉轨编码规则

| # | 规则 | 说明 |
|---|------|------|
| 1 | **画面优先** | 编码依据是画面本身，而非配文描述 |
| 2 | **主体面积优先** | 仅V11视觉主体在多个元素共存时按视觉突出度和面积判定 |

### 编码簿开发与修订规则

| # | 规则 | 说明 |
|---|------|------|
| 1 | **问题登记不等于新增编码** | 编码员可登记框架遗漏、边界案例和反例，但在团队决策生效前只能按现行值域编码或依适用规则记`UNK/NA`，不得自造标签 |
| 2 | **相关性先行** | 只有与既定研究问题和分析范围直接相关、且现行字段无法有效表达的材料才能登记为`FRAMEWORK_GAP`；一般性新奇内容不扩张框架 |
| 3 | **支持证据与反例并列** | 每项实质修订必须同时检查支持材料、分歧案例和反例，不能只凭频次、单个典型例或理论期待改规则 |
| 4 | **语境单位不改观察单位** | 编码员可阅读完整帖子与必要图文语境来消歧，但文本标签仍落在固定`seg_id`，图像标签仍落在固定`img_id`；系统性切分问题另行登记 |
| 5 | **规则与备忘分离** | `issue_note`只保存问题和分析理由；只有进入新版编码表的定义、值域、纳入/排除规则与锚点例句才具有规范效力 |
| 6 | **冻结前修订，冻结后停表评审** | 共同校准和盲试标可触发修订；正式编码开始后发现判定边界改变时，须暂停受影响字段、升版并确定重编码范围 |
| 7 | **AI不能决定类目** | AI可辅助检索相似案例或提出候选问题，但须记录工具/模型版本并由研究者核验；AI不得新增类目、关闭问题或把聚类命名为正式发现 |

**重编码门**：仅修正错别字、链接或不改变任何判定结果的表述时，`recoding_scope=NONE`；增加锚点但不改变边界时至少复核试标样本；改动操作定义、纳入/排除规则、值域、分析单位，或新增/合并类目时，旧信度结果失效，至少对全部受影响字段重编码，并用未参与规则修订的新样本重新确认信度。是否达到“实质改动”必须由两名研究者共同决定并写入修订决策表。

## 七、候选帖子级聚合指标体系（`DEFERRED`）

本节保留既有公式用于未来评估，不是当前编码表冻结、文本试标或模型训练的前置条件。只有原子标签完成正式信度、模型效度和全语料发布后，才能决定是否采用SRM、SAM、AAM、COD或其他替代方法；在此之前不得将这些指标解释为因果“传导”。

### 7.1 文本轨聚合指标

| 指标 | 公式 | 取值范围 | 含义 |
|------|------|----------|------|
| segment_count | COUNT(seg_id) | 1-N | 有效文本片段总数 |

| **V2 Layer 2** | | | |
| ICB | 自然+人文亚类出现数之和 | 0-9 | 总资源覆盖广度 |
| IMP_N | [rsd_n_geo, rsd_n_wat, rsd_n_bio, rsd_n_cli] | 四维向量 | 自然资源亚类轮廓 |
| IMP_R | [rsd_r_his, rsd_r_arc, rsd_r_gas, rsd_r_fol, rsd_r_act] | 五维向量 | 人文资源亚类轮廓 |
| **V1** | | | |
| CSP | [csd_inf, csd_edu, csd_emo, csd_int] | 四维向量 | 内容策略出现率；各维可共现 |
| **V3 Layer 1** | | | |
| ATP | [atd_inf, atd_evl, atd_sug] | 三维向量 | 语言功能出现率；各维可共现 |
| **V3 Layer 2** | | | |

| **V3 Layer 3** | | | |

### 7.2 视觉轨聚合指标

| 指标 | 公式 | 含义 |
|------|------|------|
| image_count | COUNT(img_id) | 配图数量 |
| VIC | 视觉主体覆盖广度（0-5） | 几类视觉主体被使用 |
| dominant_visual_subject | V11频次取最大值 | 主导视觉主体 |
| hpd_sin | COUNT(PC-SIN) / image_count | 单人呈现占比 |
| hpd_grp | COUNT(PC-GRP) / image_count | 群体呈现占比 |
| hpd_int | SUM(human_scene_interaction) / image_count | 人景互动占比 |

### 7.3 跨维度关联指标

**SRM_L1：策略→资源大类关联（4×2）**

```
SRM_L1[CS-X][RS-Z] = COUNT(segments with CS-X AND RS-Z=1) / COUNT(segments with CS-X)
```

**SRM_L2：策略→资源亚类关联（4×9）**

**SAM_L1：资源大类→语言功能共现（2×3）**

**SAM_L2：资源亚类→语言功能共现（9×3）**

**AAM：目的地属性→情感方向关联（6×3）**

```
AAM[ASP-X][DIR-Z] = COUNT(segments with ASP-X=1 AND sentiment_dir=Z) / COUNT(segments with ASP-X=1)
```

AAM仅分析含评价或建议且存在属性指向的片段。

**COD：共现密度**

| 指标 | 公式 | 含义 |
|------|------|------|
| COD_n_r | SUM(rs_n × rs_r) / segment_count | 自然+人文大类同片段共现密度 |
| COD_ngeo_rhis | SUM(rs_n_geo × rs_r_his) / segment_count | 地文景观+历史遗存共现密度 |
| COD_inf_evl | SUM(cs_inf × at_has_eval) / segment_count | 实用信息策略+评价功能共现密度 |
| IFD | SUM(rs_depth) / segment_count | 平均资源融合深度（0-9） |

## 八、标注方案与模型验证

理论导向的结构化内容分析依次完成“框架建立—数据校准—盲试标冻结—正式人工测量—模型扩展—统计分析”。神经网络是扩大已冻结测量的辅助工具，不是类目生成方法。人工信度与模型效度必须分开报告。

| 阶段 | 文本轨 | 视觉轨 | 目的 |
|------|--------|--------|------|
| 阶段0：框架与范围预定义 | 根据理论、标准、既有研究与H1—H8定义变量、一般状态语义、文本观察单位、置信度和证据规则；达到`CALIBRATION_READY`即可启动共同校准 | 在启动前另行冻结视觉人口、图片单位及边界T0 | 确认研究问题—构念—字段—分析输出的可追溯关系 |
| 阶段1：共同校准与规则修订 | 约20—30篇共同编码；编码员只填写单一主表，逐字段记录置信度，1—2级或`UNRESOLVED`填写一句备注；工具提取问题队列，研究负责人按第5.5节分类和裁决；不计算正式信度 | 暂不启动，或只做不占用文本预算的小规模规则探索并单独记账 | 决定哪些字段需要专门`UNK/NA`或边界规则，不生成主题或正式结果 |
| 阶段2：独立盲试标与冻结 | 另取约70—80篇新样本，双人独立编码且首轮完成前不交换判断；计算逐字段信度并在完成后裁决 | 视觉轨启动条件满足后采用同样流程 | 冻结编码表、锚点例句与裁决规则；实质修订后旧信度失效并用新样本确认 |
| 阶段3：评估金标与训练标注 | 锁定测试集全部双人独立编码并共识；训练池由主编码员标注，第二人复核预注册随机比例及全部稀有、低置信、冲突样本 | 文本人工证据通过后另行确定，不预设600张固定承诺 | 建立可追溯评估金标和训练标注；按作者/重复簇隔离训练、开发与测试 |
| 阶段4：主动学习 | 与同人工分钟数的随机扩样作等预算对照；主编码员标注，第二编码员承担风险复核和随机审计 | 仅在视觉标签信度与图片质量门通过后启动 | 检验而非预设主动学习是否节省人工；不触碰锁定测试集 |
| 阶段5：模型与统计验证 | 在预先锁定的测试集上报告逐标签Precision/Recall/F1、PR-AUC、校准、子群表现和置信区间；只对达到发布门的字段执行预设统计 | 同样执行锁定测试与选择性复核 | 逐标签决定可自动、AI辅助、人工专判或探索性，并回答预设研究问题 |

**冻结边界**：共同校准材料可用于修订规则，不能进入正式信度估计；盲试标首轮不得边标边改。若盲试标后仅增加不改变边界的锚点例句，可在决策日志中说明并复核试标样本；若定义、值域、单位或纳入/排除规则发生实质变化，必须升版、重编码受影响字段并用新样本重新验证。正式编码后不得以“框架外内容”为名增加临时类别。

“500篇文本”仅可作为初始人工预算锚点，不是充分性证明，也不等于500篇全部双人金标。实际训练规模由逐标签阳性数、学习曲线、区间宽度和人工分钟数共同决定。

**信度指标**：文本多标签信度对每个原子二值标签分别计算Krippendorff's alpha（名义尺度）；两位编码员时可同时报告Cohen's kappa作为敏感性结果。目标为`alpha >= 0.80`；同时检查类别样本数、阳性/阴性一致率、`UNK/NA`比例和分歧类型。达到目标且没有反复出现的系统性边界分歧时不再追加字段专门规则；`0.667 <= alpha < 0.80`只用于暂定分析并须复查，低于0.667的标签不得直接进入模型训练。任何实质修订均使原信度失效。

**AI边界**：模型只学习已冻结的V1/V2/V3/V5及后续获准的视觉字段。聚类、关键词、生成式摘要或模型建议只能作为错误分析和问题检索线索；它们不能直接改变值域、关闭问题登记、替代人工裁决，也不能被命名为正式“主题”。所有模型扩展结果必须回到锁定人工金标上验证。

## 九、候选研究问题与假设

研究问题只由冻结的结构化字段及其预设聚合回答，不另设“从数据中生成主题”的研究问题。H1、H2和H5可在文本主轨通过质量门后评估。依赖SRM/SAM/AAM、视觉轨或复杂调节分析的H3、H4、H6、H7和H8当前均为`DEFERRED`，不得在原子编码和模型验证完成前启动正式检验。

```
H1: 不同创作者层级在资源调用轮廓上存在显著差异（Layer 1: RS_profile; Layer 2: IMP）
H2: 不同创作者层级在内容策略轮廓上存在显著差异（CSP）
H3: 不同创作者层级在策略→资源关联矩阵（SRM_L1/L2）上存在结构性差异
H4: 不同创作者层级在资源→语言功能共现矩阵（SAM_L1/L2）及目的地属性→情感方向关联矩阵（AAM）上存在结构性差异
H5: 不同创作者层级在互动信号轮廓（ISP）上存在显著差异
H6: 文字资源与视觉资源的匹配程度在不同层级间存在差异
H7: 明确商业披露状态（V6）调节策略→资源关联关系
H8: 平台类型调节创作者层级对资源调用策略的影响
```
