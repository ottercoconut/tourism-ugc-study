# 编码表与 BERT 学习的对应关系

> 文档范围：说明旅游科研编码表如何转换为 BERT 的监督学习任务。  
> 不涉及具体标签内容、人工编码流程和样本量设计。

## 一、核心认识

编码表定义 BERT 需要学习哪些判断任务，但不直接规定 BERT 内部应该提取哪些语言特征。

普通监督微调中，BERT 不会直接阅读编码表中的文字定义。实际过程是：

```text
编码表定义研究概念
        ↓
人工依据定义产生标签
        ↓
标签成为模型监督信号
        ↓
BERT从正例和负例中学习实际判定边界
```

因此，BERT 真正学习的是编码表经过人工操作化之后形成的标签分布。

## 二、编码表与模型结构的基本映射

| 编码表中的内容 | BERT中的对应结构 |
|---|---|
| 一个研究维度 | 一个分类任务或分类头 |
| 维度下的一个代码 | 分类头中的一个输出节点 |
| 一篇帖子的编码结果 | 一个目标向量 |
| 多个代码可以同时成立 | 多个独立 Sigmoid |
| 类别严格互斥 | Softmax |
| 连续变量 | 回归头 |
| 有顺序的等级变量 | 序数分类头 |
| 父类—子类关系 | 派生计算或层级约束 |
| 无法判断、不适用 | 损失掩码，不参与该项训练 |
| 标签对应的文本片段 | 标签注意力或证据抽取任务 |
| 密度、广度、组合模式 | 模型输出后的统计计算 |

## 三、一个维度对应一个分类头

假设研究包含四个维度：

```text
共享BERT编码器
├── 旅游主题头
├── 叙事方式头
├── 体验维度头
└── 推荐意图头
```

这些分类头共享 BERT 的文本表示，但分别学习不同的研究判断。

一个分类头对应一个理论维度，不是一个标签。维度中的每个标签对应分类头中的一个输出节点。

例如，某个分类头包含：

```text
[大海, 高楼, 山岳, 古建筑]
```

一篇同时出现“大海”和“高楼”的帖子，其目标向量为：

```text
[1, 1, 0, 0]
```

不需要额外建立“大海+高楼”这一复合类别。

## 四、多标签与单标签的区别

当同一维度中的多个标签可以同时成立时，使用独立 Sigmoid：

\[
\mathbf p^{(d)}=\sigma(W_d\mathbf h+\mathbf b_d)
\]

模型可以同时输出：

```text
大海：0.92
高楼：0.81
山岳：0.07
```

当类别理论上严格互斥时，才使用 Softmax。Softmax 会使同一分类头下的概率总和为 1，不适合“大海”和“高楼”可以共存的情况。

## 五、BERT如何学会一个代码

BERT先把帖子编码成上下文表示：

\[
H=\operatorname{BERT}(x)
\]

然后每个标签利用自己的参数进行判断：

\[
p_k=\sigma(\mathbf w_k^\top\mathbf h+b_k)
\]

训练数据不断向模型提供：

```text
帖子A → 大海=1
帖子B → 大海=0
帖子C → 大海=1
```

模型由此学习哪些上下文模式与“大海=1”相关。它学习的不是单个关键词，而是训练样本中形成的语言决策边界。

如果书面定义和人工实际编码不一致，模型最终会学习人工编码表现出来的规则。

## 六、分析单位决定模型在哪里判断

| 编码单位 | 模型任务 |
|---|---|
| 一篇完整帖子 | 帖子级分类 |
| 一个句子或段落 | 片段级分类 |
| 一个词语或文本跨度 | Token/Span分类 |
| 两个实体之间的联系 | 关系分类 |

对于当前的帖子多标签分类，建议区分：

```text
帖子 = 主要监督和最终输出单位
片段 = 标签成立的证据单位
```

模型输出帖子标签，句子或段落用于说明该标签由哪些文本内容支持。

## 七、帖子级代码必须明确聚合含义

同一个“大海”标签可能表示三种不同任务：

1. 文本只要提到一次大海即为 1；
2. 文本必须对大海作出实质描述才为 1；
3. 大海必须是整篇帖子的主导意象才为 1。

三者对应的学习难度和模型聚合方式不同：

- 出现型标签主要依赖局部证据；
- 实质型标签需要理解完整上下文；
- 主导型标签需要比较不同内容在全文中的相对重要性。

因此，编码表对每个帖子级标签必须明确采用哪一种聚合含义。

## 八、未标注不能自动等同于负例

多标签训练中应区分：

```text
1   = 标签明确存在
0   = 完整判断后确认不存在
UNK = 无法判断或该标签未经检查
NA  = 对该材料不适用
```

`0`会作为负例训练模型；`UNK`和`NA`通常需要从对应标签的损失中屏蔽。

如果把未经检查的标签直接写成0，BERT会收到错误的负例信号。

## 九、父子标签的处理

假设标签存在以下结构：

```text
自然景观
└── 海滨景观
    └── 大海
```

如果父标签只是子标签的逻辑汇总，可以由程序自动计算：

```text
大海=1
→ 海滨景观=1
→ 自然景观=1
```

如果研究需要模型同时学习父类和子类，可以分别输出，并加入层级约束：

\[
p(\text{大海})
\leq p(\text{海滨景观})
\leq p(\text{自然景观})
\]

父类和子类是否都需要预测，应由其是否构成独立研究判断决定。

## 十、派生指标不作为主要预测目标

如果若干原子标签可以进一步形成：

- 组合模式；
- 建构广度；
- 标签密度；
- 共现矩阵；
- 综合指数；

这些结果应在 BERT 输出以后由程序计算：

```text
BERT预测原子标签
        ↓
统计程序计算派生指标
```

不应让模型同时预测原子标签和可以由原子标签精确计算的组合编号，否则容易产生逻辑矛盾。

## 十一、共享BERT带来的标签协同

不同分类头共享同一个 BERT，因此多个任务会共同影响文本表示。

例如：

```text
“沿着海边散步特别舒服，建议傍晚过来。”
```

可以同时支持：

- 旅游主题：海滨；
- 体验维度：放松；
- 叙事方式：体验描述；
- 推荐意图：建议。

这些任务的训练梯度共同更新 BERT，使其学习可以被多个研究维度复用的旅游语言表示。

相关任务可能相互促进；定义冲突或无关的任务也可能产生负迁移。因此，分类头的划分应反映研究维度之间的理论边界。

## 十二、最终关系

```text
研究维度
    → 一个分类头

维度中的原子代码
    → 一个输出节点

代码是否可以共存
    → Sigmoid或Softmax

代码的分析单位
    → 帖子、片段、Token或关系任务

代码的父子结构
    → 派生计算或层级约束

代码的不确定状态
    → 损失掩码

代码的文本证据
    → Attention、Chunk或Span监督

组合模式与统计指数
    → 模型输出后的计算
```

核心结论是：

> 编码表不是把人工定义的“特征”直接放进 BERT，而是把研究概念转换成一组可监督的判断任务。BERT通过带标签的文本样本，学习这些研究概念在真实语言中的操作化边界。
