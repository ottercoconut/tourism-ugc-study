## 二、P0——金标编码前必须解决

### P0-1：文本片段切分规则未确定

**问题**：所有密度指标（SRM/SAM/COD/IFD等）依赖segment_count，但"什么是一个语义片段"至今没有操作标准。人工切分与模型切分不一致会导致数据不可比。

**影响**：所有文本轨聚合指标均不可计算。

**解决方向**：
- 方案A：句末标点为边界（最简单，但长句内有多个子句时丢失信息）
- 方案B：以"主谓结构完整性"为边界（更精确，但需培训编码员）
- 方案C：模型自动切分+人工校验（效率高，但需先验证切分一致性）

**建议**：采用方案A为基础规则，辅以"同一列表中的独立攻略项分别成段"的补充规则。在试标阶段用10条帖子测试切分一致性。

### P0-2：V3-L3 目的地属性指向的必要性评估

**问题**：V3-L3（ASP-RES/PRI/SER/CRO/ACC/HYG）是从编码簿v3.4新增的维度，增加了每片段6个0/1判断。但RQ1-RQ3没有明确提出"目的地属性"作为研究焦点。

**影响**：
- 增加编码负荷（每片段从约15个判断增加到约21个）
- 增加金标样本稀疏性（6个属性类别中低频类别可能样本不足）
- 如果不服务RQ，就是"无效编码"

**解决方向**：
- 若保留：需要在RQ中补充"目的地属性"维度，或将其定位为探索性分析
- 若删除：简化编码方案，降低编码负荷和训练数据需求

**建议**：保留但降级为P1。在试标阶段先用10条帖子测试V3-L3的可操作性和信度，若Kappa < 0.60则删除。

### P0-3：V1 CS-EDU vs CS-INF 边界模糊

**问题**："栈桥免费，始建于1892年"——前半是信息（CS-INF），后半是知识（CS-EDU），整句标什么？审查报告指出这是"中高主观性"维度。

**影响**：CS-EDU在金标中的Kappa可能 < 0.70，影响该类别的训练数据质量。

**解决方向**：
- 方案A：采用语言标记规则（"始建于""传说""非遗"→ CS-EDU）——已在v3.0中提出但未整合到v3.3
- 方案B：删除CS-EDU，合并入CS-INF——丢失文化知识维度
- 方案C：保留CS-EDU但接受较低的Kappa（0.60-0.70），在论文中说明边界模糊性

**建议**：采用方案A——将v3.0中已设计的语言标记规则整合到v3.3的编码决策树中。

### P0-4：V3-L1 AT-EVL亚类的可行性

**问题**：AT-EVL的6个亚类（ADM/SAT/EXC/DIS/FRU/NOS）中，DIS vs FRU依赖"唤醒度"判断（"有点失望"vs"太失望了"），编码员难以可靠区分。NOS（怀旧/感慨）的"混合愉悦度×混合唤醒度"与其他5类的清晰定位不一致。

**影响**：
- DIS vs FRU的Kappa可能 < 0.60
- NOS的存在使分类体系不再是严格的Russell环状模型映射
- 增加编码认知负荷

**解决方向**：
- 方案A：合并DIS+FRU为"负面评价"（AT-EVL-NEG），保留ADM/SAT/EXC/NEG/NOS五类
- 方案B：删除全部亚类，仅保留AT-EVL主类——丢失情感质量维度
- 方案C：保留6类但接受较低的Kappa，在论文中说明亚类是探索性编码

**建议**：采用方案A——将DIS+FRU合并为NEG，从6类缩减为5类，降低编码难度同时保留情感质量维度。

## 三、P1——模型训练前必须解决

### P1-1：V3-L1 AT-INF vs AT-EVL 边界

**问题**："门票只要80"是AT-INF（客观信息）还是AT-EVL（隐含"便宜"的评价）？审查报告将此列为"高主观性"。

**影响**：AT-INF和AT-EVL的编码员间一致性可能较低，影响训练数据质量。

**解决方向**：
- 采用评价词词表（"美/好/棒/值/贵/坑"→ AT-EVL）替代主观判断
- "只要""才""而已"等语气副词不作为AT-EVL的判定依据

**建议**：在试标阶段用30条帖子测试AT-INF vs AT-EVL的Kappa，若 < 0.65则引入评价词词表规则。

### P1-2：sentiment_val的人工标注参照

**问题**：v3.3将sentiment_val定义为模型派生的P(POS)-P(NEG)。但训练集的sentiment_dir来自人工标注，如果训练集的sentiment_val也来自模型而非人工，就是"自己训练自己"的循环论证。

**影响**：模型输出的sentiment_val无法被独立验证。

**解决方向**：对阶段1的500条金标样本，人工标注sentiment_val（连续值），作为模型输出的参照标准。

**建议**：在阶段1金标编码中增加sentiment_val人工标注任务（每片段一个连续值），作为模型校准的基准。

### P1-3：V12场景语境SC-ICO vs SC-STR的主观性

**问题**："标志性景点"vs"日常场景"的区分依赖"对谁而言标志性"——栈桥对青岛是标志性，但对本地人是日常。审查报告将此列为"高主观性"。

**影响**：SC-ICO vs SC-STR的Kappa可能 < 0.65。

**解决方向**：
- 方案A：引入"可识别地标"判定标准——画面中出现可命名的地标建筑/景点→ SC-ICO
- 方案B：合并SC-ICO+SC-STR为"场景"单类，仅保留景别和视角两个子字段

**建议**：采用方案A——在试标阶段测试，若Kappa仍 < 0.65则采用方案B。

### P1-4：金标样本中低频类别的覆盖

**问题**：V3-L3的6个属性类别中，ASP-HYG（卫生与安全）和ASP-ACC（交通与可达性）在旅游UGC中的出现率可能很低（估计各<5%）。500条金标中每类可能只有25个正例，低于神经网络训练的最低要求。

**影响**：低频类别的模型F1可能 < 0.60，达不到目标值。

**解决方向**：
- 方案A：对低频类别进行定向过采样（在金标抽取时优先包含含ASP-HYG/ASP-ACC的帖子）
- 方案B：合并ASP-HYG+ASP-ACC为"辅助条件"单类
- 方案C：删除ASP-HYG和ASP-ACC，仅保留4个高频属性类别

**建议**：在试标阶段统计各ASP类别的出现率，若某类别 < 3%则采用方案C删除。

## 四、P2——论文投稿前必须解决

### P2-1：SRM/SAM/AAM的命名问题

**问题**：审查报告指出，SRM（策略→资源传导矩阵）中的"传导"一词暗示因果关系，但实际是统计共现关系。评审人可能质疑因果推断过度。

**影响**：论文方法论部分可能被评审人质疑。

**解决方向**：将"传导"改为"关联"或"共现模式"，或在论文中明确声明描述性性质。

**建议**：在论文中将SRM/SAM/AAM定义为"关联矩阵"而非"传导矩阵"，并在讨论部分引用ELM理论解释关联的可能机制。

### P2-2：V2用地质国标分类"创作者话语"的理论映射

**问题**：GB/T 18972-2017的分类逻辑是"目的地有什么资源"，但编码表用它来分类"创作者在文本中调用了什么资源"。两者存在差异——创作者可能夸大、虚构或选择性忽略某类资源。

**影响**：评审人可能质疑方法论的合理性。

**解决方向**：在论文方法论部分明确说明V2编码的是"创作者话语中的资源调用"而非"目的地实际资源禀赋"，并引用话语分析或修辞学理论作为支撑。

**建议**：在论文中增加一段方法论辩护，引用Krippendorff (2004) 或 Neuendorf (2017) 说明"从文本内容推断建构策略"的合理性。

### P2-3：研究问题与视觉轨的对齐

**问题**：RQ1-RQ3的文字表述均未提及图片分析。视觉轨编码（V11/V12/V14/V15）在方法论上是创新的，但需要在研究问题中有明确定位。

**影响**：评审人可能质疑"为什么要编码图片"。

**解决方向**：将RQ1扩展为包含视觉维度的表述，如"KOL和KOC通过文字和图片生产了怎样的目的地形象？"

**建议**：在论文引言中补充"旅游UGC的核心传播载体是视觉内容，文字往往只是辅助说明"的论述，并在RQ1中明确包含图片分析。

### P2-4：平台异质性的处理

**问题**：五平台（B站/携程/抖音/微博/小红书）的内容生态差异巨大——抖音以短视频为主、小红书以图文种草为主、知乎以长文本为主。编码表V7记录platform字段，但未讨论不同平台的编码调整策略。

**影响**：评审人可能质疑跨平台编码的可比性。

**解决方向**：在编码手册中提供五平台的语用特征对照表，说明编码规则如何跨平台统一应用。

**建议**：在论文中增加平台异质性的讨论段落，说明编码方案的跨平台适用性。

## 五、P3——改进项

### P3-1：V0.1创作者层级权重的敏感性分析

**问题**：四维度综合评估的权重分配（40/30/20/10）缺乏经验数据支撑。

**建议**：在论文中报告不同权重设置下的判定结果变化，作为稳健性检验。

### P3-2：V6=2隐性商业推广阈值的预实验

**问题**：V6=2的操作化标准（sentiment > 0.5且>80%且>3次）是经验性的，缺乏先验研究支撑。

**建议**：在试编码阶段收集数据，用ROC曲线确定最优阈值，替代当前的经验性阈值。

### P3-3：编码员争议案例库

**问题**：缺乏系统的边界案例积累，编码培训和论文附录缺乏支撑材料。

**建议**：在试标阶段积累20-30个典型边界案例，作为编码培训和论文附录的材料。
