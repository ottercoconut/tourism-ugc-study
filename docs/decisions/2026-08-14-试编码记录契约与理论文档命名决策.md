## 一、背景

文本轨已确定采用理论导向的结构化内容分析，并准备进入双人共同校准。此前的主要阻塞是：逐字段`UNK/NA`规则是否必须在看到材料前穷尽、行级`confidence`不能定位具体不确定字段、低置信备注缺少触发门，以及文本证据offset没有统一技术语义。同时，部分理论文档仍把版本号写入文件名，导致链接随版本变化并产生多个“当前文件”。

## 二、最终决定

### 2.1 状态规则采用“通用语义先行、字段细则后定”

共同校准前只统一`1/0/UNK/NA`的一般语义，不预先为每个字段建立复杂例外。共同校准用于发现字段专门规则，不计算正式信度；规则冻结后另取新样本进行独立盲试标。

若字段达到`alpha >= 0.80`、类别支持足够，且分歧审计没有发现反复出现的系统性边界问题，则不再追加字段专门规则。若修改值域、定义或适用条件，原信度失效，必须使用新的未讨论样本重新确认。共同校准期无法按现行规则唯一裁决的记录使用临时状态`UNRESOLVED`并进入问题登记，不得把它写入正式研究数据。

### 2.2 Confidence改为逐主观字段程序

每个主观人工判断均按五级锚点记录置信度；客观导入字段不评分，结构性`NA`记为`null`。置信度只用于风险复核和流程审计，不解释为准确概率、效度指标或模型监督目标。

- 5：直接明确证据，无合理替代判断；
- 4：证据清楚，仅需少量语境理解；
- 3：判断有依据，但接近边界或存在一个合理替代判断；
- 2：证据较弱、冲突或存在两个以上合理判断；
- 1：没有足够证据形成唯一判断。

`confidence <= 2`必须填写结构化备注并进入第二编码员重点复核。备注至少记录原因代码、可能的替代值和简短说明。原因代码固定为`BOUNDARY`、`CONTEXT`、`CONFLICT`、`EVIDENCE_MISSING`或`OTHER`。

### 2.3 文本offset采用统一契约

文本轨只使用`evidence_spans_json`。offset定位不可变`raw_text`，按Unicode字符从0开始，采用左闭右开区间`[start, end)`；每个跨度保存`fields`、`start`、`end`和`quote`，并必须通过`raw_text[start:end] == quote`校验。允许多个不连续跨度、跨度重叠，以及同一跨度支持多个字段。

实质性阳性判断原则上至少有一段最短充分证据；否定、程度和转折改变含义时须一并纳入。`0`、`UNK`、`NA`以及整体排除判断不伪造局部证据。原`resource_spans_json`和`aspect_spans_json`自编码表v3.6.0起停止使用。

### 2.4 理论文档文件名不携带版本信息

所有理论研究文档采用稳定、描述内容的文件名，不在文件名中加入`v3.4`、`v3.2`、“修订版”等版本标记。版本号、文档状态、生效日期和迭代记录只写在文档内部。日期型决策记录保留日期前缀，因为日期用于审计定位，不代表内容版本。

当前Markdown、Word投稿稿和历史Word草稿中的版本化文件名统一迁移为稳定文件名。历史材料不因重命名自动获得当前效力；其内部继续明确标记`HISTORICAL / NOT ALIGNED`及原内容版本。

## 三、影响范围

- 编码表升为v3.6.0，执行成熟度变为`CALIBRATION_READY / NOT_FROZEN`。
- 编码簿同步一般状态、逐字段置信度、低置信备注门和统一证据跨度。
- 方法审计、执行清单、模型映射和论文说明同步上位版本及文件路径。
- 理论文档文件名去除版本号或版本描述，并修复仓库内链接。
- 不修改代码、配置、测试、数据schema、正式研究数据或模型实现；工程承接须另行执行。
