## 目的与边界

本报告记录 tourism-ugc-study #20 所要求的头像历史数据治理。处置只覆盖已经被明确识别为非正式派生产物、历史备份或运行时产物的文件；正式 `TripPostCollect` SQLite、正文媒体、调度控制面和登录资料不在删除范围内。

删除动作通过系统废纸篓完成，因而项目路径中不再保留这些文件，但在废纸篓清空前仍可恢复。本报告不保存原始 UGC、作者标识、头像 URL 或 JSONL 内容。

## 已完成处置

### TripPostResearch 非正式派生库

已从 `data/processed/` 移除 12 个忽略产物：两个 v25 feasibility 派生 SQLite、两个冻结源快照、各自的 WAL/SHM、两个 snapshot manifest、旧 `cleaning_manifest.json` 与旧 `trippost_research.sqlite`。保留唯一说明文件 `data/processed/README.md`；没有建立新的派生库。

### TripPostCollect 历史备份与运行产物

- `data/backups/`：先按旧头像 schema/JSON 证据识别并移除 273 个文件，合计 57,743,089,664 bytes。保留 1 个经 JSON 内容复核未发现已知头像键或映射头像字段的 B 站历史备份。
- `outputs/`：处置前共有 43,344 个运行时文件。已移除除活动小红书运行目录外的全部历史运行产物；当时活动目录外共计 41,762 个文件。
- `temp/`：处置时没有文件。

正式数据库基线：schema v18，`web_post_images` 仅有 102,459 条 `content` 关系，逐帖 `post_images_count` 零错配，`integrity_check=ok`，外键检查无违规。正式库中不存在 `author_avatar` 关系或 `author_avatar_url` 列，且已扫描 JSON 列未发现已知头像键。
