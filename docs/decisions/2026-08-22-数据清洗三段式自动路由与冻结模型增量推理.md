# 数据清洗三段式自动路由与冻结模型增量推理

> **状态**：`FRAMEWORK_FROZEN / THRESHOLD_PENDING / IMPLEMENTATION_PENDING`
>
> **替代**：[数据清洗通用文本模型与全局审计口径](2026-08-22-数据清洗通用文本模型与全局审计口径.md)
>
> **适用范围**：旅游相关性数据清洗；不改变 KOL/KOC、内容编码或视觉研究的方法。

## 背景

数据清洗的实际目标是学习帖子是否与青岛旅游研究相关，并把这一判断用于自动化无关内容清洗。系统既需要处理当前未标注人口，也需要在未来新增记录到来时继续清洗，而不是每个批次都重新训练。与此同时，模型置信度不足的记录必须交给人工处理，自动排除只改变派生分析发布，不得删除源数据。

现有人工工作已经形成一份 700 条完成 CSV 和对应 manifest。它们本来就是从候选人口抽取、完成并封存的人工证据，不需要再次抽样，也不需要通过“导入标签”复制到数据库标注表。

## 评估过的方案

1. **全量人工处理**：避免模型错误，但无法实现所需的自动清洗能力，也不利于未来新增批次持续处理。
2. **单阈值自动二分**：自动覆盖高，但会强迫边界记录作自动决定，无法为置信度不足的记录保留人工通道。
3. **三段式选择性路由**：低无关概率自动保留，中间区间人工处理，高无关概率自动排除；在自动覆盖和错误控制之间保留明确接口。

增量处理同时比较了“每个新批次重新训练”和“冻结模型只做推理”。重新训练会让不同批次的概率和决定依赖不同模型，也把新增数据处理与重新标注、重新评估绑定；冻结模型推理能让当前与未来批次共享同一决策基础。

人工标签存储比较了“复制进数据库标注表”和“完成 CSV + manifest 作为权威源”。复制会产生两个可能不一致的标签副本；直接引用冻结文件并在数据库保存最终决定及证据哈希，权威关系更清楚。

## 最终决定

1. 所有来源帖子共同训练一个通用文本模型，输入只有规范化文本。平台只保留为来源谱系和构成披露字段，不进入特征、切分、阈值、审计配额或分类性能报告。
2. 首个正式模型采用字符 TF-IDF 和线性 SVM。训练部分内部以泄漏分组交叉验证生成折外分数，再用 Sigmoid 方法校准为 `p_unrelated`。
3. 作者、精确重复和最终确认的近重复关系共同组成泄漏分组。全体参考集统一按时间留出 20% 测试候选，再扩展到完整泄漏分组；其余数据进行全局分组分层训练/验证切分。
4. 模型与校准器冻结为不可变 artifact；阈值策略单独冻结。调整阈值不重新训练模型。
5. 路由固定为：
   - `p_unrelated <= T_keep`：自动保留；
   - `T_keep < p_unrelated < T_exclude`：人工处理；
   - `p_unrelated >= T_exclude`：从派生分析发布中自动排除，不删除源数据。
6. 已完成的 `tourism-relevance-completed.csv` 与 `round-manifest.json` 是现有 700 条人工标签的共同权威源。训练时直接读取标签并校验数据库身份与规范化文本；推理时跳过这 700 条，最终决定直接采用人工标签。标签不复制到 `text_post_annotations`。
7. 500 条概率样本保留原成员、纳入概率和总体估计用途；200 条定向样本只用于困难边界学习。
8. 初始全量和未来新增批次使用同一个冻结模型。新增记录通过结构门和规范化后直接推理，不触发 `fit` 或 artifact 替换。
9. 人工灰区、未来新增人工结果和保留集审计继续使用各自独立的完成 CSV 与 manifest。数据库只保存最终帖子决定和相应 CSV 哈希、任务身份、模型、策略及推理运行引用。
10. 部署后的常规审计只针对最终保留人口，采用全局抽样且不设置平台配额。自动排除人口不做常规随机审计。

## 当前未冻结项目

以下项目全部为 `UNSET`：

- `T_keep` 与 `T_exclude`；
- 保留集审计事件定义、样本量、最大事件率、单侧置信上限和区间方法；
- 模型测试指标和自动覆盖率的最低接受条件；
- 保留集审计失败后的恢复条件。

两个阈值最终必须满足 `0 <= T_keep < T_exclude <= 1`。在阈值、测试门和审计门冻结前，系统可以生成研究性概率，但所有未有人工作答的记录只能转人工，不得自动保留或自动排除。

## 失败降级与恢复

保留集审计失败时，模型仍可继续打分，但自动保留暂停，原自动保留区间全部转入人工处理。自动排除和原人工灰区继续按冻结策略运行。恢复自动保留必须创建并绑定新的阈值策略，满足尚待冻结的恢复门；不得原地修改旧策略、改写旧运行或更换抽样结果以追求通过。

参考 CSV/manifest 哈希不符、记录身份或规范化文本不一致、泄漏跨集合、测试集参与调参、阈值非法、推理调用训练、源库写入或 artifact 不完整时，运行必须失败关闭。

## 可靠性声明边界

正式结果可以声明的是：在冻结测试证据、三段式路由和通过门的保留集审计共同约束下，最终保留语料的残留无关风险受到控制。

由于不对自动排除人口做常规随机审计，不能声称部署期所有被排除记录都经过直接验证。避免过度删除的证据仅来自锁定测试集上的总体 Precision、Recall、F1、PR-AUC、混淆矩阵和阈值表现；论文必须披露这一限制。

## 实施状态与正式化

本决策继续冻结文档和工程接口。稳定配置、参考证据只读校验、500/200 样本迁移 manifest、独立内部 schema，以及字符 TF-IDF＋线性 SVM＋训练集分组折外 Sigmoid 的 baseline 训练代码已经完成。首次正式模型尚未训练，锁定测试集尚未开启，也未导入标签、执行正式推理或确定任何阈值。

后续依次封存泄漏分组、执行首次 baseline 训练、依据训练折外与验证证据讨论全部 `UNSET` 项、冻结策略后开启一次锁定测试、实现无训练增量推理、人工覆盖、保留集审计状态机和完整验收。四份核心文档只有在代码、阈值、测试和验收全部完成后才能统一改为 `CURRENT / FORMAL`；人类可读方法文档不再显示协议版本号，技术 artifact 继续保留内部 ID、哈希和运行谱系。
