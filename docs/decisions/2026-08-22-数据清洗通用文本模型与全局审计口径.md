# 数据清洗通用文本模型与全局审计口径

> **文档状态**：`HISTORICAL`
>
> **superseded_by**：[数据清洗三段式自动路由与冻结模型增量推理](2026-08-22-数据清洗三段式自动路由与冻结模型增量推理.md)
>
> **使用边界**：仅记录曾经批准但未进入正式实现的中间设计，不定义当前清洗方法。

## 当时解决的问题

该中间设计首先纠正了按平台训练、按平台分配测试名额、设置平台负例门和逐平台审计配额的做法。它决定把所有来源帖子作为一个通用文本分类任务，并把平台限制为来源谱系和构成披露字段。

## 当时的主要选择

1. 一个只读取规范化文本的跨来源通用模型；
2. 作者、精确重复和已确认近重复关系组成泄漏分组；
3. 全局时间测试和总体分类指标，不报告平台分类性能；
4. 保留已完成的 500 条概率样本及其纳入概率，来源比例只解释为人口构成；
5. 使用两层全局审核，并限制模型只产生审核建议，不直接自动排除。

## 被替代的原因

后续需求明确要求系统具备真实的自动清洗能力，同时把置信度不足的记录交给人工处理，并支持未来新增记录在不重新训练的情况下继续清洗。中间设计没有清楚分离模型 artifact、阈值策略和增量推理，也把审核门提前写死，且保留了“模型不得自动排除”的限制，因此不能作为最终框架。

替代决策改为以校准后的 `p_unrelated` 做三段式路由，允许自动保留、人工灰区和自动排除；阈值与保留集审计门全部回到 `UNSET`。本段关于旧700条直接作为权威源的设想又被 Issue #39 替代：当前只承认 `final-nonduplicate-model-reference` CSV 与唯一配对 `finalized` manifest，旧完成文件只作迁移谱系。

## 历史影响

该记录中“跨来源通用模型、平台不参与模型决策、全局泄漏安全切分、保留概率样本”四项方向被新决策继承。两层固定审核、预设审核门和模型不得自动排除的规则均已废止，从未成为正式可执行清洗流程。
