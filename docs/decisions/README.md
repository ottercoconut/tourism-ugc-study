对于会改变样本、标签、模型或论文解释的决定，新增一份短记录：

```text
YYYYMMDD-short-title.md
```

每份记录包含：背景、候选方案、最终决定、理由、影响范围、回滚方式和批准人。这里记录“为什么”，代码和配置记录“怎么做”。

涉及研究范围、构念、标签、编码单位、值域、派生关系或标注方案的决定，只有写入`../data-dictionary/编码表.md`、更新其内部版本并完成下游版本对齐后才成为现行规范。仅存在于决策记录中的内容状态为`PROPOSAL`，不得直接指导标注或模型实现。

决策记录用于保留当时的理由和证据，不因后续版本变化逐段改写。失效记录统一在头部标记`HISTORICAL`并用`superseded_by`指向替代版本；发生冲突时，编码表始终优先。

理论文档文件名使用稳定内容名称，不附加版本号或“修订版”。版本、状态、生效日期与迭代记录在文内；日期型决策保留日期前缀。数据清洗、实验事实和治理决定以各自manifest为事实源；编码表只约束直接涉及研究编码构念与记录契约的部分，历史决策不机械升版。
