## 一、需要解决的问题

研究希望使用BERT对旅游UGC语义片段同时预测内容策略V1、目的地资源V2、语言功能V3和互动信号V5。上述维度中的原子标签可能共现，例如同一片段既包含事实信息，也包含评价或建议。

因此，目标不是一个统一的普通单标签分类器，而是：

> **共享文本编码器之上的多任务、多头、混合输出分类：可共现原子标签用Sigmoid，条件互斥的情感方向用Softmax，派生字段不另设输出头。**

这里需要特别区分“意象”和“意向”：

- “大海、高楼”是目的地对象、资源或意象标签；
- “推荐、再访、劝阻、比较”才是行为意向或推荐意图标签。

如果原讨论中的“意向”实际指“意象”，正式研究文档中应统一术语，避免把目的地表征对象与作者行为意图放进同一个分类头。

## 二、框架的核心设计原则

### 2.1 并行维度与独立输出

这套框架建立在以下原则之上：

1. **不同理论维度并行编码**：内容策略、价值、形象和情感不是同一个变量，不能合并成一个标签池。
2. **维度之间按定义判断**：除编码簿明确规定的派生关系外，某一维度命中标签不自动推出另一维度的标签。
3. **输出结构由构念决定**：可同时成立的原子属性使用`0/1 × K`；条件互斥类别使用Softmax；可由原子标签或概率计算的字段不重复训练。
4. **帖子级输出**：片段中出现的语义最终回到完整帖子，形成可用于论文分析的帖子级变量。
5. **创作者属性与内容编码分离**：作者层级是外部解释变量或分组变量，不应成为正文 BERT 的主要预测目标。

这些维度在理论上彼此区分，在模型中共享同一个 BERT 编码器。共享编码器负责学习通用旅游语言表示，各维度分类头只负责把该表示投射到各自的研究变量空间。

对当前争议最大的V1与V3，采用原子多标签结构：V1人工金标为`cs_inf/cs_edu/cs_emo`，V3为`at_has_info/at_has_eval/at_has_sug`。V1的`cs_int`由V5派生，两个维度的“无/其他”均由零向量派生。帖子级结果由各原子标签的出现率或密度聚合，不再生成“主要类别”。

### 2.2 分析单位与证据单位

本框架区分两个相互关联但不能混同的单位：

> **帖子是论文比较与汇总的主要单位；预先固定的语义片段是V1/V2/V3/V5金标决策单位，也是标签成立的证据单位。**

也就是说：

- V1/V2/V3/V5的人工金标在固定语义片段上记录原子标签及证据；
- 同一帖子可由多个分句支持同一或不同标签；
- 帖子级“是否出现”标签可以从分句证据聚合，也可作为单独的存在性任务训练；
- 若论文分析需要各策略的频数、比例或共现关系，则片段级分类不能被一个帖子级存在标签替代；
- 片段证据同时服务于仲裁、长文本聚合、可解释性与辅助训练。

### 2.3 原子标签与派生指标

模型首先预测原子标签，不直接预测由多个标签组合而成的编号或指数。例如，三个二值标签可以在分析阶段形成若干组合模式，但组合编号不应替代三个原始输出。这样可以保留每个标签的独立概率、错误来源和理论含义。

帖子级密度、广度、共现模式和综合指数都属于派生指标，应在模型输出后计算。模型预测层与论文统计层由此保持分离：模型负责识别内容，统计分析负责组合和解释这些识别结果。

## 三、总体模型架构

推荐采用一个共享BERT编码器，以及按研究维度与输出性质划分的多个分类头。项目基线结构为：

```text
固定语义片段
       │
       ▼
共享 BERT 编码器
       │
       ├── V1内容策略头：3个 Sigmoid
       ├── V2资源头：9个 Sigmoid
       ├── V3语言功能头：3个 Sigmoid
       ├── V3情感方向头：4类条件 Softmax
       └── V5互动信号头：3个 Sigmoid
```

一个“分类头”对应一个理论维度，而不是一个标签。一个头内部有该维度全部标签的输出节点。

设第 `d` 个维度有 `K_d` 个标签，其目标向量为：

\[
\mathbf y^{(d)} \in \{0,1\}^{K_d}
\]

例如，V3语言功能头的标签顺序为：

```text
[AT-INF, AT-EVL, AT-SUG]
```

一个同时提供事实并作出评价的片段，其目标是：

```text
[1, 1, 0]
```

而不是建立一个新的复合类别“INF+EVL”。

派生字段由规则层计算：

```text
cs_int = OR(is_que, is_dir, is_soc)
cs_oth = NOT OR(cs_inf, cs_edu, cs_emo, cs_int)
at_non = NOT OR(at_has_info, at_has_eval, at_has_sug)
is_non = NOT OR(is_que, is_dir, is_soc)
rs_n / rs_r = 对应Layer 2标签的OR聚合
sentiment_val = calibrated P(POS) - P(NEG)
```

这些字段具有确定的逻辑来源，不再单设Softmax或Sigmoid头，否则同一信息会以两个损失重复监督，并可能产生相互矛盾的输出。

## 四、何时使用 Sigmoid，何时使用 Softmax

当第 `d` 个输出由可同时成立的标签组成时，其基础计算为：

\[
\mathbf p^{(d)} = \sigma(W_d \mathbf h + \mathbf b_d)
\]

其中：

- `h`是BERT对当前任务输入单位得到的表示；V1/V2/V3/V5为片段表示，纯帖子级任务为帖子表示；
- `W_d` 的输出维度是 `K_d`；
- `σ` 对每个标签独立计算 Sigmoid 概率。

此时不能使用覆盖整个标签头的 Softmax。Softmax 会令所有标签概率和为 1，隐含假设是这些标签彼此互斥，因此会让“大海”和“高楼”相互竞争。

Sigmoid 则允许：

```text
P(大海 | post) = 0.92
P(高楼 | post) = 0.81
P(山岳 | post) = 0.08
```

模型可以同时判定前两个标签成立。

反之，并非所有研究变量都必须使用 Sigmoid：

| 变量性质 | 推荐输出形式 |
|---|---|
| 同一维度可同时命中多个标签 | 多个 Sigmoid |
| 理论上严格互斥的单一类别 | Softmax |
| 有独立人工连续金标的变量 | 回归头；本项目当前没有此类文本标签 |
| 有顺序等级但间距不确定 | 序数分类头 |
| 作者粉丝量、平台、发布时间等外部变量 | 直接从数据库读取，不由正文 BERT 预测 |

因此，“每个维度使用哪种头”应由变量的测量性质决定，而不是为了统一代码全部改成多标签。

## 五、从共享 `[CLS]` 到标签级注意力

### 5.1 基线方案

多标签原子项最简单的基线是使用BERT的`[CLS]`表示：

```text
BERT → h_[CLS] → Linear(hidden_size, K_d) → Sigmoid
```

它实现容易，适合首先建立可复现实验基线。V3情感方向头只在片段包含评价或建议时计算Softmax损失；V1/V2/V3/V5的多标签头使用Sigmoid。

### 5.2 推荐方案：标签级注意力

旅游帖子的多个标签通常由不同文本片段触发。例如：

```text
第一段描述海岸和沙滩       → 支持“大海”
第三段描述城市天际线       → 支持“高楼”
第五段建议避开节假日       → 支持“劝阻/提醒”
```

如果所有标签只共享一个 `[CLS]` 向量，不同位置的证据可能被压缩或稀释。推荐让每个标签拥有自己的可学习查询向量，对全部 token 表示进行注意力聚合：

\[
\mathbf z_{d,k} = \operatorname{Attention}(\mathbf q_{d,k}, H)
\]

\[
p_{d,k} = \sigma(\mathbf w_{d,k}^{T}\mathbf z_{d,k} + b_{d,k})
\]

其中：

- `H` 是 BERT 输出的全部 token 上下文表示；
- `q_(d,k)` 是第 `d` 个维度中第 `k` 个标签的查询向量；
- `z_(d,k)` 是专门服务于该标签的帖子表示。

这样，“大海”和“高楼”可以分别关注不同句子，同时保持共享的 BERT 语言表示。

标签级注意力还可以输出每个标签最关注的文本位置，为论文中的模型解释和人工复核提供证据。但注意力权重只能作为辅助解释，不能自动等同于因果解释。

## 六、分句金标、帖子聚合与证据

建议将数据组织为两层，但两层承担不同任务。

### 6.1 片段级金标

V1/V2/V3/V5的原子标签直接记录在预先固定的语义片段上：

```json
{
  "post_id": "P001",
  "seg_id": 3,
  "text": "这个景点门票只要80元",
  "char_start": 35,
  "char_end": 47,
  "cs": {"inf": 1, "edu": 0, "emo": 0},
  "resources": {"n_geo": 0, "n_wat": 0, "n_bio": 0, "n_cli": 0, "r_his": 0, "r_arc": 1, "r_gas": 0, "r_fol": 0, "r_act": 0},
  "resource_spans": {"r_arc": [[5, 7]]},
  "at": {"info": 1, "eval": 1, "sug": 0},
  "sentiment_dir": "POS",
  "interaction": {"que": 0, "dir": 0, "soc": 0}
}
```

该层直接支持片段分类、编码仲裁，以及帖子内各类内容的频数和比例计算。

### 6.2 帖子级聚合与标签证据

帖子级字段由分句金标按预先定义的规则聚合：

```json
{
  "post_id": "P001",
  "cs_density": {"inf": 0.5, "edu": 0.1, "emo": 0.2, "int": 0.0},
  "at_density": {"info": 0.4, "eval": 0.3, "sug": 0.1},
  "cs_presence": {"inf": 1, "edu": 1, "emo": 1, "int": 0},
  "at_presence": {"info": 1, "eval": 1, "sug": 1}
}
```

每个帖子级正标签应能够回指一个或多个`seg_id`。这些证据用于：

- 支撑人工编码仲裁；
- 解释帖子为什么获得某标签；
- 为长文本分块提供监督；
- 在需要时增加 token/span 级辅助损失。

若某个研究维度本来就是纯帖子级构念，可以直接进行帖子级标注；不能把V1/V2/V3/V5的片段级原子标签与纯帖子级存在标签混成同一个任务。

## 七、长文本的分块与标签聚合

数据库中的帖子长度差异较大，完整帖子可能超过普通 BERT 的上下文长度。此时不能简单截断前 512 个 token，否则后文出现的标签会系统性漏检。

推荐使用层级式文本编码：

```text
完整帖子
  ├── chunk 1 → BERT → chunk 表示
  ├── chunk 2 → BERT → chunk 表示
  ├── chunk 3 → BERT → chunk 表示
  └── ……
             │
             ▼
      帖子级标签聚合
```

聚合仍应按标签独立进行，因为“大海”可能只出现在第一段，“高楼”可能只出现在最后一段。

可以比较三种方案：

1. **标签级 max pooling**：某个分块强烈命中即可激活帖子标签；
2. **Noisy-OR**：多个分块的弱证据共同提高帖子级概率；
3. **标签级 attention pooling**：由模型学习每个标签应关注哪些分块。

存在性较强的标签可用 max pooling 作为基线；正式模型优先考虑标签级 attention pooling。简单平均容易让局部但明确的标签证据被大量无关片段冲淡。

## 八、层级标签与标签关联

### 8.1 层级标签

如果某个标签头内部具有父子关系，模型可以同时输出父标签和子标签。例如：

```text
父类
├── 子类 A
└── 子类 B
```

应满足：

\[
p(\text{子类}) \le p(\text{父类})
\]

实现方式可以是：

- 在金标中由子标签自动补齐父标签；
- 在训练损失中加入层级一致性惩罚；
- 在推理后处理中修正违反层级的结果。

父子层级不改变多标签性质。并列标签仍可同时成立。

### 8.2 标签共现

第一版模型不建议预先硬编码标签共现关系。共享 BERT 和联合训练已经能够学习部分关联，过早加入规则容易把现有样本中的平台偏差或城市偏差固化为“理论关系”。

推荐顺序为：

1. 先训练独立 Sigmoid 基线；
2. 观察稳定的标签共现和错误模式；
3. 只有在跨平台、跨时间仍稳定时，再尝试标签图、classifier chain 或标签间 Transformer。

### 8.3 组合空间不等于组合类别

`K` 个二元标签在逻辑上最多产生 `2^K` 个标签集，但独立 Sigmoid/Binary Relevance 将其分解为 `K` 个二元任务，并不训练一个 `2^K` 类 Softmax。因此：

- 不要求训练集覆盖全部逻辑组合；
- 每个标签仍必须有足够的正例与负例；
- 若要把某个组合当成分析组、学习标签依赖或估计高阶交互，则目标组合必须有足够样本；
- 未观察到的组合不能自动解释为“理论上不可能”，也不能在没有证据时用合成样本补齐。

在模型训练前，必须先用双人试编码报告每个标签的阳性数、流行率、平均标签数、观察到的标签集及频数。样本不足时优先修改研究问题、合并/删除标签或将稀有组合降为描述性结果，而不是直接增加模型复杂度。

## 九、损失函数设计

第 `d` 个多标签头使用逐标签二元交叉熵：

\[
L_d = \frac{1}{K_d}\sum_{k=1}^{K_d}
m_{d,k}\operatorname{BCE}(y_{d,k},p_{d,k})
\]

其中 `m_(d,k)` 是有效性掩码：

- 已确定为存在或不存在：`m=1`；
- 无法判断、证据不足或不适用：`m=0`，不进入该标签损失。

总损失为：

\[
L = \sum_d \lambda_d L_d
\]

`λ_d` 用于平衡不同研究维度。维度内标签不平衡时，可以使用：

- 正类别权重；
- Focal Loss；
- Asymmetric Loss；
- 分层采样。

不建议仅按标签频率机械设置极端权重，应同时观察召回率、概率校准和误报成本。

V1/V2/V3/V5的总损失可写为：

\[
L = \lambda_{V1}L_{V1} +
\lambda_{V2}L_{V2} +
\lambda_{V3}L_{V3} +
\lambda_{V5}L_{V5} +
\lambda_{sent}L_{sent}
\]

`L_sent`只在片段含`AT-EVL`或`AT-SUG`且人工给出情感方向时生效。派生字段在规则层计算，不加入重复的一致性损失。

## 十、阈值和输出数量

对多标签原子项，模型不应预设“一个输入必须输出几个标签”，也不应统一采用Top-k。

不同帖子可能：

- 没有某一维度的有效标签；
- 只有一个标签；
- 同时包含多个标签。

每个标签应在验证集上单独确定决策阈值：

```text
标签 A：threshold = 0.42
标签 B：threshold = 0.58
标签 C：threshold = 0.35
```

统一使用 `0.5` 可以作为基线，但不应直接作为最终规则。稀有标签、边界模糊标签和高频标签的最佳阈值通常不同。

如果论文分析需要概率而非硬标签，应保存：

- 原始 logit；
- Sigmoid 概率；
- 使用的标签阈值；
- 最终二值结果；
- 模型版本。

这能保证后续敏感性分析和结果复现。

## 十一、预训练与分类训练的边界

编码簿不直接参与标准 BERT 预训练。建议将训练流程分成两个阶段：

### 阶段 A：旅游领域继续预训练

- 使用未标注旅游 UGC；
- 主要任务为 Masked Language Modeling；
- 目标是学习旅游语汇、平台表达和上下文模式；
- 此阶段没有“旅游主题头”等人工标签输出。

### 阶段 B：多任务、混合输出监督微调

- 加载阶段 A 的 BERT 编码器；
- 按输出性质添加Sigmoid和条件Softmax头；当前文本标签没有独立连续金标，故不设回归头；
- V1/V2/V3/V5使用片段级原子标签训练，再按预定规则生成派生字段并聚合到帖子级；
- 纯帖子级多标签维度使用帖子级 multi-hot 金标；
- 可选加入证据跨度辅助任务。

因此，准确说法应是：

> 编码簿定义监督微调和论文变量；继续预训练为这些任务提供领域语言表示。

## 十二、推荐的模型迭代顺序

### Model 0：可解释的最小基线

```text
BERT
  → [CLS]
  ├── V1/V2/V3/V5原子标签：Linear → Sigmoid
  └── 条件情感方向：Linear → Softmax
```

用途：验证标签体系是否可学，建立后续模型比较基线。

### Model 1：标签级注意力

```text
BERT token 表示
  → 每个标签独立查询文本证据
  → Sigmoid
```

用途：解决同一帖子中不同标签由不同片段触发的问题。

### Model 2：长文本层级模型

```text
帖子分块
  → chunk BERT
  → 标签级 chunk attention
  → 帖子级多标签输出
```

用途：解决超过 BERT 上下文长度的帖子和跨段证据。

### Model 3：结构化标签模型

在前述模型稳定后，增加：

- 父子层级约束；
- 标签关系图；
- 标签描述向量；
- 证据抽取辅助头。

不能跳过 Model 0 直接使用复杂标签图，否则难以判断性能来自 BERT、注意力、标签相关性还是数据偏差。

---

## 十三、模型评估应与编码结构一致

不能只报告一个整体 Accuracy。建议至少报告：

### 每个维度

- 原子多标签：逐标签Precision/Recall/F1和PR-AUC，以及Micro/Macro-F1；
- 条件情感方向：Macro-F1、各类别Precision/Recall/F1和混淆矩阵；
- 标签覆盖率、平均预测标签数和实际组合频数。

### 每个标签

- Precision；
- Recall；
- F1；
- 决策阈值；
- 阳性样本量；
- 概率校准情况。

### 结构化检查

- 父子标签一致率；
- 不同平台、城市、作者组的性能；
- 长文本与短文本的性能；
- 人工编码者之间的逐标签一致性；
- 模型与仲裁金标之间的逐标签一致性。

人工编码信度也应按每个二值标签分别计算，不能只把一个维度下所有标签合并后报告平均 Kappa，否则稀有标签的低信度会被高频标签掩盖。

---

## 十四、最终架构决策

结合当前研究目标，建议冻结以下原则：

| 问题 | 决策 |
|---|---|
| 主要分析与汇总单位 | 一篇完整帖子 |
| V1/V2/V3/V5金标单位 | 预先固定、可独立判断功能的语义片段 |
| 一个理论维度有几个技术头 | 由输出结构决定；派生字段不设输出头 |
| 原子标签如何表示 | 可同时成立的标签使用独立Sigmoid |
| 条件情感方向如何表示 | 片段含评价/建议时使用Softmax |
| 是否允许多标签 | 允许；只标明确表达，并保留证据位置 |
| “大海、高楼”如何表示 | 同一向量中的两个位置同时为 1 |
| 是否建立“大海+高楼”组合类 | 不建立 |
| 是否要求覆盖全部 `2^K` 组合 | 不要求；但每个标签及计划分析的组合必须有足够样本 |
| 帖子级表示 | 基线用 `[CLS]`，推荐使用标签级注意力 |
| 长文本 | 分块编码后按标签聚合 |
| 标签层级 | 保留父子关系并检查一致性 |
| 标签共现 | 先试编码并训练独立基线；样本充分且跨域稳定后再显式建模 |
| 预训练是否使用编码簿 | 标准 MLM 不使用；编码簿用于监督微调 |
| 作者层级、粉丝量 | 外部变量，不由正文 BERT 预测 |
| 视觉标签 | 另设视觉模型，不进入当前文本 BERT |

最终推荐框架可概括为：

> **以帖子为分析与汇总单位，以固定语义片段为文本金标与证据单位；共享BERT只预测可共现原子标签和条件情感方向，派生字段由规则层生成；先验证逐标签人工信度和样本分布，再决定是否学习标签依赖。**
