## 一、需要解决的问题

文本主轨拟使用BERT对预先固定的旅游UGC语义片段预测内容策略V1、目的地资源V2、V3语言功能/情感方向/评价亚类/属性指向和互动信号V5。上述维度中的原子标签可能共现，例如同一片段既包含事实信息，也包含评价或建议。

因此，目标不是一个统一的普通单标签分类器，而是：

> **共享文本编码器之上的多任务、多头、混合输出分类：可共现原子标签用Sigmoid，条件互斥类别用Softmax，派生字段不另设输出头；`at_eval_subtype`的单选/多选责任冻结前不确定其最终损失形式。**

这里需要特别区分“意象”和“意向”：

- “大海、高楼”是目的地对象、资源或意象标签；
- “推荐、再访、劝阻、比较”才是行为意向或推荐意图标签。

如果原讨论中的“意向”实际指“意象”，正式研究文档中应统一术语，避免把目的地表征对象与作者行为意图放进同一个分类头。

## 二、框架的核心设计原则

### 2.1 并行维度与独立输出

这套框架建立在以下原则之上：

1. **不同理论维度并行编码**：内容策略、价值、形象和情感不是同一个变量，不能合并成一个标签池。
2. **维度之间按定义判断**：除编码表明确规定的派生关系外，某一维度命中标签不自动推出另一维度的标签。
3. **输出结构由构念决定**：可同时成立的原子属性使用`0/1 × K`；条件互斥类别使用Softmax；可由原子标签或概率计算的字段不重复训练。
4. **片段级监督、规则聚合**：当前模型只在固定片段上训练；候选帖子级变量只能由片段结果按编码表规则派生，不另设帖子存在性任务，且帖子级聚合目前为`DEFERRED`。
5. **创作者属性与内容编码分离**：作者层级是外部解释变量或分组变量，不应成为正文 BERT 的主要预测目标。

这些维度在理论上彼此区分，在模型中共享同一个 BERT 编码器。共享编码器负责学习通用旅游语言表示，各维度分类头只负责把该表示投射到各自的研究变量空间。

对当前争议最大的V1与V3，采用原子多标签结构：V1人工金标为`cs_inf/cs_edu/cs_emo`；V3-L1为`at_has_info/at_has_eval/at_has_sug`，并在条件成立时记录`at_eval_subtype`、V3-L2 `sentiment_dir`与V3-L3六个`asp_*`字段。V1的`cs_int`由V5派生，两个维度的“无/其他”均由零向量派生。`at_eval_subtype`的记录与输出责任仍受编码表T0约束；候选帖子级出现率或密度目前为`DEFERRED`，不进入当前训练目标。

### 2.2 分析单位与证据单位

本框架区分两个相互关联但不能混同的单位：

> **帖子是论文比较与汇总的主要单位；预先固定的语义片段是V1/V2/V3/V5金标决策单位，也是标签成立的证据单位。**

也就是说：

- V1/V2/V3/V5的人工金标在固定语义片段上记录原子标签及证据；
- 同一帖子可由多个固定片段支持同一或不同标签；
- 不得把帖子级“是否出现”另设为监督任务；未来若启用帖子级存在字段，只能由片段级结果按编码表规则派生；
- 帖子级频数、比例与共现聚合当前为`DEFERRED`，不能反向改变片段级标签或训练目标；
- 片段证据首先服务于人工仲裁、模型验证与可解释复核；长文本聚合和辅助训练属于候选扩展。

### 2.3 原子标签与派生指标

模型首先预测原子标签，不直接预测由多个标签组合而成的编号或指数。例如，三个二值标签可以在分析阶段形成若干组合模式，但组合编号不应替代三个原始输出。这样可以保留每个标签的独立概率、错误来源和理论含义。

帖子级密度、广度、共现模式和综合指数都属于候选派生指标，当前状态为`DEFERRED`。只有编码表后续启用具体指标时，才可在模型输出后按其规则计算；模型预测层与论文统计层始终分离。

## 三、总体模型架构

当前最小基线采用一个共享BERT编码器，并按监督字段的输出性质划分技术头：

```text
固定语义片段
       │
       ▼
共享 BERT 编码器
       │
       ├── V1内容策略头：3个 Sigmoid
       ├── V2资源头：9个 Sigmoid
       ├── V3-L1语言功能头：3个 Sigmoid
       ├── V3 AT-EVL亚类头：6维条件输出（形式待T0冻结）
       ├── V3-L2情感方向头：4类条件 Softmax
       ├── V3-L3属性指向头：6个条件 Sigmoid
       └── V5互动信号头：3个 Sigmoid
```

技术头按监督字段的输出结构划分，不与理论维度机械一一对应：同一理论维度可以因条件与值域不同而拆成多个技术头，但不为每个派生字段或组合类别另设头。

设第 `d` 个维度有 `K_d` 个标签，其目标向量为：

\[
\mathbf y^{(d)} \in \{0,1\}^{K_d}
\]

例如，V3语言功能头的标签顺序为：

```text
[AT-INF, AT-EVL, AT-SUG]
```

一个同时提供事实并作出评价的片段，其目标是：

```text
[1, 1, 0]
```

而不是建立一个新的复合类别“INF+EVL”。

V3的另外三个技术头遵循以下边界：

- `at_eval_subtype`仅在`at_has_eval=1`时有效，候选节点为ADM/SAT/EXC/DIS/FRU/NOS；其单选Softmax还是多选Sigmoid由编码表T0裁决，冻结前不得实现正式损失。
- `sentiment_dir`在`at_has_eval=1`或`at_has_sug=1`时使用POS/NEG/MIX/NEU条件Softmax；无评价/建议时的NEU及`UNK/NA`传播仍服从编码表记录契约。
- V3-L3的`asp_res/asp_pri/asp_ser/asp_cro/asp_acc/asp_hyg`可共现，条件成立时使用六个Sigmoid；无评价/建议时存`0`还是`NA`仍是T0未决项。

派生字段由规则层计算：

```text
cs_int = OR(is_que, is_dir, is_soc)
cs_oth = NOT OR(cs_inf, cs_edu, cs_emo, cs_int)
at_non = NOT OR(at_has_info, at_has_eval, at_has_sug)
is_non = NOT OR(is_que, is_dir, is_soc)
rs_n / rs_r = 对应Layer 2标签的OR聚合
sentiment_val = calibrated P(POS) - P(NEG)
```

这些字段不再单设Softmax或Sigmoid头，否则同一信息会以两个损失重复监督，并可能产生相互矛盾的输出。具体OR、零向量以及`UNK/NA`传播真值表尚未冻结，实际规则实现必须等待编码表关闭对应T0项。

## 四、何时使用 Sigmoid，何时使用 Softmax

当第 `d` 个输出由可同时成立的标签组成时，其基础计算为：

\[
\mathbf p^{(d)} = \sigma(W_d \mathbf h + \mathbf b_d)
\]

其中：

- `h`是BERT对当前固定文本片段得到的表示；当前不设置帖子级存在性输入或输出任务；
- `W_d` 的输出维度是 `K_d`；
- `σ` 对每个标签独立计算 Sigmoid 概率。

此时不能使用覆盖整个标签头的 Softmax。Softmax 会令所有标签概率和为 1，隐含假设是这些标签彼此互斥，因此会让“大海”和“高楼”相互竞争。

Sigmoid 则允许：

```text
P(大海 | segment) = 0.92
P(高楼 | segment) = 0.81
P(山岳 | segment) = 0.08
```

模型可以同时判定前两个标签成立。

反之，并非所有研究变量都必须使用 Sigmoid：

| 变量性质 | 推荐输出形式 |
|---|---|
| 同一维度可同时命中多个标签 | 多个 Sigmoid |
| 理论上严格互斥的单一类别 | Softmax |
| V3-L3条件多选属性指向 | 6个条件Sigmoid |
| `at_eval_subtype` | 6维条件头；单选/多选与损失形式待编码表T0冻结 |
| 有独立人工连续金标的变量 | 回归头；本项目当前没有此类文本标签 |
| 有顺序等级但间距不确定 | 序数分类头 |
| 作者粉丝量、平台、发布时间等外部变量 | 直接从数据库读取，不由正文 BERT 预测 |

因此，“每个维度使用哪种头”应由变量的测量性质决定，而不是为了统一代码全部改成多标签。

## 五、当前 `[CLS]` 基线与候选复杂架构

### 5.1 基线方案

多标签原子项最简单的基线是使用BERT的`[CLS]`表示：

```text
BERT → h_[CLS] → Linear(hidden_size, K_d) → Sigmoid
```

它实现容易，适合首先建立可复现实验基线。V1、V2、V3-L1、V3-L3和V5的可共现字段使用Sigmoid；V3情感方向头只在片段包含评价或建议时计算Softmax损失；`at_eval_subtype`等待T0冻结后再确定损失。

### 5.2 候选方案：标签级注意力（`DEFERRED`）

> 本节只保留未来对照思路，不属于当前模型任务，也不得替代最小`[CLS]`基线。

旅游帖子的多个标签通常由不同文本片段触发。例如：

```text
第一段描述海岸和沙滩       → 支持“大海”
第三段描述城市天际线       → 支持“高楼”
第五段建议避开节假日       → 支持“劝阻/提醒”
```

如果未来证据表明共享`[CLS]`确实造成稳定的信息压缩，可评估让每个标签拥有自己的可学习查询向量，对全部token表示进行注意力聚合：

\[
\mathbf z_{d,k} = \operatorname{Attention}(\mathbf q_{d,k}, H)
\]

\[
p_{d,k} = \sigma(\mathbf w_{d,k}^{T}\mathbf z_{d,k} + b_{d,k})
\]

其中：

- `H` 是 BERT 输出的全部 token 上下文表示；
- `q_(d,k)` 是第 `d` 个维度中第 `k` 个标签的查询向量；
- `z_(d,k)` 是专门服务于该标签的帖子表示。

这样，“大海”和“高楼”可以分别关注不同句子，同时保持共享的 BERT 语言表示。

标签级注意力还可以输出每个标签最关注的文本位置，为论文中的模型解释和人工复核提供证据。但注意力权重只能作为辅助解释，不能自动等同于因果解释。

## 六、固定片段金标、候选帖子聚合与证据

当前监督数据以固定片段为唯一模型任务单位；帖子层只保留未来规则聚合接口，两层不得形成重复监督。

### 6.1 片段级金标

V1/V2/V3/V5的原子标签直接记录在预先固定的语义片段上：

```json
{
  "post_id": "P001",
  "seg_id": 3,
  "raw_text": "门票80元，很值得去",
  "cs_inf": 1,
  "cs_edu": 0,
  "cs_emo": 0,
  "at_has_info": 1,
  "at_has_eval": 1,
  "at_eval_subtype": "SAT",
  "at_has_sug": 0,
  "sentiment_dir": "POS",
  "asp_res": 1,
  "asp_pri": 1,
  "asp_ser": 0,
  "asp_cro": 0,
  "asp_acc": 0,
  "asp_hyg": 0,
  "aspect_spans_json": {"asp_res": [[7, 10]], "asp_pri": [[0, 10]]},
  "is_que": 0,
  "is_dir": 0,
  "is_soc": 0
}
```

该层直接支持片段分类、编码仲裁和逐字段模型验证。示例中的`at_eval_subtype`仅展示字段位置，不预判其最终单选/多选存储契约；正式记录必须等待编码表T0冻结。

### 6.2 帖子级聚合与标签证据（`DEFERRED`）

以下结构仅示意未来可能由片段结果规则派生的帖子级输出，不是人工金标或模型训练目标：

```json
{
  "post_id": "P001",
  "cs_density": {"inf": 0.5, "edu": 0.1, "emo": 0.2, "int": 0.0},
  "at_density": {"info": 0.4, "eval": 0.3, "sug": 0.1},
  "cs_presence": {"inf": 1, "edu": 1, "emo": 1, "int": 0},
  "at_presence": {"info": 1, "eval": 1, "sug": 1}
}
```

若编码表未来启用帖子级聚合，每个帖子级正值都应能够回指一个或多个`seg_id`。片段证据当前用于：

- 支撑人工编码仲裁；
- 解释帖子为什么获得某标签；
- 支撑锁定评估与错误分析；
- 为未来长文本或token/span辅助实验保留接口；这些实验均为`DEFERRED`。

当前文本BERT不包含任何帖子级存在性头。V0/V6/V7等帖子级字段来自元数据或其自身上游规则，也不得与V1/V2/V3/V5的片段级原子标签混成同一个监督任务。

## 七、长文本分块与标签聚合（`DEFERRED`）

> 当前输入已经由确定性程序切成固定片段，不启动长文本层级模型；本节仅保留未来对照方案。

数据库中的帖子长度差异较大，完整帖子可能超过普通 BERT 的上下文长度。此时不能简单截断前 512 个 token，否则后文出现的标签会系统性漏检。

若未来研究问题确需直接处理完整帖子，可评估层级式文本编码：

```text
完整帖子
  ├── chunk 1 → BERT → chunk 表示
  ├── chunk 2 → BERT → chunk 表示
  ├── chunk 3 → BERT → chunk 表示
  └── ……
             │
             ▼
      帖子级标签聚合
```

聚合仍应按标签独立进行，因为“大海”可能只出现在第一段，“高楼”可能只出现在最后一段。

可以比较三种方案：

1. **标签级 max pooling**：某个分块强烈命中即可激活帖子标签；
2. **Noisy-OR**：多个分块的弱证据共同提高帖子级概率；
3. **标签级 attention pooling**：由模型学习每个标签应关注哪些分块。

上述三种方式均不在当前任务范围。即使未来评估，也不得增加帖子级存在性监督头；帖子级值仍须由片段预测按届时生效的编码表规则派生。

## 八、层级标签与标签关联

> **状态：`DEFERRED`**。当前最小基线不学习层级约束、标签图、classifier chain或标签间Transformer。

### 8.1 层级标签

未来若编码表允许学习某个父子层级，可评估同时输出父标签和子标签。例如：

```text
父类
├── 子类 A
└── 子类 B
```

应满足：

\[
p(\text{子类}) \le p(\text{父类})
\]

实现方式可以是：

- 在金标中由子标签自动补齐父标签；
- 在训练损失中加入层级一致性惩罚；
- 在推理后处理中修正违反层级的结果。

父子层级不改变多标签性质。并列标签仍可同时成立。但当前`rs_n/rs_r`等父项由Layer 2原子标签规则派生，不得另设父类输出头；本节公式不适用于当前基线。

### 8.2 标签共现

第一版模型不建议预先硬编码标签共现关系。共享 BERT 和联合训练已经能够学习部分关联，过早加入规则容易把现有样本中的平台偏差或城市偏差固化为“理论关系”。

若未来重新启用标签关联实验，顺序为：

1. 先训练独立 Sigmoid 基线；
2. 观察稳定的标签共现和错误模式；
3. 只有在跨平台、跨时间仍稳定时，再尝试标签图、classifier chain 或标签间 Transformer。

### 8.3 组合空间不等于组合类别

`K` 个二元标签在逻辑上最多产生 `2^K` 个标签集，但独立 Sigmoid/Binary Relevance 将其分解为 `K` 个二元任务，并不训练一个 `2^K` 类 Softmax。因此：

- 不要求训练集覆盖全部逻辑组合；
- 每个标签仍必须有足够的正例与负例；
- 若要把某个组合当成分析组、学习标签依赖或估计高阶交互，则目标组合必须有足够样本；
- 未观察到的组合不能自动解释为“理论上不可能”，也不能在没有证据时用合成样本补齐。

在模型训练前，必须依据编码表的分层人工证据方案，使用盲试标、锁定双标评估集与训练池复核记录，报告每个标签的阳性数、流行率、平均标签数、观察到的标签集及频数。样本不足时应回到编码表裁决研究范围，不能由本文件自行合并或删除标签，也不能直接增加模型复杂度。

## 九、损失函数设计

第 `d` 个多标签头使用逐标签二元交叉熵：

\[
L_d = \frac{1}{K_d}\sum_{k=1}^{K_d}
m_{d,k}\operatorname{BCE}(y_{d,k},p_{d,k})
\]

其中 `m_(d,k)` 是有效性掩码：

- 已确定为存在或不存在：`m=1`；
- 无法判断、证据不足或不适用：`m=0`，不进入该标签损失。

总损失为：

\[
L = \sum_d \lambda_d L_d
\]

`λ_d` 用于平衡不同研究维度。维度内标签不平衡时，可以使用：

- 正类别权重；
- Focal Loss；
- Asymmetric Loss；
- 分层采样。

不建议仅按标签频率机械设置极端权重，应同时观察召回率、概率校准和误报成本。

V1/V2/V3/V5的总损失可写为：

\[
L = \lambda_{V1}L_{V1} +
\lambda_{V2}L_{V2} +
\lambda_{V3}L_{V3} +
\lambda_{V5}L_{V5} +
\lambda_{sent}L_{sent} +
\lambda_{subtype}L_{subtype} +
\lambda_{aspect}L_{aspect}
\]

`L_sent`和`L_aspect`只在片段含`AT-EVL`或`AT-SUG`且相应人工字段有效时生效；`L_subtype`只在`AT-EVL=1`时生效，其Softmax/BCE形式等待编码表T0裁决。派生字段在规则层计算，不加入重复的一致性损失。上述有效性掩码仍须服从尚未冻结的`1/0/UNK/NA`记录契约。

## 十、阈值和输出数量

对多标签原子项，模型不应预设“一个输入必须输出几个标签”，也不应统一采用Top-k。

不同固定片段可能：

- 没有某一维度的有效标签；
- 只有一个标签；
- 同时包含多个标签。

每个标签应在验证集上单独确定决策阈值：

```text
标签 A：threshold = 0.42
标签 B：threshold = 0.58
标签 C：threshold = 0.35
```

统一使用 `0.5` 可以作为基线，但不应直接作为最终规则。稀有标签、边界模糊标签和高频标签的最佳阈值通常不同。

如果论文分析需要概率而非硬标签，应保存：

- 原始 logit；
- Sigmoid 概率；
- 使用的标签阈值；
- 最终二值结果；
- 模型版本。

这能保证后续敏感性分析和结果复现。

## 十一、继续预训练（`DEFERRED`）与监督微调

编码表不直接参与标准BERT预训练。当前只要求建立可复现的监督微调最小基线；旅游领域继续预训练是候选增量实验，不是前置条件。

### 阶段 A：旅游领域继续预训练（`DEFERRED`）

- 使用未标注旅游 UGC；
- 主要任务为 Masked Language Modeling；
- 目标是学习旅游语汇、平台表达和上下文模式；
- 此阶段没有“旅游主题头”等人工标签输出。

### 阶段 B：多任务、混合输出监督微调

- 加载预注册的基础BERT编码器；只有未来继续预训练实验通过对照验证后，才可替换该编码器；
- 按输出性质添加V1、V2、V3-L1、V3-L2、V3-L3和V5技术头；`at_eval_subtype`头等待T0冻结后启用；当前文本标签没有独立连续金标，故不设回归头；
- V1/V2/V3/V5只使用固定片段级字段训练，派生字段由规则层生成；
- 不设置帖子级存在性任务，证据跨度辅助损失也标为`DEFERRED`。

因此，准确说法应是：

> 编码表定义监督微调与论文变量；继续预训练若未来启用，只能作为与基础编码器对照的`DEFERRED`实验。

## 十二、当前基线与候选模型顺序

### Model 0：可解释的最小基线

```text
BERT
  → [CLS]
  ├── V1/V2/V3-L1/V3-L3/V5：Linear → Sigmoid
  ├── V3-L2条件情感方向：Linear → Softmax
  └── AT-EVL亚类：条件头（输出形式待T0冻结）
```

用途：验证标签体系是否可学，建立后续模型比较基线。

### Model 1：标签级注意力（`DEFERRED`）

```text
BERT token 表示
  → 每个标签独立查询文本证据
  → Sigmoid
```

用途：解决同一帖子中不同标签由不同片段触发的问题。

### Model 2：长文本层级模型（`DEFERRED`）

```text
帖子分块
  → chunk BERT
  → 标签级 chunk attention
  → 片段预测的规则聚合（不得另设帖子存在性监督头）
```

用途：解决超过 BERT 上下文长度的帖子和跨段证据。

### Model 3：结构化标签模型（`DEFERRED`）

在前述模型稳定后，增加：

- 父子层级约束；
- 标签关系图；
- 标签描述向量；
- 证据抽取辅助头。

当前不得跳过Model 0启动任何复杂架构。只有最小基线通过人工信度、锁定评估与学习曲线质量门，且编码表显式解除`DEFERRED`后，才可比较Model 1—3。

## 十三、模型评估应与编码结构一致

不能只报告一个整体 Accuracy。建议至少报告：

### 每个维度

- 原子多标签（含V3-L3条件属性指向）：逐标签Precision/Recall/F1和PR-AUC，以及Micro/Macro-F1；
- 条件情感方向：Macro-F1、各类别Precision/Recall/F1和混淆矩阵；
- `at_eval_subtype`：待T0确定单选/多选责任后，分别采用多类或逐标签指标；冻结前不得虚设总体Accuracy；
- 标签覆盖率、平均预测标签数和实际组合频数。

### 每个标签

- Precision；
- Recall；
- F1；
- 决策阈值；
- 阳性样本量；
- 概率校准情况。

### 结构化检查

- 父子标签一致率；
- 不同平台和创作者层级的性能；
- 长文本与短文本的性能；
- 人工编码者之间的逐标签一致性；
- 模型与仲裁金标之间的逐标签一致性。

人工编码信度依编码表的分层人工证据方案取得，并按每个原子二值标签分别计算Krippendorff's alpha；两位编码员时可附报Cohen's kappa作为敏感性结果。不能只把一个维度下所有标签合并后报告平均值，否则稀有标签的低信度会被高频标签掩盖。

## 十四、当前对齐决策（`NOT_FROZEN`）

下表记录与编码表v3.4.2一致的当前边界。它不是独立冻结源；编码表T0关闭或版本变化后，本文件必须再次对齐。

| 问题 | 决策 |
|---|---|
| 主要分析与汇总单位 | 一篇完整帖子 |
| V1/V2/V3/V5金标单位 | 预先固定、可独立判断功能的语义片段 |
| 一个理论维度有几个技术头 | 由输出结构决定；派生字段不设输出头 |
| 原子标签如何表示 | 可同时成立的标签使用独立Sigmoid |
| 条件情感方向如何表示 | 片段含评价/建议时使用Softmax |
| `at_eval_subtype`如何表示 | 保留6维条件头；单选/多选与损失形式待编码表T0冻结 |
| V3-L3如何表示 | 片段含评价/建议时，6个属性指向使用条件Sigmoid |
| 是否允许多标签 | 允许；只标明确表达，并保留证据位置 |
| “大海、高楼”如何表示 | 同一向量中的两个位置同时为 1 |
| 是否建立“大海+高楼”组合类 | 不建立 |
| 是否要求覆盖全部 `2^K` 组合 | 不要求；但每个标签及计划分析的组合必须有足够样本 |
| 帖子级存在性任务 | 不设置；若未来启用聚合，只能从片段结果规则派生 |
| 当前文本表示 | 固定片段的`[CLS]`最小基线；标签级注意力为`DEFERRED` |
| 长文本 | 确定性切分后做片段预测；层级模型为`DEFERRED` |
| 标签层级 | 当前父项按编码表规则派生；显式层级约束为`DEFERRED` |
| 标签共现 | 先试编码并训练独立基线；显式标签依赖模型为`DEFERRED` |
| 继续预训练 | `DEFERRED`；编码表仅定义监督微调与论文变量 |
| 作者层级、粉丝量 | 外部变量，不由正文 BERT 预测 |
| 轨道关系 | 文本是主轨；视觉仅为辅助轨，另设视觉模型且不阻塞文本主研究 |

最终推荐框架可概括为：

> **以帖子为论文比较单位，以确定性程序预先固定的语义片段为文本金标、训练与证据单位；共享BERT基线覆盖V1、V2、V3-L1/L2/L3和V5，并为`at_eval_subtype`保留待T0裁决的条件头；不设置帖子存在性任务，派生字段只由规则层生成，继续预训练与复杂架构保持`DEFERRED`。**
