1. 目标、边界与总流程

要解决的问题

识别被关键词召回、但正文主题并非旅游的帖子；排除头像、页面背景、站点图标、默认图等不属于 UGC 内容的图片；记录重复、缺失和异常，但不把它们混成一个“脏数据”标签。

不解决的问题

不在清洗阶段进行论文正式编码，不判定图片主题类别，不识别情感或目的地形象，不评价内容真假，也不因画质、广告、水印或文本较短而自动删除。

六条不可改变的原则

  • 检索关键词只负责召回，不是“旅游相关”的真值。
  • 城市研究范围由上游采集与数据集定稿工作决定；清洗不得把非青岛记录写成“非旅游”“无效”或任何清洗状态。
  • 文本可用性、旅游相关性、重复、商业推广和内容形态分别记录。
  • 规则或模型产生的是候选；除明确的结构角色外，主题性排除必须有人工作出最终确认。
  • 文本模型和图片指纹均在本地离线运行；不发送原始 UGC 到外部 API。
  • 任何清洗都生成新的 run_id 与分析视图，不回写或删除采集证据库。

2.1 已发现的问题与尚不能下的结论

  • 已确认的输入边界：青岛范围由上游负责；当前 schema 以迁移 13 声明范围已定稿。清洗只接受或拒绝整次输入，不执行城市筛选。
  • 已确认的平台结构差异：标题等字段不是所有平台的必填结构；统一使用“标题为空即无效”的规则会造成系统性误删。
  • 已确认的图片角色混入：图片关系包含头像和页面证据，不能将 web_post_images 全表直接当作 UGC 内容图片；应按角色分流并保留来源关系。
  • 重复规模尚待冻结：文本相同和图片 URL 复用证明需要重复关系表，但其数量必须由正式快照重算，也不能证明内容应删除。
  • 探索性内容观察：此前由 LLM 对少量标题、正文和图片关系进行的非正式浏览，发现部分记录虽由旅游关键词召回，主旨可能并非旅游，问题在 B站和小红书样本中更显眼；也存在头像、页面资产或通用技术图片混入图片关系的风险。该浏览仅用于发现问题和设计抽样，不产生正式标签。
  • 仍待正式验证：“非旅游内容约占 8%–10%”只是先前浏览印象，图片 URL 复用中有多少是真正技术噪声也未知。两者都必须由青岛抽样框中的概率样本、双人标注和置信区间确认，不能写作当前数据事实。
报告口径：论文的数据来源部分交代青岛研究范围和最终冻结输入量；清洗方法段只报告“青岛正式输入数 → 结构无效/非旅游/重复视图处理数 → 最终分析数”。不报告城市筛选或范围外清洗数，定向高风险样本也不得进入污染率分母。

3. 清洗标签与可操作编码手册

3.1 帖子级清洗判断轴

旅游相关性related / unrelated / uncertain；结构无效时不适用只对结构可用文本判断。主旨涉及目的地、景点、行程、旅行交通/住宿/餐饮、游客体验、旅行决策或目的地传播时为相关；仅偶然出现城市/景点词而主旨属于其他领域时为不相关。

3.2 旅游相关性的判定顺序

  1. 先阅读标题与正文整体主旨，不以单个城市名、景点名或检索关键词作结论。
  2. 如果去掉地名后，文本仍主要在讲出行、游览、游客消费或目的地体验，判为 related。
  3. 如果地名只是人物籍贯、赛事地点、新闻发生地、商品名、影视/音乐梗或日常社交背景，判为 unrelated。
  4. 本地餐饮、节庆与生活方式只有在出现游客、路线、攻略、目的地体验或旅行决策语境时判为相关。
  5. 内容过短、语义依赖图片或同时具有两种主旨且无法确定主导主题时，标为 uncertain 并仲裁，不强行二分。

4. 非旅游文本的正式清洗路线

本节默认输入已经由数据集定稿工作限定为青岛，不包含任何城市筛选步骤；“相关/不相关”只判断青岛帖子主旨是否属于旅游。

4.1 确定性规范化

  • 使用 Unicode NFKC；去除零宽及不可见格式字符；合并段内连续空白；保留段落换行与标点。
  • 用独立行构造 [TITLE] 标题和 [BODY] 正文作为分类输入；任何平台无标题但正文有效都不判无效。
  • 保存原文、规范化文本及其 SHA-256；模型只读取规范化副本，不覆盖 web_posts。
  • URL、@用户、话题和表情符号采用固定替换规则；规则版本写入配置，不能每次临时修改。

4.2 重复检测

精确重复

另建不影响分类输入的重复键：标题与正文分别经 NFKC、大小写折叠并移除全部空白，保留两字段边界后计算 SHA-256；URL、@用户、话题和表情不先替换为公共占位符，避免不同实体被误合并。只有结构可用记录形成精确键，相同哈希自动进入同一簇。只传播“重复关系”，不传播旅游相关标签，也不物理删除。

近重复

每次从显式快照中状态成功且输出哈希一致的当前规范化结果建立不可变语料构建；精确簇只取稳定代表项进入字符 3–5 gram TF-IDF，先按长度比和稀有共享 n-gram 确定性阻塞，再计算余弦相似度。当前 0.80 仅为版本化候选召回线，最终阈值保持未定，须由已标注文本对校准；候选仍需人工确认。

精确重复保存 cluster_id、代表项和全部成员；近似结果保存候选对、相似度证据和候选连通分量。每个构建同时冻结规则、CPython、Unicode、regex、NumPy、SciPy、scikit-learn 和语料 manifest 身份，完成后封存全部子表。候选对先形成追加式原始复核，再由第三人引用原始复核 ID 仲裁；候选边的传递闭包只服务人工工作流，不得称为已确认近重复簇。人工确认的近重复关系可保守用于训练泄漏隔离，但泄漏分量仍不等于分析去重真值；传播/转载研究使用全量视图，主题频数分析须另行确认去重簇和代表项，并与全量结果做敏感性对照。

4.3 线性模型的职责

人工标注形成金标后，训练唯一的正式离线文本模型：字符 n-gram TF-IDF＋线性 SVM。模型不充当主题真值，而是将未标记录分为“优先复核为不相关”“边界复核”“低风险保留候选”三段。所有最终标为 unrelated 的模型候选均由人工确认；低风险保留候选再做分层抽样审计。

5. 图片技术噪声的正式清洗路线

本节默认处理的是正式青岛输入中的帖子关联图片，不负责按城市选择或处置图片关系。

当前验收边界：截至派生 schema v18，工程除 Issue #9 的冻结运行/快照、manifest、固定 8/4 pHash 和候选构建外，已实现 Issue #10 的候选代表复核、30 张 pilot/50 张边界计划、动态第二槽、追加式标签与仲裁、决定快照、SHA 精确簇传播，以及主样本＋平台补充的两层保留集审计。测试图片均由程序生成，不是采集所得 UGC；完整命令链在封锁 socket 的子进程中运行，并验证原图 SHA 不变和回执不泄露路径。正式图片目前仍只有上游 URL、尚未按受控 manifest 落盘，所以尚未执行真实解码、候选分布、人工抽样、噪声率或效果评估。d≤10 仍只用于高召回候选和 complete-linkage 展示，数据库与 API 均不允许沿 pHash 传播标签；当前方案不要求固定 300 对校准。当前高频复用 signal 只按文件 SHA 统计帖子数与已知作者数，URL/pHash 复用次数和跨平台统计仍待真实输入后另行版本化。

5.1 Issue #9 已实现的技术框架

环节真实输入或动作当前产物

文件校验路径、声明 SHA、实际文件、解码和去敏元数据成功指纹或彼此分离的阻塞理由；原图、源库和历史 attempt 均不修改。
候选SHA 精确簇、d≤10 的 pHash 对及 URL/尺寸/透明/高频复用信号只形成封存候选构建，不产生技术噪声标签和排除决定。

Issue #9 不需要研究者逐张判断图片。研究者当前只需控制正式图片文件的落盘与访问边界；manifest 可由工程流程根据下载结果生成和校验，不应要求研究者手工计算 SHA 或重新标注来源角色。真实图片未落盘时，图片任务保持 blocked，文本路径继续运行。

5.2 第一层：现有角色直接分流

  • image_role=author_avatar：从内容图片视图排除，但保留关系记录。
  • image_role=page：标为 evidence_only，仅用于采集审计。
  • image_role=content：进入后续指纹与噪声识别；不能因角色名直接假定全部有效。

角色、所属帖子和作者身份均以本次运行绑定的冻结快照为准。即使图片文件在后续批次才下载并导入 manifest，当前 inventory 中已经变化的帖子关系、角色或作者也不能反向改变旧快照语义；当前 inventory 只保证派生外键目标仍有登记。

5.3 第二层：离线文件指纹

在合法保存且受访问控制的本地图片快照上运行；不在清洗时重新访问平台。每张图片固定记录：

  • manifest 行身份、去敏 URL 技术资产词布尔信号、文件字节 SHA-256、文件字节数、解码状态、宽高、长宽比、MIME、alpha 通道信息和不含 GPS/设备序列号的 EXIF 技术字段；不在派生库保存 URL 或本地绝对路径。
  • 64 位 DCT 感知哈希：固定实现为 imagehash.phash(hash_size=8, highfreq_factor=4)，依赖锁定为 Pillow==12.3.0、ImageHash==4.3.2，并在计算前执行 ImageOps.exif_transpose。
  • 当前实现按文件 SHA-256 统计跨帖子与跨已知作者复用；同一 URL、pHash 近同组的复用次数，以及跨平台出现次数属于后续统计字段，未在现有框架中生成。

冻结快照缺失或不可读统一记录为不含机器路径的 snapshot_unreadable 并终止本次操作。manifest 权威关系核对与候选构建都通过同一只读重开边界查询冻结快照；即使文件在摘要核验后消失、权限改变，或 SQLite 打开、查询、迭代失败，也不得回退到当前库存或暴露底层路径。没有 manifest、图片文件缺失、manifest SHA 与实际字节冲突、解码失败分别记录为 blocked_by_manifest、image_file_missing、image_sha256_mismatch、image_decode_failed。这些是前置材料/技术阻塞，不是模型失败。不得伪造感知哈希，也不得据此自动排除。下载完成或文件修复后必须显式恢复对应任务，历史 attempt 保留。

5.4 第三层：高召回候选规则

信号发现的候选允许的动作
URL 路径含 avatar、head、profile、logo、icon、sprite、bg、background、default、placeholder、error、loading、qr头像、站点资产或占位图只进入复核队列；词表命中不能单独排除。
宽或高小于 64 px、文件小于 2 KiB、长宽比大于等于 8，或图像完全透明图标、分隔条、追踪像素只作为初始候选信号；阈值写入配置并由标注样本校准。
同一 URL 或 SHA-256 出现在至少 10 个帖子且横跨至少 3 个作者站点背景、默认图、统一推广素材这是正式方案的候选规则；当前代码只实现 SHA-256 高频复用，URL 高频复用待实现。审阅簇代表项；确认后只可向字节完全相同成员传播标签。
64 位 pHash 汉明距离较小压缩、缩放或轻微裁剪后的近同图框架当前只在 d≤10 内生成候选；本版本只用它组织人工复核，不传播标签，也不据此排除。
同帖重复采集重复或页面复用保留关系，标记 within_post_duplicate；不影响其他帖中的独立使用。

5.5 最小人工确认与有限传播

  1. 头像和页面图完全依据冻结来源角色自动分流；缺失、哈希冲突和解码失败依据文件事实自动阻塞。这两类工作都不进入人工标注量。
  2. 人工只审阅 content 中由技术信号命中的候选代表和难以判断的边界图片。任何拟进入 exclude 的候选代表必须由两名研究者独立同意；分歧交第三人仲裁，uncertain 默认保留。
  3. SHA-256 完全相同意味着文件字节一致。代表项的 technical_noise_label 经双人确认后，可以传播到同一精确簇；来源角色、帖子语境、视觉相关性、内容格式和属性旗标均不得传播。
  4. pHash 对和 complete-linkage 分组只用于减少翻看顺序与展示代表/最远成员；当前版本禁止沿 pHash 自动传播任何排除标签，因此不强制 300 对距离校准。
  5. 若未来确有规模压力而要启用 pHash 自动传播，必须另立版本，以独立验证集和 precision 的单侧置信下限论证阈值；不能把当前 d≤10 候选上限直接升级为传播阈值。

5.6 自动处理与人工工作的边界

对象当前动作是否需要人工
头像、页面背景/UI 关系按冻结快照角色分流并保留理由不需要；若怀疑采集角色错误，应退回上游做采集质量审计，不计入 Issue #10 人工量。
缺失、损坏、SHA 冲突、完全相同文件硬规则记录阻塞或精确簇不需要判断技术事实；精确簇代表若拟排除才需要人工确认标签。
极小图、透明图、异常长宽比、URL 技术词、高频复用只生成候选只有候选代表需要判断，信号本身不能排除。
pHash 近似对排序和分组供复核不做固定规模校准，不自动传播；仅在具体候选需要排除时复核。
路线图、推荐计划图、攻略卡、菜单、票据和信息图作为 content 保留不因非实景、文字多、水印、推广或二维码特征而要求排除。

6. 分层抽样、人工标注与仲裁

6.1 文本样本

文本抽样框由后续冻结的正式青岛输入生成。首轮计划包含 500 条概率样本和 200 条定向样本；两个抽样框允许重叠，所以唯一帖子数可能少于 700。概率样本用于估计正式输入的相关性构成；定向样本按确定性困难信号增加短文本和近重复边界覆盖，不以增加不相关标签为预设目标，也不读取模型预测。两类样本使用完全相同的标签手册、盲标和仲裁程序，但用途和权重分开。

样本抽取方式用途
500 条概率样本以正式冻结输入中结构可用帖子为抽样框，对每个平台先分配最多 80 条最低配额，再按各平台剩余容量分配其余名额；平台内以固定种子无放回随机抽取。保存平台内纳入概率与逆概率权重，最终平台数和规模由快照动态确定。估计正式青岛输入的相关/不相关/不确定比例；报告时使用抽样权重。
200 条定向样本当前实现按跨平台近重复、一般近重复、规范化后不超过 80 字的短文本和确定性补足依次选取；不读取人工标签或模型预测。覆盖重复边界与短文本困难案例；不得用于估计总体污染比例。

标注导出不显示记录属于概率框还是定向框，标注者不得因抽样来源调整判断标准。概率样本可能得到 unrelated，定向样本也可能得到 related；抽样来源不是标签。总体比例只使用概率成员及其权重，定向成员只用于困难案例覆盖和仲裁后模型学习。同一帖子同时属于两个抽样框时只标一次，系统保留两种来源，训练与计数按帖子版本去重。

6.2 图片样本

图片清洗不再预设 600 张训练式样本。人工工作由两部分组成：其一，审阅所有“拟排除”的内容图候选代表；其二，在决定应用后的全部 content 保留关系/图片中做两层质量审计。第一层 primary 从全部保留人口等概率、稳定、无放回抽取至多 200 张；人口小于 200 时全查。总体残余噪声点估计和单侧 95% Wilson 只使用该主样本的非加权事件数。第二层 platform_supplement 在主样本冻结后，将主样本观察数不足 30 的每个平台补至 min(30,Np)；补充项保存条件纳入概率和权重，但不进入总体 Wilson。任一补充项出现技术噪声或 uncertain 同样使轮次失败。

200 张主样本零事件的单侧 95% Wilson 上限约为 1.33%，低于 2% 控制线；一事件上限约为 2.21%，不能通过。发现任何残余技术噪声或未解决项时修正规则/决定、冻结新决定版本并抽取非重叠新轮，累计最多三轮；人口已全查时不能复抽旧成员凑轮次。规则候选、SHA 代表和 pHash 边界属于定向复核，只用于发现与修正，不能混入主样本分母；当前不为 pHash 自动传播抽取固定 300 对样本。

6.3 标注流程

  1. 两名标注者先共同试标文本 30 条、图片 30 张，修订定义与边界示例，冻结编码手册 v1.0。图片 pilot 的两人各完成 30 个判断；这些校准证据不直接生成正式排除决定。
  2. 正式文本样本仍有 200 条双标。图片另从候选与保留边界中冻结 50 张独立双标，并对所有拟排除或 uncertain 的候选代表追加第二人盲标。候选复核、边界验证和 pilot 是不同 review_run 的独立判断；即使图片身份重叠，也不得跨运行拼接两个槽位或把校准标签冒充正式证据。标注者看得到帖子上下文，但看不到候选分数和另一人的标签。同一对象在同一运行、同一槽位只能有一条原始记录。
  3. 只有计划中的全部 slot 1/2 均完成后才分别报告原始一致率与 Cohen's κ。图片双标集经过边界富集，κ 只反映手册可重复性，不能用来估计总体噪声率；当阳性极少时还必须同时报告原始一致率和分标签分歧。现有 v2.4 文本一致性程序仍有商业字段与结构无效处理阻塞，正式文本标注前必须修正；该差异不得扩展到新的图片接口。
  4. 分歧由不同于两名原标注者的第三人按冻结手册仲裁，并同时引用同一对象、同一手册版本的 slot 1/2 两条证据。文本适用判断轴的通过线仍为 κ≥0.70 且原始一致率≥0.80；未达到时从未双标对象中追加最多 100 条。图片边界集以原始一致率≥0.80和“全部拟排除代表已双人同意或仲裁”为硬门；κ 在至少出现两个标签时报告并以 0.70 为警戒线，若因单类别而不可估，不得仅为得到 κ 人为扩样。图片原始一致率未达标时修订手册并追加最多 50 张边界双标。所有补充轮次都先冻结预期成员 manifest，再核对实际 manifest 后单向封存；原始记录、轮次与仲裁记录都只追加。
  5. 正式青岛数据在基线快照后每累计首次出现 2,000 个新的 source_post_id，冻结一个不重叠的 true-new 窗口，再从窗口内当前结构可用对象中概率抽取最多 100 条；窗口同样在成员数、当前可用数和 manifest 核对后单向封存。旧帖删失、失效或新 source version 不得抵消或重复新增计数。内容图每累计新增约 20,000 张，从 true-new 内容图中抽取 100 张漂移审计，并复核所有新的拟排除候选代表；新增关键词、平台或抓取结构改变时立即触发同样审计。若输入出现非青岛记录，应退回数据集定稿环节，而不是在清洗中标注或过滤。

文本 700 条仍是当前项目规划；图片改为“候选代表＋至多 200 张等概率主样本＋平台缺口补充”的自适应工作量，不再把 600 张图片、固定 200 张审计总量或 300 对 pHash 写成启动 Issue #10 的固定门槛。图片判断任务由 30 张 pilot 双人判断、候选代表首标、拟排除/不确定代表第二槽、50 张边界双标、必要仲裁和审计组成，实际数量由候选簇数、首标结果及平台构成决定。

7. 离线文本模型、训练和无泄漏评估

7.1 唯一正式配置

  • 输入总体：使用正式冻结的青岛标注记录；输入文本为规范化的 title + content_text，不把平台、城市和检索关键词作为语义特征，避免模型记住采集设计。
  • 特征：TfidfVectorizer(analyzer="char", ngram_range=(2,5), min_df=2, sublinear_tf=True, max_df=0.995)。
  • 分类器：L2 正则 LinearSVC(class_weight="balanced")；仅在 C∈{0.1,1,10} 中选择。
  • 模型、向量器、标准化规则、依赖锁文件和随机种子一并保存；禁止在线词典、在线嵌入和 LLM 特征。

7.2 防止作者、重复和时间泄漏

  1. 建立泄漏组：同一作者哈希、同一精确簇或显式人工仲裁为 duplicate 的近重复关系之间连边，取连通分量作为不可拆分的 leakage_group_id。候选 pair/候选连通分量不得直接参与；作者缺失时使用帖子自身 ID，禁止把所有空作者哈希成同一组。
  2. 该分量只服务训练泄漏隔离，不是分析去重簇或代表项真值。即便一个人工确认近重复 relation 用于隔离，与其传递相连的整组帖子也不能因此自动在分析中删除。
  3. 每个平台先按 published_at、缺失时按冻结的采集时间，冻结较晚的 20% 且至少 20 条帖子身份作为测试候选，再将候选所在泄漏组整体扩展到测试集。其他平台随分量带入的旧成员不能替代本平台的最新候选。
  4. 剩余数据按泄漏组形成训练与验证集；只在训练集拟合 TF-IDF，不能先在全体文本上建立词表。固定 random_seed=20260728。
  5. C∈{0.1,1,10} 只在验证集按不相关类 PR-AUC 选择，并列时选择较小的 C；测试集在 C 与阈值冻结前不可读取指标。
  6. 若某平台测试集中不相关样本少于 30 条，该平台只报告描述性结果并显式抑制稳定泛化结论；数据扩展后冻结新的时间测试集。

7.3 阈值分流

区间动作最终责任
不相关高分段进入优先人工复核；验证集上选择同时达到不相关 precision≥0.90、recall≥0.50 的最低 margin。只有人工确认并保存理由与证据后才能 exclude。
中间不确定段全部人工复核并可回流训练集；每次回流生成新模型版本。人工标签优先于模型。
相关低风险段验证集上选择同时达到相关 precision≥0.95、recall≥0.80 的最高 margin；按平台抽取 min(Np, max(ceil(0.05×Np), 50)) 条审计。验证目标无解时关闭低风险自动保留，全部转人工；审计超线时扩大复核区间并重训。

模型评估至少报告不相关类的 precision、recall、PR-AUC、混淆矩阵及平台/时间切片。margin 正方向统一表示更可能 unrelated。模型只产生三种候选动作，不写人工标签或最终判断；商业属性 promotion 也不单独触发排除。所有最终 unrelated 排除项必须追溯到人工仲裁。

8. 科研可复现性

科研可复现性的对象不是“得到一份看起来干净的 CSV”，而是让另一名研究者在同一输入快照上恢复相同的抽样、标签合并、模型切分和最终纳入清单。

增量处理不改变科研总体：工程上可以按新抓取批次持续登记并完成文本、图片等阶段，但“已清洗”只对指定源版本和方案版本有效。批次大小是断点恢复单位，不是统计抽样单位；论文分析只能使用最终冻结快照上已验收的 run_id，并重新汇总全部分布与质量指标。
训练运行身份：正式训练必须显式提交仲裁金标 ID 清单、人工确认近重复 ID 清单和 formal 执行确认；核心接口在打开 SQLite 前核验确认，不存在默认读取“全库全部标签”的入口。小样本连通测试必须写成 smoke；金标清单先校验唯一性，候选帖子清单在开库前排序、去重并校验正整数身份，两者去重后的规模分别固定为最多 100 条，调用方不能扩大上限。规范化请求哈希与实际预测候选哈希同时写入派生库、指标和模型 artifact；候选清单变化必须形成新运行，完全相同且已封存的请求则在读取金标、切分或拟合前直接复用。smoke_only 必须写入报告和模型 manifest，不能当作正式效果。
复现对象必须保存的证据
输入总体源库与图片 manifest 哈希、只含青岛的输入契约检查结果，以及正式输入的平台/关键词/时间分布和帖子/图片数量。检查失败时不产生清洗结果。
规则文本规范化、图片候选规则、标签手册和理由代码的版本。
抽样抽样框、分层变量、抽中 ID、抽样概率、随机种子；概率样本与定向样本分开；周期复核另存 true-new 窗口上下界、全部成员、当前可用数和 manifest。
人工判断两名标注者的原始标签、盲标状态、分歧、仲裁与一致性统计。
模型规范化训练请求、实际预测候选、显式仲裁金标、训练/验证/测试各自及总清单哈希、冻结时序候选清单、泄漏组、特征和超参数、阈值、候选动作、formal/smoke 身份及分平台指标。单类别切片的 PR-AUC 或 precision/recall 零分母必须保存明确的空值理由。
最终样本保存每条清洗排除理由、最终帖子/图片 ID，以及去重与未去重视图的样本量。

源数据、原始图片和作者直接标识不进入公开仓库；可复现性通过代码、配置、去标识化标签、ID 清单和哈希实现。具体 SQLite 表、目录、命令、测试与回滚方式由工程方案规定。

9. 质检、漂移与停止条件

9.1 每次运行必须报告

  • 源快照、输入契约检查、规则、手册、代码和依赖版本，以及正式青岛输入中各平台帖子和图片的输入/输出数量。
  • 帖子按 reason_code 的保留、复核、排除数量；图片按主标签和角色的数量。
  • 文本与图片精确重复簇数、成员数和跨平台簇；近重复在人工确认前分别报告候选对、候选连通分量和跨平台候选对，不与确认簇混报。
  • 文本双标一致率、κ、仲裁数；图片边界双标的一致率、κ、拟排除代表数、仲裁数和精确 SHA 传播成员数；文本模型总体及分平台 PR 指标。
  • 最终保留集抽样审计的污染率和 95% Wilson 区间；不能只报一个总体准确率。

9.2 误删保护与停止线

  1. 文本模型建议排除项 100% 人工确认；图片所有拟排除候选代表均须双人同意或第三人仲裁，pHash 近同关系在当前版本不得传播排除标签。
  2. 文本适用双标轴的 κ≥0.70且原始一致率≥0.80。图片边界双标原始一致率须≥0.80，全部拟排除代表须双人同意或仲裁；图片 κ 可估时报告并以 0.70 为警戒线，单类别不可估不单独触发扩样。任一硬门未达到时停止新增排除并继续修订手册和双标。
  3. 最终文本保留集按平台分层抽查至少 300 条；若非旅游内容点估计超过 3%，或 95% Wilson 上限超过 5%，追加复核并调整阈值。
  4. 最终图片保留集每轮先抽至多 200 张等概率 primary 主样本，再以 platform_supplement 补足小平台观察量。验收要求主样本总体技术噪声点估计和单侧 95% Wilson 上限均不超过 2%，且两个层次都没有技术噪声或 uncertain；补充层不进入总体区间但可单独触发失败。
  5. 任何平台的模型“不相关候选”精确率低于 0.90时，关闭该平台的模型分流，全部转人工排序复核。
  6. 同一快照重跑后，行数、状态计数、簇成员清单和输出哈希一致；构建前后源库哈希不变。

9.3 漂移触发

正式青岛数据每新增约 2,000 条帖子执行文本增量抽样；每新增约 20,000 张内容图执行 100 张 true-new 图片漂移审计。新增平台/关键词、采集器版本或平台页面改版立即触发。若收到包含其他城市的输入，正式清洗不启动，并将问题退回数据集定稿环节。任一平台的非旅游率或图片技术噪声率相对上一冻结批次增加 5 个百分点，或文本长度、URL 域名、尺寸分布明显变化时，重审手册、词表、pHash 候选上限和文本 margin 阈值；pHash 仍只用于候选组织。

10. 科研实施与人工量

工作首次正式青岛输入青岛扩展至约 1 万条以内时
文本标注700 条，其中 200 条双标累计约 1,000–1,100 条；每新增约 2,000 条补 100 条
图片复核30 张共同试标（60 个判断）；候选代表各 1 次首标；拟排除/不确定代表再加第二槽；另取 50 张边界样本双标（100 个判断）；保留集每轮至多 200 张等概率主样本并追加平台缺口样本每新增约 20,000 张内容图审计 100 张 true-new 图片，并复核新的拟排除代表
仲裁只处理双标分歧和 uncertain若手册稳定，通常不会随总体规模等比例增长
保留集审计至少 300 条文本；图片审计为至多 200 张 primary 加各平台补至 min(30,Np) 的缺口，不再重复另抽 500 张平台或采集结构变化时重新抽查

图片人工时间不再预先写成固定人时，因为它取决于真实图片落盘后产生的候选代表数、首标中拟排除/不确定的比例、平台构成和仲裁率。先用 30 张共同试标记录单张耗时，再按“60 个 pilot 判断＋候选代表首标＋动态第二槽＋100 个边界判断（必要时再补最多 100 个）＋仲裁＋每轮 primary 实际数与平台缺口”生成工作量预算。文本模型训练和图片哈希计算均可在普通工作站离线完成；头像/page 分流、文件校验和指纹计算不计入人工标注时间。
