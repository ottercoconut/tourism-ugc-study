旅游 UGC 数据清洗科研方案

状态：FRAMEWORK_FROZEN / THRESHOLD_PENDING / IMPLEMENTATION_PENDING。本文件冻结研究框架；证据校验、内部 schema 和 baseline 训练代码已实现，但首次正式训练尚未执行，锁定测试集尚未开启，也未授权自动保留或自动排除。

1. 研究目标与边界

数据清洗只判断一条候选帖子是否与青岛旅游研究相关，目标是以可复核的人机流程排除无关内容，并控制最终保留语料中的残留无关风险。所有来源帖子属于同一个文本分类任务；模型只读取规范化文本。平台只用于来源谱系、数量和样本构成披露，不作为模型特征、切分层、阈值、审计配额或分类性能比较维度。

自动排除只改变派生分析语料的纳入状态，不删除源数据，不回写正式采集库。KOL/KOC、内容编码和视觉研究中的平台变量与分析设计不属于本清洗方案。

2. 人工标签权威源

已完成的 tourism-relevance-completed.csv 及同目录 round-manifest.json 是本轮 700 条人工标签的共同权威源。完成表共有 700 条非空记录，其中 related 387 条、unrelated 313 条、uncertain 0 条；其文件哈希、成员清单、源快照和样本运行身份由 manifest 封存。

这 700 条记录不重新抽样，也不把标签复制到 text_post_annotations。它们仍属于完整候选人口并保留在派生库中。训练程序未来必须从冻结 CSV 读取标签，同时根据 manifest 到数据库校验帖子身份、版本、样本成员关系和规范化文本一致性。全量或新增批次推理时跳过这些已有人工作答的记录，最终帖子决定直接采用人工标签：related 为保留，unrelated 为排除；若未来出现 uncertain，则保持待处理且不得直接进入分析发布。

500 条概率样本保留既有成员、纳入概率和权重，用于总体相关性比例估计及模型学习平台总体推断、平台性能比较、平台阈值

3. 首个正式模型与泄漏控制

首个正式模型采用规范化文本、字符 TF-IDF 与固定 C=1.0、class_weight=balanced 的线性 SVM，不执行隐式超参数搜索。作者关系、精确重复关系和最终确认的近重复关系共同组成泄漏分组；同一分组不得跨训练、验证和测试集合。

全体参考集统一按时间留出 20% 测试候选，再扩展到候选所连接的完整泄漏分组，因此最终测试比例可以略高于 20%。剩余记录进行全局分组分层的训练/验证切分，平台不参与名额分配。训练集内部最多使用五折分组交叉验证；若泄漏分量结构不能支持五折，可下降到仍保证每个拟合端和留出端都有双类的折数，否则失败关闭。每条训练记录只生成一次折外 SVM 分数，再用无正则一维 Sigmoid 拟合校准器，将分数转换为无关概率 p_unrelated。锁定测试集不参与特征、超参数、校准器或阈值选择。

训练运行只报告训练折外和验证集的总体 Precision、Recall、F1、PR-AUC、混淆矩阵、Brier score 与 log loss；其中 0.5 只作验证诊断分界，不是路由阈值。训练阶段将测试集标为 locked_not_opened，不生成测试概率或测试指标。阈值和验收门冻结后才开启一次锁定测试，报告总体阈值表现、自动覆盖率和时间切片。平台只披露来源数量与构成，不报告分类性能或稳定性差异。

4. 三段式路由

模型和 Sigmoid 校准器作为不可变模型 artifact 冻结。阈值策略独立保存，并满足 0 ≤ T_keep < T_exclude ≤ 1。路由定义如下：

条件动作
p_unrelated ≤ T_keep自动保留
T_keep < p_unrelated < T_exclude进入人工处理
p_unrelated ≥ T_exclude从派生分析发布中自动排除；源数据不删除

当前阈值状态：T_keep = UNSET，T_exclude = UNSET。在两个阈值、测试门和审计门全部冻结前，系统未来即使能够输出 p_unrelated，所有未有人工作答的记录也只能进入人工处理，不得自动保留或自动排除。

人工结果优先于模型建议。阈值调整只产生新的不可变策略 artifact，不重新训练或替换冻结模型。

5. 冻结模型的全量与增量推理

模型通过验收后，初始未标注人口和未来新增记录都调用同一个冻结模型。新增记录完成结构门与同版文本规范化后直接推理，不调用 fit，也不因增加一个批次而替换模型 artifact。每次推理保存模型 ID、阈值策略 ID、目标批次、规范化输入 manifest、p_unrelated、路由动作和输出 manifest。

人工灰区、未来新增人工结果和保留集审计分别使用独立的完成 CSV 与 manifest。数据库只保存最终帖子决定，以及对应 CSV 哈希、任务身份、模型 ID 和阈值策略 ID 等谱系引用；人工标签本身仍以冻结 CSV 为权威证据。

6. 可靠性证据与失败降级

部署后的常规审计对象是最终保留人口，采用全局抽样，不设置平台配额。保留集审计的事件定义、样本量、最大事件率、单侧置信上限和恢复条件目前均为 UNSET，须在代码框架完成后单独讨论并冻结。

保留集审计失败时，冻结模型仍可继续打分，但自动保留立即暂停；原本会自动保留的记录转入人工处理。自动排除和人工灰区仍按已冻结策略运行。恢复自动保留必须绑定新的阈值策略，并满足尚待冻结的恢复条件，不能修改既有运行结果。

不对自动排除人口实施常规随机审计。因此正式可靠性声明严格限定为“最终保留语料的残留无关风险受控”。避免过度删除的证据仅来自锁定测试集上的总体指标、混淆矩阵和阈值表现；这些证据不能等同于部署期对全部自动排除记录的直接审计，论文必须披露这一限制。

7. 阈值阶段与正式化条件

下列项目现在全部为 UNSET：T_keep、T_exclude、保留集审计事件定义与样本量、最大事件率、单侧置信上限、模型测试指标最低门、自动覆盖率最低门及审计失败后的恢复门。阈值选择只能使用训练部分的折外预测或独立验证证据，并遵循预先定义的效用权衡；锁定测试集只用于对已冻结模型和策略作一次最终验收，不得据其结果反复调整阈值。

当前下一步固定为：先封存泄漏分组并执行首次 baseline 训练；再依据训练折外与验证证据讨论阈值、测试门、自动覆盖率门和审计门；策略冻结后只开启一次锁定测试；随后实现无训练增量推理、人工覆盖和保留集审计。只有代码、稳定配置入口、模型 artifact、阈值策略、推理契约和测试全部通过验收后，本文件才可统一改为 CURRENT / FORMAL。正式状态前不得对候选人口执行自动决定或构建正式发布语料。

8. 可复现记录与文献边界

每个正式运行必须保存 Git SHA、源快照、完成 CSV 与 manifest 哈希、规范化规则身份、泄漏分组 manifest、测试集 manifest、模型与校准器 ID、阈值策略 ID、随机种子、预测、人工覆盖、审计和最终发布 manifest。技术 artifact 可使用内部 ID 和哈希；人类可读方法文档不再显示协议版本号。
