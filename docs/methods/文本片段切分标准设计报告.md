# 文本片段切分标准设计报告

> **对应版本**：编码表v3.4 / 编码簿v3.4
> **撰写日期**：2026年8月2日
> **目的**：为文本轨片段级编码提供可操作、可复现的切分标准，确保两位编码员产出一致的`seg_id`划分

---

## 一、问题背景

### 1.1 为什么需要片段级编码

本研究的文本轨采用**片段级编码**而非帖子级编码，核心原因有三：

1. **消除帖子长度的混杂效应**：帖子越长，命中的标签种类越多——这是长度驱动的伪共现，而非创作者的策略选择。片段级编码下，密度指标（命中数/片段数）自动对长度进行标准化。
2. **共现分析的信效度**：SRM（策略→资源关联矩阵）和SAM（资源→语言功能共现矩阵）只有在片段级才有意义。帖子级的共现几乎对所有中等长度以上的帖子都成立，信息量低。
3. **模型训练的技术优势**：短文本的标签-证据对应关系更直接，多标签分类在短文本上的表现通常优于长文本。

### 1.2 切分标准的必要性

所有文本轨聚合指标（CSP、ATP、SRM、SAM、COD等）的分母都是`segment_count`。如果切分标准不明确：

- 两位编码员切出不同数量的片段 → 信度计算的单位不同 → 信度结果不可比
- 同一编码员在不同帖子上的切分标准不一致 → 密度指标失去可比性
- 人工切分与模型切分不一致 → 训练数据存在系统性偏差

因此，切分标准必须在编码开始前冻结，并在试标阶段验证一致性。

## 二、设计原则

| 原则 | 说明 |
|------|------|
| **P1 可操作性** | 规则必须基于文本表面特征（标点、换行、连接词），不依赖编码员对语义独立性的主观判断 |
| **P2 可复现性** | 两位编码员面对同一文本，应切出相同的片段边界 |
| **P3 语义粒度合理** | 切出的片段应适合做共现分析——既不过粗（一个片段混杂多种策略），也不过细（把一个语义单元拆成碎片） |
| **P4 尊重作者标点** | 切分标准尊重原作者的标点选择，编码员不替代作者决定"哪里该断句" |
| **P5 宁合不拆** | 当切分存在争议时，倾向于合并而非拆分。切得过粗损失共现精度，切得过细损失共现信号——两害相权取其轻 |

---

## 三、核心切分规则

### 3.1 规则一：句末标点为主边界

以**句末标点**作为片段的主要切分边界。

| 标点符号 | 处理方式 | 理由 |
|----------|----------|------|
| 句号（。） | **切分** | 标志一个完整命题或言语行为的结束 |
| 感叹号（！） | **切分** | 标志一个完整的情感表达或感叹的结束 |
| 问号（？） | **切分** | 标志一个完整提问的结束 |
| 分号（；） | **切分** | 前后通常是独立的命题、评价或并列陈述 |
| 逗号（，） | **不切分** | 逗号连接的是同一语义单元内部的子句，切分会碎片化 |
| 冒号（：）后接完整句子 | **不切分** | 冒号引出的解释性从句与前文构成一个语义单元 |
| 冒号（：）后接列表 | **见规则三** | 列表项独立成片段 |
| 省略号（……） | **不切分** | 通常连接同一语义单元的省略部分 |
| 破折号（——） | **不切分** | 通常连接补充说明，与前文构成一个语义单元 |

**示例**：

```
原句："栈桥始建于1892年，傍晚海风吹过来很舒服。"
→ 1个片段（逗号不切，句号切）
→ cs_edu=1, cs_emo=1（知识+氛围共现）
```

```
原句："栈桥始建于1892年。傍晚海风吹过来很舒服。"
→ 2个片段
→ 片段1：cs_edu=1  片段2：cs_emo=1（无共现）
```

两种切分结果都是合理的，区别在于原作者是否用句号将两件事断开。

### 3.2 规则二：转折连接词为次边界

当文本**无句末标点**但包含明确的转折或并列连接词时，以连接词前为片段边界。

**触发切分的连接词**（转折/递进/并列）：

| 类型 | 连接词 |
|------|--------|
| 转折 | 但是、但、不过、可是、然而、可惜、遗憾的是 |
| 递进 | 而且、并且、还、更、甚至 |
| 并列 | 另外、还有、同时、此外、一方面…另一方面 |
| 顺承 | 然后、接着、随后、之后 |

**不触发切分的连接词**：

| 类型 | 连接词 | 理由 |
|------|--------|------|
| 因果 | 因为…所以、因此、于是 | 前后构成一个完整的因果论证 |
| 条件 | 如果…就、只要…就 | 前后构成一个完整的条件句 |
| 让步 | 虽然…但是 | "虽然"引导的从句不独立成段，与"但是"后的主句合并 |

**示例**：

```
原句："门票80有点贵但是风景真的美到窒息"
→ 切分点在"但是"
→ 片段1："门票80有点贵" → cs_inf=1, at_has_eval=1, asp_pri=1
→ 片段2："风景真的美到窒息" → cs_emo=1, at_has_eval=1, asp_res=1
```

```
原句："因为是淡季所以人很少体验很好"
→ 不切分（因果连接）
→ cs_inf=1, at_has_eval=1, asp_cro=1
```

### 3.3 规则三：列表项独立成段

攻略帖中常见的列表结构，每项独立为一个片段，即使没有句末标点。

**识别标准**：冒号或换行后，以以下任一方式分隔的独立攻略项：
- 编号（1. 2. 3. / ① ② ③ / 一、二、三、）
- 项目符号（·、-、•）
- 换行符（每个独立行）
- 箭头序列中的独立节点（Day1→A→B 中的 A 和 B 属于同一项）

**示例**：

```
原帖：
"青岛三日游攻略：
Day1：栈桥→天主教堂→信号山
Day2：崂山一日游
Day3：啤酒城→金沙滩"
```

→ 3个片段（Day1、Day2、Day3各为一个片段）

```
原帖：
"推荐几个必吃：
· 海鲜大排档（人均80）
· 青岛啤酒（原浆最正宗）
· 烤鱿鱼（台东夜市）"
```

→ 3个片段（每个推荐项独立）

### 3.4 规则四：对话/引用整体成段

直接引用、对话、转述整体作为一个片段，不在引号内部切分。

```
原句："我问老板'这个多少钱'，他说'30块随便吃'。"
→ 1个片段（整段对话）
```

### 3.5 规则五：纯表情/纯标签独立成段

独立的emoji行、话题标签行、@提及行作为单独片段。

```
原帖：
"泰山日出太震撼了！！！
🔥🔥🔥
#泰山日出 #旅行打卡"
```

→ 3个片段：
- 片段1："泰山日出太震撼了！！！" → cs_emo=1, rs_n_geo=1, rs_n_cli=1
- 片段2："🔥🔥🔥" → cs_oth=1, at_non=1
- 片段3："#泰山日出 #旅行打卡" → cs_oth=1, at_non=1

### 3.6 规则六：无标点且无连接词的长句不切分

当文本既无句末标点也无转折连接词时，**不切分**，即使内部包含多个语义成分。

```
原句："门票80有点贵风景也很美"
→ 1个片段（无标点、无连接词）
→ cs_inf=1, cs_emo=1, at_has_eval=1
```

这条规则是"宁合不拆"原则的体现。

## 四、边界案例裁决表

| # | 案例 | 正确切分 | 理由 |
|---|------|----------|------|
| 1 | "免费！不要门票！冲！" | 1个片段 | 感叹号虽然出现多次，但属于同一情感表达的重复强调，不切 |
| 2 | "免费。不要门票。冲。" | 3个片段 | 句号明确断开三个独立命题 |
| 3 | "门票80，有点贵，但值得去" | 1个片段 | 逗号不切；"但"虽是转折，但前后均在逗号内，属于同一复合句 |
| 4 | "门票80有点贵。但值得去" | 2个片段 | 句号切分+转折词 |
| 5 | "说实话，这个地方一般般" | 1个片段 | "说实话"是话语标记，不构成独立语义单元 |
| 6 | "总的来说，景色很美，服务很差" | 1个片段 | "总的来说"是话语标记；逗号不切分 |
| 7 | "景色很美。服务很差。" | 2个片段 | 句号断开两个独立评价 |
| 8 | "推荐！必去！" | 1个片段 | 同一言语行为的重复强调 |
| 9 | "推荐这家店。必去打卡。" | 2个片段 | 句号断开 |
| 10 | "去了才知道，青岛真的太美了，海风特别舒服" | 1个片段 | 逗号不切，无句末标点，无转折词 |
| 11 | "栈桥免费。始建于1892年。是最早的军事码头。" | 3个片段 | 三个句号断开三个独立命题 |
| 12 | "今天天气很好适合出去玩" | 1个片段 | 无标点无连接词，不切 |

## 五、切分操作流程

编码员在正式编码前，按以下流程完成切分：

```
步骤1：通读全文，了解帖子整体内容
         ↓
步骤2：按规则一，在所有句末标点（。！？；）处标记切分点
         ↓
步骤3：按规则三，识别列表结构，为每个独立列表项标记切分点
         ↓
步骤4：按规则二，检查是否有无标点但含转折连接词的长句，
       在连接词前标记切分点
         ↓
步骤5：按规则四、五，处理对话引用和纯表情/标签行
         ↓
步骤6：为每个片段分配seg_id（从1开始递增）
         ↓
步骤7：记录raw_text（片段原文）
```

## 六、与编码簿的衔接

### 6.1 编码员职责

- 编码员负责按本标准切分并分配`seg_id`
- 两位编码员编码相同的`seg_id`，**不得自行改变边界**
- 边界争议在试标阶段单独记录和裁决

### 6.2 切分一致性验证

在试标阶段，两位编码员独立切分同一批帖子，计算以下指标：

| 指标 | 计算方式 | 目标值 |
|------|----------|--------|
| 片段数一致率 | 两位编码员切出相同片段数的帖子占比 | ≥ 80% |
| 边界位置一致率 | 以字符位置为单位，两位编码员标记相同边界的占比 | ≥ 85% |
| 片段数相关系数 | Pearson/Spearman相关 | ≥ 0.90 |

### 6.3 切分与编码的分离

切分和编码应作为**两个独立步骤**执行：

1. **第一步：切分** → 产出固定的`seg_id`列表
2. **第二步：编码** → 在固定的`seg_id`上标注各维度标签

这样做的好处：
- 避免编码员在编码过程中"顺便"调整切分，导致两位编码员的单位不一致
- 切分一致性可以独立于编码一致性进行评估
- 模型训练时，切分和编码可以分别建模

## 七、对聚合指标的影响

切分标准直接决定`segment_count`，进而影响所有密度指标。在论文方法论部分需要报告：

| 需报告的指标 | 说明 |
|-------------|------|
| 样本片段长度分布 | 均值、中位数、标准差、最大值、最小值 |
| 每位编码员的平均切分数量 | 用于检测系统性偏差（一位编码员倾向于切得更细） |
| 片段数的平台差异 | 不同平台的帖文风格可能导致切分数量的系统性差异 |
| 切分一致率 | 见6.2节 |

如果切分一致率低于目标值，需要：
1. 分析分歧模式（是标点规则的分歧还是列表识别的分歧？）
2. 补充边界案例到裁决表
3. 修订规则后重新试标
4. 冻结最终版本

## 八、与模型切分的衔接

当模型辅助编码时，片段切分也需要由模型完成。建议方案：

### 8.1 模型切分策略

1. **基于标点的规则切分**：先用本报告的规则1-6进行自动切分
2. **人工校验**：编码员对模型切分结果进行校验，修正明显错误
3. **一致性评估**：计算模型切分与人工切分的一致率，作为模型质量的补充指标

### 8.2 注意事项

- 模型切分和人工切分使用**完全相同的规则**，不允许模型有"自己的切分逻辑"
- 如果模型切分与人工切分的一致率低于80%，需要检查规则是否在模型端被正确实现
- 训练集和测试集的切分必须来自同一套规则

## 附录A：社交媒体文本的标点使用特征

社交媒体文本的标点使用与规范书面语存在显著差异，切分标准需要适配这些特征：

| 特征 | 示例 | 切分处理 |
|------|------|----------|
| 连续感叹号/问号 | "太美了！！！""真的吗？？？" | 作为单个句末标点处理，不因数量增加而切分 |
| 无标点长句 | "今天去了栈桥人超多但是海很蓝" | 按规则六不切分（无标点无连接词） |
| 标点混用 | "这个地方、真的、太美了" | 顿号按逗号处理，不切分 |
| 表情替代标点 | "太美了😍😍😍海风也很舒服" | 表情不作为切分边界 |
| 空格断句 | "推荐 必去 冲" | 空格不作为切分边界 |
| 英文标点 | "So beautiful! Must go!" | 英文句号/感叹号/问号按中文对应标点处理 |

## 附录B：与问题清单的对应关系

本报告直接回应编码表问题清单中的 **P0-1：文本片段切分规则未确定**。该问题被列为P0（金标编码前必须解决），因为所有文本轨聚合指标均依赖`segment_count`。
