## 一、SRM（策略→资源传导矩阵，Strategy-Resource Matrix）

### 公式

```
SRM[CS-X][RS-Y] = COUNT(segments with CS-X AND RS-Y=1) / COUNT(segments with CS-X)
```

### 数学本质

这是一个**条件概率**：

$$P(RS\text{-}Y = 1 \mid CS\text{-}X)$$

即：**给定一个片段使用了策略X，它调用资源Y的概率是多少？**

### 从哪来的

直接改造自v2.0的 **SITE矩阵**。v2.0的SITE公式是：

```
SITE[CS-X][IM-Y] = COUNT(CS-X AND IM-Y=1) / COUNT(CS-X)
```

v3.0做的唯一改动是把分子里的 **IM-Y（形象建构类型）** 替换为 **RS-Y（目的地资源类型）**。分母不变——都是"使用策略X的片段数"。

### 为什么要替换

v2.0的SITE矩阵在审阅文档中暴露了两个问题：

1. **IM的操作化困难**：IM-COG需要"实体指称+属性描述"两个条件同时满足，IM-AFF需要"语义指向目的地的评价词"——编码员间一致性预期偏低
2. **SITE的理论声称过强**：P(IM-Y | CS-X) 反映的是"策略句子与形象维度的**语言共现频率**"，而非"策略如何**导致**形象建构"——后者需要受众实验才能验证

SRM的改进在于：**RS（目的地资源）是文本表层特征**，可以直接从句子中观察到（"栈桥"→RS-NAT/RS-CUL，"门票5块"→RS-FAC），不需要推断"这段话建构了什么形象"。这使得SRM比SITE更可操作、更诚实。

### 计算示例

帖子中有3个CS-INF片段：
- seg2："住宿选青岛站附近，人均200以内" → RS-FAC=1
- seg3："栈桥喂海鸥（免费）→ 台东夜市吃海鲜（人均50）" → RS-NAT=1, RS-GAS=1, RS-FAC=1
- seg5："避雷：不要买袋装啤酒" → RS-GAS=1

则：

```
SRM[CS-INF][RS-NAT] = 1/3 = 0.33
SRM[CS-INF][RS-CUL] = 0/3 = 0.00
SRM[CS-INF][RS-GAS] = 2/3 = 0.67
SRM[CS-INF][RS-FAC] = 2/3 = 0.67
SRM[CS-INF][RS-ATM] = 0/3 = 0.00
```

**解读**：信息策略主要调用美食和设施资源（各67%），较少调用自然资源（33%），从不调用文化资源和氛围资源。

### 双标签处理

当V1为双标签（如CS-INF+CS-EMO）时，该片段**同时向CS-INF和CS-EMO两行**的分母和分子贡献计数。这保证了SRM中策略-资源的多对多关系不被压缩。

## 二、SAM（资源→态度耦合矩阵，Resource-Attitude Matrix）

### 公式

```
SAM[RS-Y][AT-Z] = COUNT(segments with RS-Y=1 AND AT-Z) / COUNT(segments with RS-Y=1)
```

即：

$$P(AT\text{-}Z \mid RS\text{-}Y = 1)$$

### 数学本质

同样是**条件概率**，但传导方向翻转了：

- SRM问的是：**给定策略X，调用什么资源？**（策略→资源）
- SAM问的是：**给定资源Y，用什么态度表达？**（资源→态度）

### 从哪来的

借鉴了v2.0的 **VICS矩阵**（价值→形象耦合）。v2.0的VICS公式是：

```
VICS[PV-Y][IM-Z] = COUNT(PV-Y AND IM-Z) / COUNT(PV-Y)
```

v3.0做的改动：
1. 分子中的 PV-Y 替换为 RS-Y（资源类型）
2. 分子中的 IM-Z 替换为 AT-Z（态度类型）
3. 分母从PV维度数改为RS维度数

### 设计依据

v2.0的审阅文档指出，PV-EMO（情感价值）和sentiment（情感极性）在操作上很难分离——"门票只要80，太划算了"是功能价值还是情感价值？两者几乎不可区分。

SAM的改进：**不再问"受众感知到什么价值"（这是受众端推断），而是问"创作者用什么态度来表达资源"（这是生产端观察）**。

两种不同的资源-态度耦合模式：
- RS-NAT + AT-INF = "栈桥的海蓝蓝的"（自然+信息陈述）
- RS-NAT + AT-EVL = "栈桥的海真的太蓝了好美"（自然+评价表达）

这两种组合代表了不同的"资源-态度耦合模式"，在不同创作者层级间可能存在系统性差异。

### 计算示例

帖子中有5个片段调用了RS-NAT：

```
SAM[RS-NAT][AT-INF] = 2/5 = 0.40（自然资源中40%用信息方式呈现）
SAM[RS-NAT][AT-EVL] = 2/5 = 0.40（自然资源中40%用评价方式呈现）
SAM[RS-NAT][AT-SUG] = 1/5 = 0.20（自然资源中20%用建议方式呈现）
SAM[RS-NAT][AT-NON] = 0/5 = 0.00
```

## 三、COD（共现密度，Co-occurrence Density）

### 公式

```
COD_nat_cul = SUM(rs_nat × rs_cul) / segment_count
COD_gas_atm = SUM(rs_gas × rs_atm) / segment_count
COD_inf_evl = SUM((cs=CS-INF?1:0) × (at=AT-EVL?1:0)) / segment_count
```

### 数学本质

这是一个**联合概率的样本估计**：

$$\hat{P}(A=1 \text{ and } B=1) = \frac{\sum_{i=1}^{n} (A_i \times B_i)}{n}$$

其中 n = segment_count。

当A和B都是0/1变量时，A×B=1当且仅当A=1且B=1，其余情况为0。因此SUM(A×B)就是"两个维度同时为1的片段数"。

### 从哪来的

直接沿用v2.0的COD公式。v2.0的原始公式是：

```
COD_cog_aff = SUM(im_cog × im_aff) / segment_count
```

v3.0做的改动：
1. 把 im_cog/im_aff 替换为 rs_nat/rs_cul 等资源维度
2. 新增了跨轨道的COD（如CS-INF × AT-EVL）

### 设计依据

**Anderson (1981) 信息整合理论**（Information Integration Theory）和**Petty & Cacioppo (1986) ELM**（精细加工可能性模型）。

ELM的核心主张：信息可以通过**中央路径**（高卷入、仔细加工）或**边缘路径**（低卷入、启发式加工）被处理。**当认知信息和情感评价在同一片段中融合出现时**（如"栈桥始建于1892年，太震撼了"），它比分别陈述两句话具有更强的说服力——因为受众被迫同时加工两类信息。

COD衡量的就是这种**融合程度**：
- COD_nat_cul 高 → 创作者在同一个句子中同时调用自然资源和文化资源（如"崂山的道教文化太震撼了"）
- COD_gas_atm 高 → 创作者在同一个句子中同时调用美食资源和氛围体验（如"台东夜市的烟火气太治愈了"）
- COD_inf_evl 高 → 信息策略和评价态度在同一片段中共现（如"门票只要80，太划算了"）

### 计算示例

7个片段中：
- seg3：rs_nat=1, rs_gas=1, rs_fac=1, AT-EVL → rs_nat×rs_cul=0, rs_gas×rs_atm=0
- seg4：rs_nat=1, rs_atm=1, AT-EVL → rs_nat×rs_atm=1
- seg6：rs_cul=1, AT-INF → 无共现

```
COD_nat_cul = (0+0+0+0+0+0+0)/7 = 0.00
COD_nat_atm = (0+0+0+1+0+0+0)/7 = 0.14
COD_gas_atm = (0+0+0+0+0+0+0)/7 = 0.00
```

## 四、IFD（融合深度，Integration Fusion Depth）

### 公式

```
IFD = SUM(rs_depth) / segment_count
```

其中：

```
rs_depth = rs_nat + rs_cul + rs_gas + rs_fac + rs_atm（每片段取值0-5）
```

### 从哪来的

沿用v2.0的IFD公式。v2.0原始公式：

```
IFD = SUM(im_depth) / segment_count
其中 im_depth = im_cog + im_aff + im_con（每片段取值0-3）
```

改动：把 im_depth（形象建构深度，0-3）替换为 rs_depth（资源调用深度，0-5）。

### 设计依据

ELM + 信息整合理论。IFD衡量的是**每个片段平均调用了多少类目的地资源**：
- IFD=1.0 → 每个片段平均只调用1类资源（碎片化呈现）
- IFD=2.5 → 每个片段平均调用2.5类资源（融合式呈现）

IFD与COD的区别：
- IFD衡量的是"融合的**广度**"（调用了多少类资源）
- COD衡量的是"特定维度对的融合**深度**"（某两个维度同时出现的频率）

## 五、CED / CEI_pos / CEI_neg / CER（建构效能指标）

### 公式

```
CED    = SUM(rs_depth × sentiment) / segment_count
CEI_pos = SUM(sentiment > 0 ? rs_depth × |sentiment| : 0) / segment_count
CEI_neg = SUM(sentiment < 0 ? rs_depth × |sentiment| : 0) / segment_count
CER    = CEI_pos / (CEI_pos + CEI_neg)
```

### 数学本质

- **CED**：资源深度与情感极性的**加权平均**，衡量"建构效能的方向"（正值=整体正面建构，负值=整体负面建构）
- **CEI_pos**：正面片段的"资源深度×情感强度"均值，衡量"正面建构的力度"
- **CEI_neg**：负面片段的"资源深度×情感强度"均值，衡量"负面建构的力度"
- **CER**：正面建构强度占总建构强度的**比例**

### 从哪来的

v2.0的CE体系。v2.0原始公式：

```
CED    = SUM(im_depth × sentiment) / segment_count
CEI_pos = SUM(sentiment > 0 ? im_depth × |sentiment| : 0) / segment_count
```

改动：im_depth 替换为 rs_depth。

### v2.0的CE硬伤修正

v2.0审阅文档指出v1.0的CE使用|sentiment|导致正负建构无法区分（"避雷"帖贡献等价于"赞美"帖）。v2.0已修正（拆解为CEI/CED/CEI_pos/CEI_neg/CER五指标），v3.0保留这一修正，仅替换深度变量。

### 设计依据

核心思想是：**一个片段调用的资源维度越多（rs_depth越大）、情感越强烈（|sentiment|越大），它对目的地形象建构的"贡献"就越大**。

示例对比：
- "栈桥的海太蓝了" → rs_depth=1（仅RS-NAT），sentiment=+0.9 → CED贡献 = 1×0.9 = 0.9
- "栈桥始建于1892年，门票免费，太值得去了" → rs_depth=2（RS-CUL+RS-FAC），sentiment=+0.7 → CED贡献 = 2×0.7 = 1.4

后者虽然情感强度稍低，但因为调用了更多资源维度，建构效能反而更高。

### CER的分母为零问题

当一篇帖子的所有片段sentiment都处于中性区间[-0.3, +0.3]时，CEI_pos=0且CEI_neg=0，CER的分母为0。

**守卫条件**：若 CEI_pos + CEI_neg = 0，则 CER = 0.5（标记为"中性建构"）。

## 六、ICB（资源调用广度，Image Construction Breadth）

### 公式

```
ICB = (RS-NAT出现过 ? 1 : 0) + (RS-CUL出现过 ? 1 : 0) + (RS-GAS出现过 ? 1 : 0) + (RS-FAC出现过 ? 1 : 0) + (RS-ATM出现过 ? 1 : 0)
```

取值范围：0-5

### 从哪来的

v2.0的ICB修正版。v2.0原始公式：

```
ICB = (SUM(im_cog) > 0 ? 1 : 0) + (SUM(im_aff) > 0 ? 1 : 0) + (SUM(im_con) > 0 ? 1 : 0)
```

改动：3个IM维度 → 5个RS维度。

### 为什么是二值求和而非直接求和

v2.0审阅文档指出：ICB衡量的是"帖子中**至少激活过一次**的维度数"（广度），而非"总激活次数"（密度）。

一个帖子有10个片段都含RS-NAT，和只有1个片段含RS-NAT，在ICB上得分相同（都是1）——因为ICB关注的是"覆盖了多少类资源"，不是"每类资源出现了多少次"。

密度由 rsd_nat = SUM(rs_nat)/segment_count 单独衡量。

## 七、VIC（视觉主体覆盖广度，Visual Image Coverage）

### 公式

```
VIC = (VS-NAT出现过 ? 1 : 0) + (VS-ARC出现过 ? 1 : 0) + (VS-PEO出现过 ? 1 : 0) + (VS-FOD出现过 ? 1 : 0) + (VS-FAC出现过 ? 1 : 0)
```

取值范围：0-5

### 从哪来的

v2.1双轨版新增，是ICB的**视觉轨镜像**——用VS（视觉主体）替代RS（文本资源），逻辑完全一致。

## 八、双轨交叉指标

### text_visual_resource_match

```
text_visual_resource_match = (文本主导资源类型 == 视觉主体对应资源类型) ? 1 : 0
```

其中：
- **文本主导资源类型** = IMP向量中取最大值对应的RS维度
- **视觉主体对应资源类型** = 将VS维度映射到RS维度：

| 视觉主体 (V11) | 映射到资源 |
|---------------|-----------|
| VS-NAT（自然景观） | RS-NAT（自然资源） |
| VS-ARC（建筑遗产） | RS-CUL（文化资源） |
| VS-PEO（人物活动） | RS-ATM（氛围/体验资源） |
| VS-FOD（美食物产） | RS-GAS（美食资源） |
| VS-FAC（服务设施） | RS-FAC（设施资源） |

**设计目的**：衡量文字描述和视觉呈现是否指向同一类目的地资源。如果文字强调文化资源（RS-CUL）但配图全是自然景观（VS-NAT→RS-NAT），说明图文不匹配。

### resource_sentiment_gap

```
resource_sentiment_gap = 文本CED方向 - 视觉氛围情感倾向
```

其中视觉氛围情感倾向的赋值：
- VB-BRI（明亮欢快）→ +1
- VB-TRA（宁静治愈）→ +0.5
- VB-GRA（宏大壮观）→ +0.5
- VB-VIV（烟火气）→ 0
- VB-HIS（历史厚重）→ 0

**设计目的**：衡量文本情感倾向和视觉氛围倾向之间的差距。差距大说明"文字说的"和"画面传的"不一致。

## 九、公式来源总览

| 指标 | 数学本质 | v2.0原型 | v3.0改动 |
|------|----------|----------|----------|
| **SRM** | 条件概率 P(RS\|CS) | SITE P(IM\|CS) | IM→RS |
| **SAM** | 条件概率 P(AT\|RS) | VICS P(IM\|PV) | PV→RS, IM→AT |
| **COD** | 联合概率 P(A∩B) | COD P(IM_cog∩IM_aff) | IM→RS/CS/AT |
| **IFD** | 加权平均 depth/n | IFD | im_depth→rs_depth |
| **CED/CEI/CER** | 加权平均 (depth×sentiment)/n | CE体系 | im_depth→rs_depth |
| **ICB** | 二值求和 | ICB | 3维→5维 |
| **VIC** | 二值求和 | 新增 | ICB的视觉轨镜像 |
| **双轨交叉** | 映射+比较 | 新增 | — |

**核心数学工具只有两个**：
1. **条件概率**（SRM、SAM）——衡量"给定X条件下Y的概率"
2. **加权平均**（COD、CED、IFD）——衡量"某一特征在样本中的平均强度"

所有公式都不是从头发明的，而是把v2.0的公式中的变量名从"形象类型"替换为"资源类型/态度类型"，数学结构不变。

## 十、与v2.0 SITE/VICS体系的理论对话

### v2.0 SITE的问题

v2.0的SITE矩阵声称衡量"策略→形象传导效率"，但P(IM-Y | CS-X)实际衡量的是"策略句子与形象维度的语言共现频率"。这是一个**描述性统计**，而非**因果推断**——我们不能从"CS-INF句子中IM-COG出现频率高"直接推断"信息策略**导致了**认知形象建构"。

可能的混淆：
- 同一句子可能同时被编码为CS-INF和IM-COG，仅仅是因为两者共享"包含实体指称+属性描述"这一操作化标准，而非存在因果关系
- 这种**操作化定义的重叠**会导致SITE矩阵中某些单元格系统性偏高

### v3.0 SRM的改进

SRM用RS替代IM后，这种操作化重叠被打破：
- CS-INF的判定标准是"提供事实性信息"（策略层面）
- RS-FAC的判定标准是"涉及设施/交通/住宿"（内容层面）
- 两者在操作化上不重叠——一个句子可以是CS-INF但不含RS-FAC（如"Day1路线：栈桥→信号山"），也可以含RS-FAC但不是CS-INF（如"这个酒店太棒了！"是CS-EMO+RS-FAC）

因此SRM中的传导率比SITE更少受到操作化定义重叠的干扰，更接近"策略选择如何影响资源调用"的真实关系。
