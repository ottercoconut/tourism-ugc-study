## 一、现在要解决的研究问题

主问题是：KOL型与KOC型个人旅游UGC创作者，在旅游目的地形象的内容选择、表达资源和建构模式上是否存在差异？条件性次问题是：同一创作者的文本与图片产出之间是否存在资源对应。

角色分类因此不是人口画像装饰，而是组间比较的自变量。它必须与V1—V6文本结果、后续视觉结果及帖子互动结果隔离，不能用研究结果反向定义作者身份。

## 二、现行角色规则

### 2.1 先判断是否适用个人角色分类

```text
actor_scope =
  PERSONAL_CREATOR /
  ORGANIZATION /
  MULTI_AUTHOR /
  UNCLEAR
```

- `PERSONAL_CREATOR`进入EA、CE与SC判断；
- `ORGANIZATION`和`MULTI_AUTHOR`的最终角色为`NA`，而不是`UNK`；
- `UNCLEAR`因主体身份不足得到`UNK`；
- 组织官方号仍保留在范围审计中，但不进入个人创作者角色比较。

### 2.2 三个有效角色组件

| 组件 | 操作定义 | 人工/程序责任 |
|---|---|---|
| EA 专业权威 | 职业/资历、领域认证、机构关联或持续专业化历史至少一项有证据 | 两位编码员分别判断封闭criterion codes |
| CE 消费者同伴导向 | 至少两个不同日期的第一手旅行/消费来源，并持续面向同伴提供经验或建议 | 两位编码员分别判断封闭criterion codes |
| SC 持续创作 | 至少3个不同日期的旅游相关来源，最早与最晚相隔不少于30天 | 程序从证据manifest派生 |

关系性社群影响`CI`保留字段，但现库不含评论、回复或作者关系材料，统一记录为`UNAVAILABLE`，不参与证据充分性和角色派生。本轮不补抓相关数据。

### 2.3 唯一派生矩阵

| 条件 | 派生角色 |
|---|---|
| PERSONAL + EA=1 + CE=0 + SC=1 | `KOL_TYPE` |
| PERSONAL + EA=0 + CE=1 + SC=1 | `KOC_TYPE` |
| PERSONAL + EA=1 + CE=1 + SC=1 | `HYBRID` |
| 个人且证据充分，但未满足以上组合 | `ORDINARY` |
| 身份、时间或EA/CE/SC关键证据不足 | `UNK` |
| 机构或多人账号 | `NA` |

`ORDINARY`只是证据充分的残余创作者型别，不证明作者是“普通游客”。若论文未来要增加普通游客第三组，必须另建旅行者经历构念并重新校准；当前不进入关键路径。

## 三、为什么不按粉丝量一刀切

粉丝量测量的是可见触达规模，不等同于专业权威、消费者同伴导向或持续创作。因此：

- 高粉账号不自动成为KOL型；
- 低粉账号不自动成为KOC型；
- 一般认证、商业披露、点赞或评论数量均不能单独派生角色；
- 粉丝量只用于独立`reach_tier`及后续描述、分层或预设调整。

这能避免“用规模定义角色、再用角色解释规模相关内容差异”的循环逻辑。

## 四、缺失证据如何处理

只有证据包覆盖至少3个日期、跨度不少于30天，并包含可用主页信息或等价身份材料时，才允许填写`EA_NONE`或`CE_NONE`。否则必须使用`UNK`，不得把未抓到资料编码为0。

2026-08-24快照的五个平台均有帖子和作者键，但结构化主页信息主要集中在小红书和知乎；B站、抖音、微博的身份材料不足是实际数据限制。它不阻塞规则共同校准，但可能导致较高`UNK`比例，并阻塞正式KOL型/KOC型组间比较。

## 五、已经落地的试点路径

### 5.1 只读研究切片

- 源快照：13,831条`web_posts`，schema v18，完整性检查`ok`；
- 研究切片：`data/processed/role-pilot.sqlite`，只含规范化`web_posts`字段，不含图片、评论、调度、登录或爬虫控制表；
- 作者键：`platform_key + author_platform_id`；帖子键：`platform_key + platform_post_id`；
- SQLite、证据包和含作者资料的文件均受Git忽略保护。

### 5.2 同轮双任务共同校准

同一私有轮次内已生成：

1. V0身份任务：25名作者，其中15名历史较丰富、5名边界、5名随机；五个平台均有覆盖；每位作者最多展示5篇按最早、最晚和时间分位点确定性抽取的现库帖子。
2. V1—V6文本任务：另取25篇帖子，每个平台5篇；作者与V0完全不重叠；编码员看不到作者ID、主页、粉丝量或角色结果。

两名编码员的原始文件相互独立，裁决记录单独追加。`SC`、证据充分性和最终角色均由编码员直接填写，并由第三人逐字段人工裁决；人工期不运行公式、模型建议或程序派生。当前共同校准用于讨论和修订规则，不计算正式信度。

## 六、共同校准后的推进门

1. 汇总25名作者的逐字段分歧、`UNK`比例、角色支持数及锁定后的疑问标记；疑问标记不进入信度计算；
2. 完成15—25篇聚焦文献矩阵的人类核读，逐项标明“文献继承”或“本研究自定义”；
3. 修订并冻结`role-pilot-v0.2`；
4. 另抽50名未讨论作者进行双人独立盲试标，至少包含10名KOL型候选和10名KOC型候选；
5. 对`actor_scope`、`content_vertical`、EA/CE原子项与总体值、SC、证据充分性和最终人工角色分别计算Krippendorff's alpha、作者级bootstrap 95%置信区间、类别支持和混淆矩阵；
6. 任一核心字段`alpha < 0.80`或存在系统性边界分歧时，返回共同校准；原盲试标不能冒充正式信度；
7. 当前数据库若无法形成至少10名证据充分的KOL型与10名KOC型作者，规则试点仍可完成，但正式组间比较保持阻塞，不能用粉丝高低或缺失值强行补组。

## 七、对工程伙伴的直接要求

- 不回写正式采集数据库；
- 不新增评论、回复、关系材料采集；
- 不让角色模型或V1—V6内容标签出现在身份编码界面；
- 人工金标全部锁定并完成模型训练与锁定测试前，不启动非金标程序预测或派生；程序不得回写金标；
- 不让作者资料、粉丝量或角色候选出现在文本编码界面；
- 不覆盖两份原始编码，裁决另表；
- 在共同校准两侧都锁定前，不开放受限映射；
- 视觉V7—V11暂不启动，其延期不阻塞文本主论文和2026年11月前的预印本目标。

## 八、当前结论

身份界定问题已经达到“可以开始人工共同校准”的成熟度，但尚未达到“可以进行正式KOL型/KOC型比较”的成熟度。现阶段应立即编码、用真实分歧检验规则；不再等待导师前置确认，也不把试点规则或试点信度写成正式研究结论。
