## 一、当前决定

现阶段不把Label Studio作为共同校准或首轮人工编码的前置条件。人工编码直接使用固定Excel文件；每个标签单独成列，需要置信度的标签与对应置信度列相邻。负责人在收表后执行无损校验和确定性转换，生成规范长表`labels.csv`、问题清单与修订决策记录。

Excel只是人工录入界面，CSV是规范交换和分析格式；两者都不是理论规范源。字段名、中文列头、值域、适用条件和版本均以编码表v3.13.0为准，父子关系只用于审计，不自动生成或覆盖任何人工编码。固定Excel模板只承载V1—V11内容任务；V0作者角色使用独立作者表和证据manifest。

## 二、当前Excel→CSV流程

| 环节 | 输入或动作 | 责任边界 |
|---|---|---|
| 任务准备 | 预填`post_id`、`seg_id`/`img_id`、原文或图像定位信息 | 不修改正式采集数据库 |
| 人工编码 | 在固定Excel中逐字段判断全部标签、状态和对应置信度 | 不手写JSON、offset或问题编号 |
| 条件记录 | 置信度1—2或`UNRESOLVED`时填写原因和简短说明；文本阳性标签摘录最短充分证据 | 置信度不是效度或模型概率 |
| 负责人校验 | 检查必填、值域、结构性`NA`、父子冲突和跨字段冲突 | 只列出冲突，不静默改码 |
| 确定性转换 | 将宽表展开为`labels.csv`，生成证据offset与问题队列 | 转换规则不得推断新标签 |
| 决策与升版 | 两名负责人处理规则缺口、是否实质改码及重编码范围 | 实质规则变化须先更新编码表 |

当前固定Excel共承接文本与视觉全部人工字段。文本轨包括V3的5个父类与22个子项、V4的2个父类、10个Layer 2亚类与4个事件子类、V5语言功能/评价亚类/可判定性/方向/双向强度，以及V6的适用性、4个父类、12个子类和其他项；视觉轨包括V7、V8、V9、V10和V11。所有人工标签在模型训练完成后仍分别作为模型输出目标或经批准的视觉任务目标，不能只预测父类或用逻辑OR替代人工字段。V4旧`rs_r_act`例外：它只在分析阶段由`rs_r_rec OR rs_r_evt`汇总，不进入人工模板或模型输出。

## 三、Label Studio何时才值得引入

只有出现下列至少一项真实瓶颈时，才启动Label Studio技术探针：

1. 多轮任务分配和回收已无法用固定Excel及manifest稳定管理；
2. 文本证据需要频繁的多跨度可视化框选，复制引文明显成为主要负担；
3. 图片区域级证据或视频抽帧任务已经冻结，Excel无法可靠表达；
4. 编码员数量增加，需要账号隔离、盲标分配和集中审计；
5. 已有锁定金标和测试集，准备引入模型预标注或主动学习。

在此之前引入Label Studio只会增加界面配置、JSON适配、权限隔离、备份恢复和版本维护成本，不解决当前更关键的规则冻结与信度问题。

## 四、若以后引入Label Studio

Label Studio只负责人工录入和证据框选；项目程序继续负责任务准备、格式转换、校验、信度、仲裁和版本追踪。技术探针应先用少量文本与图片验证：

- 全部原子字段及对应置信度能否无损导出；
- `0/1/UNK/NA/UNRESOLVED`是否保持原义，空白不会被误写成0；
- 中文、emoji、重复引文和重叠证据的Unicode offset是否可逆；
- A/B编码员是否真正隔离，原始判断能否按稳定ID合并；
- 导出后能否确定性转换为现行`labels.csv`而不丢失字段。

模型建议不得进入共同校准、独立盲试标或锁定测试集。视觉轨在研究人口、V7/V8边界、V11专门规则和独立信度验证完成前，也不得因工具可用而提前进入正式生产。

## 五、当前阻塞边界

工具本身不是当前阻塞。真正阻塞正式研究的是：

- `at_eval_subtype`的最终单选/多选及其专门裁决规则尚未冻结；
- V4新增活动/事件字段仍须完成边界校准和独立盲试标，旧`rs_r_act`记录须回到原文重编码；
- 共同校准后仍须用新样本完成独立盲试标并达到逐字段信度门；
- 视觉研究人口、V7/V8唯一裁决规则与V11专门状态规则尚未冻结；
- 当前转换脚本默认编码表版本已对齐v3.13.0；正式运行仍应显式记录版本、任务manifest和随机种子。
