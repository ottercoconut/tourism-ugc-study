## 七、阶段 3：双人试标与编码表冻结

### 3.1 试标设计

- [ ] 将约100篇帖子拆为两种用途：20—30篇共同校准，只讨论规则、不计算正式信度；另取70—80篇新样本进行独立盲试标。
- [ ] 试标预算以帖子计，实际工作量按这些帖子的全部固定片段和有效标签判断数记录。
- [ ] 覆盖正式平台集合、KOL/KOC候选、长短文本、商业/非商业和预期稀有标签。
- [ ] 试标样本包含概率部分和边界定向部分；两者用途分开报告。
- [ ] 两名编码员在不查看模型建议的情况下独立完成。
- [ ] 记录逐模块和逐帖耗时。

### 3.2 必须计算的诊断

- [ ] 确定性切分的重复运行一致性、`post_id + seg_id`唯一性、原文可追溯性与人工审计问题率；不计算编码员独立切分一致率。
- [ ] 每个原子二值标签的 Krippendorff's alpha。
- [ ] Cohen's kappa、原始一致率、阳性一致率和阴性一致率。
- [ ] 每个标签的阳性数、流行率、`UNK/NA` 比例。
- [ ] 多标签集合的补充一致性。
- [ ] 主要混淆对和分歧原因分类。
- [ ] 每个标签和模块的人工耗时。

### 3.3 修订与再试标

- [ ] 逐条裁决分歧，但信度只使用裁决前盲标。
- [ ] 将典型分歧加入边界案例库。
- [ ] 只修改定义、规则和例句，不根据期望研究结论修改标签。
- [ ] 规则发生实质变化后，使用未参与讨论的新确认样本检验改进；不得只在已讨论样本上证明信度提高。
- [ ] 旧试标样本若进入训练池，必须按最终规则重新编码并标明其不承担独立确认功能。
- [ ] 为每个标签分别决定研究地位（核心/探索）和执行方式（可自动/AI辅助确认/人工专判），两条轴不得混为一谈。

### G3 试标通过门

- [ ] 核心标签目标为 `alpha >= 0.80`。
- [ ] `0.667 <= alpha < 0.80` 的标签只能暂定使用并继续复查。
- [ ] `alpha < 0.667` 的标签不得进入正式模型训练，除非修订后重新通过试标。
- [ ] 稀有标签不能仅凭 alpha 判断；同时检查正例数和阳性一致率。
- [ ] 编码时间在两人团队可承受范围内；否则先优化界面和规则，再考虑标签状态。
- [ ] 先在编码表内部升版并冻结理论契约，再同步编码簿和模型说明；工程schema需另行授权后按该版本实现。

## 九、阶段 5：建立锁定评估金标与训练标注

### 5.1 样本与用途

- [ ] 明确“500 篇文本”只是起始人工编码预算锚点，不是充分性承诺，也不默认全部属于双人评估金标。
- [ ] 预算以帖子计，其实际成本按全部固定语义片段、有效标签判断数和人工分钟记录。
- [ ] 明确区分：双人独立编码并共识形成的“评估金标”，与单人主标、风险复核形成的“训练标注”。
- [ ] 概率样本用于代表性评估；定向样本用于稀有/边界学习，不能混用总体权重。
- [ ] 同一作者和近重复泄漏组不得跨训练、开发和测试集合。
- [ ] 平台、KOL/KOC、文本长度和核心稀有标签在可行范围内分层。

### 5.2 锁定测试与挑战集

- [ ] 在任何模型训练、主动学习和阈值选择前冻结测试成员。
- [ ] 测试集只在模型和阈值全部冻结后开启。
- [ ] 代表性锁定测试集与稀有标签挑战集分开。
- [ ] 挑战集只报告稀有标签识别能力，不估计总体流行率。
- [ ] 若测试集中核心标签正例不足，先调整设计或追加独立评估样本，不能从训练集事后挑选。

### 5.3 分层人工质量控制

- [ ] 锁定代表性测试集由两人全部独立盲标；模型答案不可见，并在讨论前计算冻结规则下的逐标签信度。
- [ ] 两人以共识裁决形成评估金标；无法达成共识时保留 `UNK` 并从该标签的评估/损失中屏蔽，透明说明没有第三位仲裁员。
- [ ] 训练与主动学习样本由理论负责人主标；工程负责人复核预注册的随机比例，并复核全部稀有、低置信、规则冲突和分布外样本。
- [ ] 随机复核比例根据试标错误率和时间预算预先设定，建议以20%为起点后用审计结果调整，不把建议比例写成既定事实。
- [ ] 只有双标共识部分称为“评估金标”；训练标注的来源和复核状态必须随记录保留。
- [ ] 原始双标、单人主标、复核、裁决、理由、证据跨度和版本全部追加式保留。

### G5 人工证据通过门

- [ ] 每个拟自动化标签都有足够训练正例和可解释的测试正例；充分性由学习曲线与区间决定，不采用统一神奇数字。
- [ ] 锁定测试金标的正式人工信度达到标签预定状态的要求。
- [ ] 训练标注与评估金标身份不混用；训练/开发/测试/挑战集 manifest 和 SHA-256 已封存。
- [ ] 任何成员、标签或规则变化都会产生新金标版本，而不是原地覆盖。

## 十、阶段 6：建立模型基线与多头 Transformer

### 6.1 最小模型集合

- [ ] 建立 TF-IDF + One-vs-Rest 线性模型作为非神经基线。
- [ ] 实现共享预训练文本编码器 + V1/V2/V3/V4逐字段混合输出的Model 0。
- [ ] 可共现原子标签使用独立 Sigmoid；条件互斥情感方向使用条件 Softmax。
- [ ] V1/V2/V4父类与子类、“无/其他”和适用性均保留输出；规则层只报告冲突，不覆盖概率。
- [ ] 第一轮不同时实现标签注意力、标签图、层级长文本模型、领域继续预训练和多种增强。

### 6.2 训练完整性

- [ ] 只使用训练集拟合参数，开发集选择超参数和逐标签阈值。
- [ ] 测试集在最终冻结前不可读取指标。
- [ ] 保存随机种子、依赖、代码版本、输入 manifest、标签版本和所有超参数。
- [ ] 对类别不平衡方法做最小消融，不机械使用极端权重。
- [ ] 检查作者、近重复、平台复用和时间泄漏。

### 6.3 模型评估

- [ ] 逐标签 Precision、Recall、F1、PR-AUC 和置信区间。
- [ ] Macro/Micro 汇总，但不能用汇总掩盖稀有标签失败。
- [ ] 逐标签阈值、阳性数、混淆矩阵和概率校准。
- [ ] KOL/KOC、平台、长短文本和商业/非商业子群表现。
- [ ] 保存原始 logit、概率、阈值和二值结果。

### G6 模型通过门

- [ ] 每个标签独立决定“可自动/仅辅助/人工专判”，不以一个总 F1 一刀切。
- [ ] 核心标签的阈值由误判成本和后续用途预先定义。
- [ ] 子群中无法验证的标签不得用于该子群的自动比较。
- [ ] Model 0 未显示明确问题前，不进入复杂模型开发。

## 十一、阶段 7：验证主动学习与选择性人机协同

### 7.1 主动学习等预算实验

- [ ] 在完全标注的训练/开发池内离线模拟主动学习，不触碰锁定测试集。
- [ ] 随机抽样与主动学习使用相同初始种子、人工预算、模型和评估集。
- [ ] 比较随机、仅不确定性、不确定性+多样性、以及加入稀有标签候选的策略。
- [ ] 使用多个随机种子报告学习曲线和不确定性。
- [ ] 记录达到同一质量门所需的人工片段数和人工分钟数。

### 7.2 标签级选择性自动化

- [ ] 高置信标签自动编码；只有不确定标签转人工，不因一个标签不确定而退回整条全部标签。
- [ ] 稀有标签、模型冲突和关键标签对优先人工复核。
- [ ] 高置信预测仍按平台和创作者组随机抽审。
- [ ] 复核界面区分盲法审计与可见模型建议的生产复核，避免把两种证据混合。
- [ ] 报告风险—覆盖率、自动覆盖率、人工复核率和审计错误率。

### 7.3 停止规则

- [ ] 在开发集预先定义“连续若干轮无实质提升”的停止条件。
- [ ] 稀有标签连续定向采样仍不能通过时，转为人工专判或探索性标签。
- [ ] 主动学习未优于随机抽样时，不声称节省标注。
- [ ] 选择性复核未优于随机复核时，不声称人机路由有效。

### G7 AI 协同通过门

- [ ] 证明神经模型相对线性基线的增益。
- [ ] 证明主动学习相对等预算随机抽样的增益，或诚实报告没有增益。
- [ ] 证明选择性复核在给定人工预算下改善风险—覆盖率。
- [ ] 节省比例来自真实标注时间和实验结果，不来自预设数字。

### 两人团队的硬约束

- [ ] 工程负责人必须参与盲法试标和锁定评估金标，不能完全退出人工信度环节。
- [ ] 理论负责人不得单独根据模型建议修改金标。
- [ ] 没有第三仲裁员时，使用两人共识裁决并明确报告这一限制。
- [ ] 同一阶段只保留一个主模型和一个必要基线，避免模型竞赛耗尽工程资源。
- [ ] 图片辅助工作不能挤占文本主线的金标和模型验证预算。

## 十七、全局停止与禁止规则

- [ ] 编码表和切分规则未冻结，不启动正式评估金标或训练标注。
- [ ] 正式人工信度未通过，不启动对应标签的模型训练。
- [ ] 锁定测试集未冻结，不启动模型选择。
- [ ] 模型答案不得出现在盲法金标界面。
- [ ] 主动学习没有等预算随机对照，不声称节省标注。
- [ ] 标签未通过子群和随机审计，不在该子群全自动使用。
- [ ] 模型未通过下游测量误差审计，不用其预测作正式内容结论。
- [ ] G8 未通过，不正式计算或解释 SRM/SAM。
- [ ] 图片质量或视觉信度未通过，视觉轨降级，不阻塞文本论文。
- [ ] 未经独立数据支持，不新增创作者意图、受众反应或因果机制结论。
- [ ] 不因预算接近耗尽而降低已预声明的质量门；改为缩小结论范围。

## 二十、清单维护规则

- 每次只更新已经产生证据的复选框，并附对应 artifact、报告或 commit。
- 任何阶段门失败时，记录失败标签、失败原因、回退方案和新版本，不原地修改历史结论。
- 理论构念、标签、单位、值域、派生关系、平台设计范围或结论边界变化时，必须先更新编码表并升版，再同步受影响的当前理论文档。
- 理论文档文件名保持稳定，不添加版本号或“修订版”等描述；版本与迭代记录只写在文档内部。
- 本清单不授权修改代码、配置、测试、数据模板或运行协议；工程对齐须由单独任务明确授权。
- 本清单只决定执行顺序；具体算法、阈值和样本量仍需由试标与正式验证结果决定。
