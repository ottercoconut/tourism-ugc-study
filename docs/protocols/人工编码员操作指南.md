# 人工编码员操作指南

## 文档信息

- 文档状态：`CURRENT_ALIGNED`
- 内部版本：`v1.0`
- 对齐标准：[`编码表.md`](../data-dictionary/编码表.md) `v3.14.0`
- 配套编码簿：[`编码簿_青岛旅游UGC编码框架.md`](../data-dictionary/编码簿_青岛旅游UGC编码框架.md)
- 适用人员：第一次接触本项目、不了解论文理论或模型的人工编码员
- 当前可执行任务：V0创作者身份共同校准、V1—V6文本共同校准
- 当前不可执行任务：V7—V11图片轨，须等待负责人另行通知
- 更新日期：2026年8月31日

这份指南只告诉你**拿到任务后应该怎么做**。你不需要理解论文假设、统计方法、机器学习或程序实现，也不需要猜研究者希望看到什么结果。

你的任务只有四件事：

1. 阅读指定材料；
2. 按表中问题逐项作出判断；
3. 记录判断把握和最短证据；
4. 遇到现有规则无法处理的情况，如实标记，不自行发明新标签。

## 一、先确认你拿到的是哪一种任务

| 任务 | 你会看到什么 | 你要判断什么 | 不能看什么 |
|---|---|---|---|
| V0创作者身份 | 作者主页资料和固定历史帖子 | 主体类型、内容方向、专业权威、消费者经验、持续创作、证据是否充分、最终角色 | 目标帖的文本/图片标签、粉丝档位、互动结果、模型建议 |
| V1—V6文本 | 完整帖子和已经切好的文本片段 | 商业披露、目的地类型、内容策略、旅游资源、语言功能与情感、目的地属性 | 作者姓名、主页、粉丝数、创作者角色、图片标签、模型建议 |
| V7—V11图片 | 单张图片 | 画面主体、拍摄方式、人物、消费符号、可见对象状态 | 正文、文本标签、作者身份、互动结果 |

三种任务使用不同材料和不同表格。不要把作者判断写进文本表，也不要用正文替图片作判断。

当前图片轨尚未开始。除非负责人明确通知，否则不要填写V7—V11。

## 二、所有编码员都必须遵守的十条规则

1. **只使用发给你的个人文件。** 不复制或覆盖另一名编码员的文件。
2. **第一轮独立完成。** 在负责人宣布本批次锁定前，不讨论答案，不查看另一人的答案。
3. **空白不是0。** 空白表示“还没做”；检查后没有发现相应内容才填0。
4. **按证据判断。** 不因为“感觉像”“通常会”“粉丝很多”或“研究可能需要”而补标签。
5. **可以同时成立就分别填。** 多标签任务没有“只能选最主要一个”的要求。
6. **父类和子类都由你填写。** 不等程序自动补父类，也不要用父类替代子类。
7. **不要改片段。** 不自行拆分、合并、删除或调整`seg_id`。
8. **不要发明标签。** 现有值都不合适时，按本指南记录未决或额外问题。
9. **每个判断都要独立给置信度。** 不能给整行或整篇帖子只填一个总分。
10. **不使用任何模型建议。** 人工共同校准、盲试标、金标编码和人工裁决期间均不让系统替你判断、补值或纠错。

## 三、表格中的值是什么意思

### 3.1 二值字段

| 填写值 | 最直白的意思 | 什么时候用 |
|---|---|---|
| `1` | 有 | 材料中有直接证据支持这个标签 |
| `0` | 没有 | 这个问题适用于当前材料，但认真检查后没有发现 |
| `NA` | 不需要判断 | 前置条件没有触发，这个字段对当前材料不适用 |
| `UNK` | 材料不足，无法判断 | 字段适用，但材料缺失、模糊或互相冲突；只有表中允许时才能使用 |
| `UNRESOLVED` | 现行规则解决不了 | 只在共同校准阶段临时使用；必须同时填置信度1、原因和一句说明 |
| 空白 | 还没做 | 不能把空白当作任何正式答案 |

最容易混淆的是：

- `0`＝已经判断，而且没有；
- `NA`＝根本不需要判断；
- `UNK`＝应该判断，但材料不够；
- `UNRESOLVED`＝共同校准时发现现行规则本身无法给出唯一答案；
- 空白＝没有完成。

### 3.2 单选字段

目的地类型、情感方向等字段不是填0或1，而是从该行`valid_values`列列出的值中选择一个。不要填写表中没有的缩写。

### 3.3 多标签字段

“可共现”表示同一片段可以同时有多个标签。例如“门票80元，很值得去”既有信息，也有评价；两个字段都应填1，不需要二选一。

## 四、置信度怎么填

置信度表示“你认为这个判断能不能稳定重复”，不是帖子质量，也不是标签为真的数学概率。

| 分数 | 怎么理解 | 你还要做什么 |
|---|---|---|
| `5` | 证据非常直接，基本没有别的合理答案 | 正常保存 |
| `4` | 证据清楚，只需要少量语境理解 | 正常保存 |
| `3` | 有依据，但靠近边界，可能有一个合理替代答案 | 正常保存，不强制备注 |
| `2` | 证据较弱、冲突或很依赖上下文，有多个合理答案 | 必须选原因并写一句说明 |
| `1` | 没有足够证据形成唯一答案 | 共同校准时填`UNRESOLVED`；必须选原因并写一句说明 |

只有置信度1—2时填写以下内容：

- `reason_code`：从`BOUNDARY`、`CONTEXT`、`CONFLICT`、`EVIDENCE_MISSING`、`OTHER`中选择；
- `alternative_values`：确实有合理替代答案时用`|`分隔，没有就留空；
- `low_confidence_note`：用一句话说明“为什么难判断”。

置信度3—5时，上述三项保持空白。客观字段和结构性`NA`不填置信度。

## 五、文本任务的完整操作顺序

当前文本共同校准固定按以下顺序完成。不要跳着做，也不要先看标签名再寻找符合它的句子。

### 第一步：打开自己的工作簿

先在“开始这里”页确认：

- 编码表版本是`v3.14.0`；
- 文件中的编码员编号是你自己的编号；
- 当前阶段是`COMMON_CALIBRATION / PILOT_ONLY`；
- 你没有打开另一名编码员的文件。

### 第二步：先判断整篇帖子

每篇帖子先完成两个帖子级问题：

1. **V1明确商业披露**：帖子是否直接写明广告、赞助、合作、受邀体验或推广？
   - 明确写出才填1；
   - 只出现品牌、购买链接、夸赞或营销语气，不能据此填1；
   - 填0只表示“没有观察到明确披露”，不等于证明没有商业关系。
2. **V2主要目的地类型**：整篇帖子主要属于自然、文化、城市、度假还是混合类型？按表中允许值单选。

平台、字符数等已经预填的系统信息不要修改。

### 第三步：逐个处理固定文本片段

每个`seg_id`都按V3→V4→V5→V6的顺序回答四组问题。

#### V3：这段话在“怎么表达”？

依次问：

1. 是否在提供旅行信息？
2. 是否在解释背景、原因或意义？
3. 是否在营造感官、氛围或个人感受？
4. 是否在提问、号召互动或邀请参与？
5. 如果前四类都不是，它是否属于寒暄、结构过渡、平台话语、纯符号或其他残余表达？

父类和子类都要逐项填。同一片段可以同时有多个父类和多个子类。

#### V4：这段话“提到了什么旅游资源”？

先判断自然资源或人文资源，再判断具体子类：

- 自然资源：地文、水域、生物、天象气候；
- 人文资源：遗址遗迹、建筑设施、饮食文化、民俗风情、休闲游憩活动、节事与文体事件；
- 如果是节事与文体事件，再判断体育赛事、演艺活动、节庆会展或其他事件。

只根据片段实际提到的内容判断。不要因为地点在青岛就自动给所有青岛相关资源标签。

#### V5：这段话“在说什么话、态度是什么”？

依次判断：

1. 是否陈述可以核验的事实？
2. 是否明确评价好坏、价值、满意或不满？
3. 是否向读者提出建议、推荐、提醒或劝阻？
4. 如果前三项都没有，是否属于其他/未命中？

信息、评价和建议可以同时为1。

如果有评价，再选择评价亚类。只要片段包含评价或建议，还要判断情感方向是否可判：

- 可判时选择正面`POS`、负面`NEG`、混合`MIX`或真实中性`NEU`；
- 不可判时，方向和正负强度填`NA`；
- 正面强度和负面强度分别填0、1或2，不要自行计算净分。

#### V6：评价或建议“针对目的地的什么方面”？

先问：这段话是否在评价或建议某个目的地属性？

- 如果没有，`asp_applicable=0`，其余V6字段全部填`NA`；
- 如果有，`asp_applicable=1`，再逐项判断它针对资源品质、活动体验、氛围、价格、服务、设施、拥挤、管理、交通、卫生、风险或治安保障中的哪一项；
- V6只记录“评价对象是什么”，正面还是负面仍由V5记录。

纯事实“门票80元”可以属于V5信息，但如果没有“贵、便宜、值不值”等判断，V6通常不适用。

### 第四步：为每个主观字段填写置信度

不要给整段只填一个置信度。每个需要人工判断的字段都有自己的置信度。

### 第五步：阳性标签摘录最短证据

V3—V6实质性阳性判断原则上都要复制一段最短、足够支持判断的原文：

- 原样复制，不改字；
- 保留会改变意思的否定、程度和转折，例如“不太推荐”不能只摘“推荐”；
- 同一段证据可支持多个字段；
- 不需要手算字符位置；只有同一句证据在片段中重复出现时，才填写重复位置提示。

### 第六步：片段切分看起来不对时不要改`seg_id`

保持当前片段不变，在额外问题中选择`UNITIZATION_PROBLEM`，用一句话说明建议在哪里拆分或合并。负责人会在批次结束后统一处理。

### 第七步：完成一批后保存并锁定个人文件

- 检查本批没有空白答案；
- 检查置信度1—2都有原因和说明；
- 不把`0`误当作“没做”；
- 保存自己的文件，不覆盖旧文件；
- 在负责人确认两份原始文件都锁定前，不与另一名编码员讨论答案。

## 六、一个完整的文本判断示例

片段：“海风很舒服。”

一种符合现行规则的填写思路如下：

| 维度 | 判断思路 |
|---|---|
| V3 | “海风”带来感官和身体感受，可判断是否命中情感渲染及其相应子类 |
| V4 | 片段直接调用天象气候类自然资源，可判断`rs_n`和`rs_n_cli` |
| V5 | “很舒服”是明确评价，方向为正面；再分别判断正、负强度 |
| V6 | “舒服”评价的是地方氛围/体验，可判断适用性及对应父类、子类 |
| 证据 | 对评价和情感可摘录“很舒服”；对资源可摘录“海风” |
| 置信度 | 如果判断直接明确，可填4或5；如果对V6具体子类仍犹豫，可单独给该字段3或更低 |

示例只演示思考顺序。正式答案必须根据完整片段、完整帖子语境和当前编码簿判断。

## 七、V0创作者身份任务怎么做

只有收到V0作者任务的编码员才执行本节。每名作者只使用指定T0证据包，并按以下顺序完整人工判断：

1. 这是单一自然人、机构、多人账号还是无法确认？
2. 作者长期内容主要属于旅游、美食、生活方式、多领域还是其他？
3. 逐项检查EA专业权威证据，再给出EA总体人工判断；
4. 逐项检查CE重复第一手经验和同伴导向，再给出CE总体人工判断；
5. 检查是否至少有3个不同日期的旅游相关来源，且最早与最晚相隔不少于30天，给出SC人工判断；
6. 判断现有证据是否足以完成角色判断；
7. 综合材料直接填写最终人工角色；
8. 为每个字段分别填写置信度和证据来源ID。

角色判断时不要看粉丝数，也不要用高粉、认证、单篇专业表达或单次旅游经历直接决定KOL/KOC。角色主表锁定后，触达规模才在另一张表中人工记录。

V0共同校准和裁决期间同样不运行自动公式或模型建议。程序不能替人填写EA、CE、SC、证据充分性或最终角色。

## 八、哪些情况必须报告负责人

出现下列任一情况时，在额外问题列中记录，不要自行解决：

- 现有标签完全无法表达材料中的重要内容；
- 两条现行规则给出互相冲突的答案；
- 必须依靠完整上下文才能判断，但表中没有相应规则；
- 当前片段明显应该拆分或合并；
- 表中允许值与编码簿不一致；
- 工作簿版本不是`v3.14.0`；
- 发现自己看到了本任务不应出现的作者、图片、文本或模型信息。

报告问题不等于新增标签。只有负责人形成书面决定并更新编码表后，新规则才生效。

## 九、交表前一分钟检查

- [ ] 我使用的是自己的文件和自己的编码员编号。
- [ ] 我没有查看或讨论另一名编码员的答案。
- [ ] 所有应填字段都不是空白。
- [ ] `0`、`NA`、`UNK`和`UNRESOLVED`没有混用。
- [ ] 所有主观判断都填写了逐字段置信度。
- [ ] 所有置信度1—2都有原因和一句说明。
- [ ] 所有实质性阳性文本判断都尽量附上最短证据原文。
- [ ] 我没有改动`post_id`、`seg_id`、原文、字段名、允许值或版本字段。
- [ ] 我没有自行新增标签、合并标签或修改编码规则。
- [ ] 文件已经按负责人指定位置保存，且没有覆盖另一人的原始文件。
