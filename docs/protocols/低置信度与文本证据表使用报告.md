# 疑问标记与文本证据表使用报告

> 文档状态：`CURRENT_OPERATIONAL`
> 内部版本：`v2.0`
> 对齐编码表：`v3.16.0`
> 更新日期：2026年9月5日
> 路径说明：为避免外部链接失效，文件名暂时保留旧称；现行内容不再使用1—5级人工置信度。

## 一、两类记录分别解决什么问题

| 记录 | 回答的问题 | 不能代表什么 |
|---|---|---|
| 可选疑问标记 | 编码员完成这个字段后，是否仍觉得需要锁定后讨论？ | 准确率、效度、模型概率、信度或研究结果 |
| 文本证据 | 这个阳性判断可以回到原文的哪一段核查？ | 自动证明标签正确或代替第二编码员 |

编码值才是研究判断。疑问标记和证据都是过程辅助信息，不替代双人独立编码、Krippendorff's alpha或人工裁决。

## 二、疑问标记的最简规则

正常情况下，编码员只填写`label_value`。确实拿不准时：

1. 先填写当前最可辩护的值；现行规则无法给出唯一值时填`UNRESOLVED`。
2. 在`review_flag`填`?`。
3. 从`BOUNDARY / CONTEXT / CONFLICT / EVIDENCE_MISSING / OTHER`中选一个`reason_code`。
4. 有合理替代值时填`alternative_values`，多个值用`|`连接。
5. 在`review_note`用一句话说明难点。

`UNRESOLVED`必须标`?`。客观字段和结构性`NA`不得标`?`。没有标记时，原因、替代值和说明都留空。

离线转换将问号规范化为`review_flag=1`，并生成：

```json
{"reason_code":"BOUNDARY","alternative_values":["ADM","SAT"],"note":"主导评价亚类难以唯一判断。"}
```

带标记但已经填写正式值的记录只供锁定后复核，不自动进入问题队列。`UNRESOLVED`以及编码员另行登记的框架缺口、反例、语境依赖或切分问题才自动进入负责人问题队列。

## 三、独立编码和讨论边界

- 每名编码员在锁定前只能看见自己的标签和疑问标记。
- 两份个人原始文件必须先锁定并记录哈希，再显示双方差异。
- 一致性统计比较全部应编码字段，不只比较标过`?`的字段。
- 讨论时先看实际分歧，再看双方疑问标记；即使两人答案相同，双方都标问号也应复核边界。
- 疑问标记不进入Krippendorff's alpha，不写作论文变量，也不作为模型输入、监督目标或样本权重。
- 旧轮次已有1—5级置信度原样保留为历史过程资料，不删除、不换算、不与新轮次合并统计。

## 四、文本证据怎么填

文本轨V3—V6的实质性阳性判断原则上至少摘录一段最短充分证据。`0`、`UNK`、`NA`及整体排除或不适用判断不伪造局部证据。

编码员只填写：

- `evidence_quote`：从`raw_text`原样复制的最短充分文本；
- `evidence_start_if_repeated`：同一引文在原文重复出现时才填写其起点。

否定、程度和转折会改变意思时必须一起复制。父类与子类可以共享同一段证据。编码员不手算JSON和offset。

转换工具生成`evidence_spans_json`：

```json
[
  {"fields":["at_has_eval","sentiment_dir"],"start":2,"end":5,"quote":"很舒服"}
]
```

必须满足`raw_text[start:end] == quote`。文本字符位置按Unicode字符、从0开始、采用左闭右开区间`[start, end)`。

## 五、三类人员分别做什么

| 角色 | 负责 | 不负责 |
|---|---|---|
| 编码员 | 标签值；有疑问时的问号、原因和一句说明；阳性文本证据 | JSON、offset、问题编号、规则修订或裁决 |
| 转换工具 | 校验输入；生成`review_notes_json`、`evidence_spans_json`和初步问题队列 | 决定标签、解释语义或改写人工答案 |
| 研究负责人 | 锁定文件；比较全部字段；组织讨论；记录裁决与修订 | 在锁定前向编码员展示另一人的答案 |

## 六、从工作簿到规范长表

```text
个人工作簿
  ├─ 每个字段填写 label_value
  ├─ 拿不准才填 review_flag=? + 原因 + 一句说明
  └─ 阳性文本判断摘录 evidence_quote
          ↓ 两份原始文件锁定
离线转换
  ├─ labels.csv：原子标签、疑问过程字段、文本证据
  └─ calibration-issues.csv：UNRESOLVED和显式额外问题
          ↓
负责人复核、讨论、裁决和规则修订
```

转换命令：

```bash
.venv/bin/python scripts/annotation_prepare_calibration.py \
  round_*/calibration-coding.csv \
  --labels-output round_*/labels.csv \
  --issues-output round_*/calibration-issues.csv \
  --codebook-version v3.16.0
```

当前契约为`calibration-coding-v2.0`和`labels-v3.0`。

## 七、交表检查

- [ ] 每个应判断字段都有`label_value`。
- [ ] 正常判断没有被要求填写置信度。
- [ ] 所有`UNRESOLVED`都标了`?`。
- [ ] 每个`?`都有合法原因和一句说明。
- [ ] 没有标`?`的行没有多余疑问备注。
- [ ] 客观字段和结构性`NA`没有疑问标记。
- [ ] 实质性阳性文本标签有最短充分证据，或已记录可解释的缺失问题。
- [ ] 两名编码员的文件保持独立并先锁定。
- [ ] 一致性检查覆盖全部字段。

## 八、常见错误

| 错误 | 正确做法 |
|---|---|
| 每个字段仍填1—5分 | 后续任务改用新版空模板；已填写记录原样保存，不换算 |
| 为所有字段都标问号 | 只有确实拿不准才标`?` |
| 两人只讨论带问号的字段 | 全量比较标签值，问号只是补充线索 |
| 把问号当作低质量标签并删除 | 保留当前判断，锁定后复核；只有人工裁决能改金标 |
| 用疑问标记计算信度或训练模型 | 从研究变量、alpha和模型输入中排除 |
| 给`0`随便摘一段“证据” | 保持证据为空；必要时用疑问说明记录困难 |
| 锁定前共享疑问和答案 | 两份个人文件先独立完成并锁定 |

本报告只说明过程字段和文本证据的使用方式。标签定义与状态边界以[`编码表`](../data-dictionary/编码表.md) v3.16.0为准，面向编码员的完整顺序见[`人工编码员操作指南`](人工编码员操作指南.md)。
