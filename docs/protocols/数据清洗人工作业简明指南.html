数据清洗人工作业简明指南

非正式说明｜用朴素的话告诉你坐下来以后具体做什么

这份文件是便于实际操作的说明，不是新的研究协议。遇到边界冲突时，以 正式人工审核方法和 工程方案为准。

先说结论：确实没有想象中复杂

对绝大多数正常帖子，你基本只需要做两件事：
  1. 这段文字能不能正常看懂？
  2. 如果能看懂，它的主要内容是不是和旅游有关？

所以，它不只是单独标一个“是否旅游相关”，但只多了一个很简单的前置检查： 先排除空白、删除提示、登录提示和损坏文本。大多数正常文本都会直接进入第二问。

你不需要判断帖子写得好不好、是不是广告、作者是什么类型、图片是否好看， 也不需要计算抽样、权重、Kappa、Wilson 上限或模型分数。系统会处理这些技术工作。

你拿到文件以后怎么做

  1. 打开系统导出的 CSV。
    不要自己从数据库挑帖子，也不要复制空白模板后添加帖子。系统导出的文件已经固定了本轮要看的对象。
  2. 不要改系统预填的列。
    任务 ID、帖子 ID、版本、平台、轮次和规范化文本都保持原样。
  3. 先看文字能不能正常用于分析。
    填写 structure_label。
  4. 再看主要内容是不是旅游。
    填写 tourism_label。不要只看到“青岛”两个字就判为旅游。
  5. 填写简短理由、身份哈希和完成时间。
    理由尽量使用项目规定的代码，不在表里写真实姓名或不必要的自由文本。
  6. 保存并交给导入程序检查。
    导入程序会检查标签组合、对象身份、轮次和时间格式。不要直接修改派生数据库。

第一问：文字能不能正常看懂

情况怎么填常见例子
有实际内容，哪怕很短 usable “青岛两日游路线”“今天去了栈桥”“这家酒店离地铁很近”
没有可分析的实际文字 invalid 空白、内容已删除、请登录查看、加载失败、乱码到无法辨认
现有文字不足以稳定判断 uncertain 内容被截断，只剩无法判断含义的零碎片段
短、口语、错别字多、写得普通、有广告语气，都不等于 invalid。 只要还能看懂实际意思，一般就是 usable。

第二问：主要内容是不是旅游

标签朴素理解例子
related 读者主要会把它理解成旅行、游玩或目的地信息 景点体验、旅行路线、游客吃住行、交通攻略、目的地推荐、旅行避坑
unrelated 虽然可能提到青岛或某个地点，但重点是别的事情 本地招聘、房产销售、学校通知、普通社会新闻、与出游无关的日常办事
uncertain 内容太少，或者两个主题混在一起，现有规则无法稳定决定 只有“青岛见”“终于到了”，没有其他上下文
not_applicable 文字本身已经无效，所以不再判断旅游相关性 只和 structure_label=invalid 配套使用

拿不准时，可以顺着问

  1. 有没有在讲到访、游玩、路线、交通、酒店、餐饮或景点体验？
  2. 有没有在评价目的地、景点、旅游服务或游客感受？
  3. 这些信息会不会影响别人是否去、怎么去或怎么玩？
  4. 如果出现地名，它是不是仅仅作为地址或事件背景？

前三问任意一项明显成立，通常就是 related。只有第四问成立， 而前三问都不成立，通常才是 unrelated。证据确实不够时就填 uncertain，不要猜。

最常见的四种填写组合

结构旅游含义
usablerelated正常可用的旅游内容
usableunrelated文字正常，但主题不是旅游
invalidnot_applicable文字无效，不再判断旅游
usable 或 uncertainuncertain保留到后续确认，不自动排除

为什么 14 天后还要再看一小批

系统会提前从第一轮样本中固定 200 条。至少 14 天后，你会收到第二轮文件。 第二轮做法完全一样，只是：

  • 不要查看第一轮答案；
  • 文件会重新排序；
  • 仍然按同一版规则重新判断；
  • 系统会比较两轮结果，检查判断是否稳定。

你仍然只是在回答前面两个简单问题。原始一致率和 Cohen's κ 由系统计算， 不需要手工处理。如果稳定性没有过门槛，先看哪些边界容易混淆，再按新版本规则做一轮补充复核。

哪些东西之后还会回来找你

1. 少量最终确认

两轮答案不同、出现 uncertain 或模型与人工结果冲突的帖子，会进入最终确认。 你会重新看原文和已有理由，补一条最终记录。原来的两轮答案不会被删除。

2. 近重复候选对

系统可能给你两段很相似的文字，让你判断：

  • duplicate：基本是复制、转载或不改变实质内容的轻微改写；
  • not_duplicate：只是同景点、同话题或相似模板，但提供了不同经历或信息；
  • uncertain：证据不够，暂不合并。

3. 模型边界和最终抽查

模型只会帮忙把可能有问题的帖子排到前面。你仍按同样的两个问题复核。 最后还会从准备保留的帖子中随机抽查至少 300 条，确认剩余错误足够低。

大概有多少工作

  • 第一轮：概率样本目标 500 条，加定向边界样本目标 200 条；重叠对象只看一次。
  • 至少 14 天后：复核其中预先固定的 200 条。
  • 后续：只处理分歧、不确定、近重复候选和模型边界对象，数量由实际数据决定。
  • 发布前：对候选保留人口做至少 300 条概率抽查；人口不足时全部检查。

所以最主要的劳动确实是对正常文字判断“旅游相关 / 不相关”。其他步骤是为了让这个简单判断有记录、能复查、经得起论文审阅。

你不需要做什么

  • 不需要自己随机抽样或挑选疑似无效帖子。
  • 不需要判断图片。
  • 不需要标广告、情绪、目的地形象或论文内容分析维度。
  • 不需要计算一致率、Kappa、权重或置信区间。
  • 不需要决定模型参数或直接接受模型答案。
  • 不需要删除源数据库里的任何记录。
  • 不需要为了让结果好看而减少 uncertain。

每次交文件前的 30 秒检查

  • 我没有修改系统预填的 ID、版本、平台、轮次和文本。
  • 每条都先判断了结构，再判断旅游相关性。
  • invalid 只和 not_applicable 配套。
  • 不确定的对象没有被硬猜成相关或不相关。
  • 时间使用带时区的 UTC 格式。
  • 文件里没有真实姓名、绝对路径、公式或隐私信息。
一句话记忆：先看文字有没有实际内容，再看它主要是不是在讲旅游； 拿不准就如实标不确定，剩下的抽样、复核、统计和发布由系统负责。

对应正式方案版本：数据清洗 v3.1 / text-cleaning-v1.1。
