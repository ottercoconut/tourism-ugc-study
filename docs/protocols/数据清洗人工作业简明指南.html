数据清洗：你实际要做什么

一句话：你只需要看一条文字，判断它是不是以旅游为主要内容。系统已经检查过文字结构，所以不用再判断“有效/无效”，也不用过 14 天重新做一遍。

你要填的核心内容

填写值什么时候用
related主要在讲游览、旅行经历、攻略、景点、住宿餐饮交通等旅游体验。
unrelated虽然抓到了关键词，但主体是日常生活、新闻、招聘、房产、普通商品等非旅游内容。
uncertain只看现有文字必须靠猜才能决定。可以不用；如果确实没有这种记录，最后就是 0 条。

最快的判断办法

第一问：如果去掉“青岛”、景点名或抓取关键词，这条内容还明显在讲一次出行、游览或目的地体验吗？
是：通常选 related。不是：继续看第二问。
第二问：地名是不是只充当背景，真正主体是日常生活、社会事件、招聘、房产或其他事情？
是：选 unrelated。
第三问：现有文字是否少到两种解释都说得通？
是：选 uncertain，不要硬猜。

几个直观例子

内容大意标签理由
青岛三日路线、住宿和景点体验related旅游行程是主体
在栈桥看日落，人太多但风景很好related明确是目的地游览体验
青岛某小区招聘物业人员unrelated地名只是招聘地点
青岛队比赛结果和球员转会unrelated主体是体育新闻
“今天终于到了”，没有地点或活动上下文uncertain现有文字不足以判断

实际操作顺序

  1. 打开导出的 CSV。
  2. 逐行阅读 normalized_model_text。
  3. 只填 tourism_label。
  4. 在 reason_codes 填简短代码，例如 travel_main_subject、keyword_only 或 insufficient_context。
  5. 保持 annotator_hash 一致，填写带时区的 annotated_at_utc。
  6. 保存 CSV，运行导入命令；程序会检查错字、非法值和重复记录。

不用做的事

  • 不用判断文字结构是否有效；系统已对全部记录做确定性检查。
  • 不用找第二个人重复标。
  • 不用 14 天后再标一次。
  • 不用为了“看起来完整”故意制造 uncertain。
  • 不用看模型预测，也不要让模型替你改标签。

最后怎么把关

系统会把概率样本和边界样本分开记录，用人工结果训练并在独立测试集上评价模型。模型认为很像非旅游的内容仍要人工确认；模型认为低风险的保留候选还要再做一次冻结概率抽检。这个终验是抽新样本检查整体结果，不是让你重新标以前的同一批记录。

对应正式方案：数据清洗 v3.2 / text-cleaning-v1.2 / schema 32。具体边界以《文本数据清洗人工审核方法》为准。
