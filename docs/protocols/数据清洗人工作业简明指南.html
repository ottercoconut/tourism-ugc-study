数据清洗：你实际要做什么

一句话：你只需要看一条文字，判断它是不是以青岛旅游为主要内容。系统已经检查过文字结构，所以不用再判断“有效/无效”，也不用过 14 天重新做一遍。

你要填的核心内容

填写值什么时候用
related主要在讲青岛的游览、旅行经历、攻略、景点、住宿餐饮交通、旅拍，或面向游客的展览、节庆、演出、市集等城市体验。
unrelated主体不是青岛旅游，例如日常生活、新闻、招聘、房产、普通商品、其他目的地旅游，或面向商家的招商、行业展会和供应链活动。
uncertain只看现有文字必须靠猜，或者文字明显由多个不连贯来源拼接而成。可以不用；如果确实没有这种记录，最后就是 0 条。

最快的判断办法

第一问：这条内容是否明确在讲到访青岛的出行、游览或目的地体验？
是：通常选 related。不是：继续看第二问。
第二问：青岛是否只充当地点或关键词，真正主体是日常生活、社会事件、招聘、房产、其他目的地旅游或商家推广？
是：选 unrelated。
第三问：现有文字是否少到两种解释都说得通，或明显混入互不相干的抓取内容？
是：选 uncertain，不要硬猜。

几个直观例子

内容大意标签理由
青岛三日路线、住宿和景点体验related旅游行程是主体
在栈桥看日落，人太多但风景很好related明确是目的地游览体验
周末去青岛看面向公众开放的艺术展related展览被作为到访和城市休闲体验
供应商报名参加青岛食品产业展unrelated主体是 B2B 招商或行业经营
青岛某小区招聘物业人员unrelated地名只是招聘地点
青岛队比赛结果和球员转会unrelated主体是体育新闻
“今天终于到了”，没有地点或活动上下文uncertain现有文字不足以判断
一条记录异常拼接餐厅、招聘和无关新闻片段uncertain抓取污染导致没有单一可判断的主体，保留记录等待确认

实际操作顺序

  1. 打开导出的 CSV。
  2. 逐行阅读 normalized_model_text。
  3. 只填 tourism_label。
  4. 标签留空表示还没有标；只有读完仍无法稳定判断时才填 uncertain。
  5. 不填原因码或自由文本备注；这类字段不属于清洗学习输入。
  6. 原始标注表和后续最终确认表都不填写编码者/复核者哈希或逐条时间；轮次完成时间和数据库导入时间由系统在文件级、操作级记录。
  7. 保存待标 CSV 后先运行 finalize-post，程序会把它合回完整样本，并检查错字、遗漏、越界和重复记录。
  8. 合并成功后只保留一张 tourism-relevance-completed.csv，即可运行正式导入。

不用做的事

  • 不用判断文字结构是否有效；系统已对全部记录做确定性检查。
  • 不用找第二个人重复标。
  • 不用 14 天后再标一次。
  • 不用为了“看起来完整”故意制造 uncertain。
  • 不用看模型预测，也不要让模型替你改标签。

最后怎么把关

系统会把概率样本和边界样本分开记录，用人工结果训练并在独立测试集上评价青岛旅游相关性模型。概率样本中的自然重复保留，以反映帖子层面的真实占比；定向样本按高相似文本分量选择，每个分量最多给你一条，不再让同一广告或模板反复占用标注名额。近重复确认另用独立任务完成。模型认为很像非旅游的内容仍要人工确认；模型认为低风险的保留候选还要再做一次冻结概率抽检。这个终验是抽新样本检查整体结果，不是让你重新标以前的同一批记录。

对应正式方案：数据清洗 v3.2 / text-cleaning-v1.5 / schema 34。具体边界以《文本数据清洗人工审核方法》为准。
