## 1. 工程边界

1. 正式采集数据库始终只读。`exclude` 只表示不进入派生分析发布，不得删除或覆盖源记录。
2. 模型输入只有按冻结规则生成的规范化文本。`platform_key` 只保留为来源谱系字段，不得进入特征、切分、阈值、审计配额或性能门。
   规范化从候选构建绑定的冻结采集快照重做：普通正文原样进入通用规则；Quill Delta JSON 仅拼接字符串 `insert`，忽略已声明的图片/截断嵌入和全部格式属性。损坏 Delta、非法操作、未知嵌入或无文本结构以稳定 reason code 失败关闭。识别依据正文结构，不读取平台。
3. 训练、阈值策略和推理是三个解耦阶段：训练产出不可变模型与校准器；阈值策略独立冻结；初始全量和未来新增批次调用同一冻结模型。
4. 唯一权威标签证据是 `final-nonduplicate-model-reference` CSV 与唯一配对的 `finalized` manifest，不复制到 `text_post_annotations`。
5. 人工处理结果优先于模型路由；任何自动动作都必须能追溯到模型、策略、输入批次和输出 manifest。

## 2. 最终700条不重复建模参考集

现有完成 CSV、旧 manifest、重复候选 CSV、人工重复决定、候补队列和补充标注只作为生成谱系，不是并列权威源。生成器执行以下冻结步骤：

1. 只读校验旧700条文件哈希、样本框、数据库身份、旧派生文本和旧概率证据；再校验冻结源快照哈希，从源标题/正文生成新的规范化文本投影。旧派生文本只作输入谱系，不能成为最终模型字段；
2. 对700条执行 `700 × 699 / 2 = 244,650` 个无序对的字符3–5 gram TF-IDF余弦计算；`similarity >= 0.80` 只进入人工候选，低于阈值的人工明确关系可显式补入；
3. 精确规范哈希相同自动成组，其他边必须人工最终确认；确认边取传递闭包。组内旅游标签冲突必须由独立最终证据关闭；
4. 初始700条的每个确认重复分量按规范化文本完整度、稳定帖子身份决胜；样本框、平台和旅游标签均不参与代表选择，产生的500/200框缺口由后续候补调度恢复；
5. 去重缺口从同一冻结候选人口按固定种子生成全局候补队列。队列在读取候补标签前冻结，不设平台配额、不按平台排序；候补进入标注前与初始700条全部谱系成员（包括已排除成员）和同轮候补执行相同重复检查，并沿初始确认分量传播。仅由候补组成的确认重复分量沿用完整度与稳定身份规则；触及任一已有确认分量成员的候补属于“确认重复候补”，不得计数，也不重新抽样既有代表；
6. 结构不可用、确认重复、重复候选未确认或标签未最终确定者不计数，继续按冻结秩补充，直至概率/定向框分别为500/200。前轮已标候补若在新分量中不再是代表，其标签不得自动转移给新代表；新代表必须获得自身人工最终标签，只有显式标签冲突确认可以覆盖分量代表标签。

概率框补样不得继承被替换记录的纳入概率或权重。只有能够从冻结补样设计证明联合纳入概率时，才可记录新概率和倒数权重；当前无法证明时 manifest 必须使用 `unavailable_after_replacement` 和稳定 reason code，总体估计不得使用。

最终验证器要求 manifest `status=finalized`，CSV 恰好700条，空白与 `uncertain` 均为0，源身份和重复分量身份各700个，最终确认重复对为0，样本框为500/200，并明确概率估计状态。CSV 至少包含任务/源身份、规范化文本、标签、样本框、选择原因与秩、合法概率证据、证据来源和重复分量；manifest 绑定标签手册、候选构建、新旧规范化规则身份、冻结源快照、文本投影及输入、成员、重复决定、候补队列和输出哈希。验证与训练均强制使用当前冻结配置从无 WAL、SHM 或回滚日志旁文件的源快照重新投影，逐身份核对最终正文及投影哈希；通过后训练才使用最终 CSV 的模型文本，绝不退回旧派生库正文。

## 4. 训练与校准契约

### 4.1 泄漏分组和测试冻结

作者、精确重复和最终确认的近重复关系通过传递闭包组成泄漏分量。全体参考记录按时间选择最后 20% 为测试候选，再扩展到候选连接的完整泄漏分量。扩展后的测试集一次冻结，最终比例允许高于 20%。剩余数据进行全局分组分层训练/验证切分；平台不参与任何名额分配。

测试集不得用于词表拟合、特征选择、超参数搜索、Sigmoid 校准、阈值选择或失败后的反复调参。训练输出必须保存测试成员 manifest 和跨集合泄漏检查结果。

### 4.2 折外校准

首个正式模型为字符 TF-IDF 加固定 `C=1.0`、`class_weight=balanced` 的线性 SVM。训练部分内部最多使用五折相同泄漏分组交叉验证；如分量结构不能支持五折，实现在不低于两折且每个拟合端、留出端都含双类的范围内下降折数，否则失败关闭。每条训练记录只获得其未参与拟合的一个折外决策分数；无正则一维 Sigmoid 校准器只以这些折外分数和训练标签拟合。随后以完整训练部分拟合最终向量器和 SVM，冻结向量器、分类器、校准器、规范化规则和依赖环境。该 baseline 不执行 C 搜索，避免在尚未定义模型选择门时引入隐式调参。

校准器输出 `p_unrelated`，其值必须为 `[0, 1]` 内有限数。训练运行包保存训练折外概率和验证集概率；验证报告包括总体 Precision、Recall、F1、PR-AUC、混淆矩阵、Brier score 和 log loss，其中 `0.5` 只用于诊断分类指标，不是路由阈值。训练阶段的测试集状态固定为 `locked_not_opened`，不生成测试概率或测试指标。阈值策略冻结后，测试报告再包括总体指标、阈值表现、自动覆盖率和时间切片，不生成平台分类指标。

### 4.3 不可变模型 artifact

模型运行包至少保存：

- `model_id`、artifact SHA-256 与创建时间；
- 参考 CSV、参考 manifest、源快照和成员 manifest 的哈希；
- 规范化规则、字符 TF-IDF、线性 SVM、Sigmoid 校准器及其参数；
- 泄漏分组、训练/验证/测试成员与随机种子；
- Git SHA、Python 与关键依赖版本；
- 总体测试输出和机器可读验收状态。

artifact 一旦冻结不得原地覆盖。新增记录的到来不触发 `fit`，也不替换 artifact。

### 4.5 challenger 实验边界

下一轮模型提升按以下顺序实施，任何一项都不得读取测试概率：

1. 标签一致性复核已完成：复核者只看文本与规则，34条强矛盾记录与34条按原标签、切分和长度匹配的随机预测正确对照被随机混合；两组结果分别统计，不用于外推全体错标率。用户明确批准的10条已由 `apply` 入口原位封存，3条否决结果在 manifest 中维持原标签；
2. 首轮只建立三类有限候选：现有字符 TF-IDF＋线性 SVM 的小网格、字符 binary count＋NB log-count ratio＋线性 SVM、同一字符 TF-IDF＋逻辑回归。标题/正文分通道、中文分词特征和 fastText 不进入首轮；
3. TF-IDF＋线性模型只比较 `ngram_range ∈ {(2,5),(3,5),(2,6)}`、`min_df ∈ {1,2}`、正则强度 `C ∈ {0.3,1,3}`；`max_df=0.995`、`sublinear_tf=true`、类别权重、文本规范化和随机种子保持冻结。候选选择在训练侧嵌套 `StratifiedGroupKFold` 中完成，外层与内层都使用同一 leakage component；
4. 当前验证集已被分析，只能作为次级开发稳健性检查。sparse 唯一候选的验证 ID `6d105b334df0234350a4b5c32358f7a9` 已封存为 `directionally_consistent`；验证 Accuracy 由86.36%升至88.18%，UGC误排仍为10条，无关误留由5条降至3条，log loss/PR-AUC/Brier 三项方向均改善。该结果不允许继续修改 sparse 网格；
5. 因 sparse 改善幅度有限且预计人工灰区仍大，已另行完成唯一 Qwen3-Embedding-4B 冻结语义 baseline。它不是依据验证结果扩 sparse 参数，而是独立模型族：固定公开权重 revision、单通道全文、任务说明、2048 token、L2 归一化、唯一逻辑回归头、随机种子、训练预算和依赖身份。运行 `14feebc04a7a61b8b97f959a998d14dc` 的 UGC 误排率改善2.09个百分点，但 log loss、PR-AUC 与 Brier 均恶化，故 `validation_status=not_allowed`；
6. Issue #45 在上述失败之后冻结三层改进树：第一层只复用已封存训练 embedding 做 MRL 维度与线性头 nested OOF；若失败，第二层做每个外层训练端内独立选择的 sparse＋Qwen logit 融合；若仍失败，第三层采用固定英文 instruction 与 head-tail 双视图重新编码。任一层通过既有训练验收门即停止扩展；
7. 比较同时报告两类错误、PR-AUC、Brier、log loss、风险—覆盖率与自动覆盖；不得仅按 Accuracy 排名，也不得在验收门冻结前决定生产模型。

如果模型族、特征、超参数搜索空间或模型选择门发生变化，必须先同步科研方案、工程方案、配置身份与运行契约，再开始拟合。旧 baseline 和开发证据保持历史可验证，不得覆盖。

## 5. 独立阈值策略契约

阈值策略是与模型分离、不可变并可哈希的 artifact，至少保存：

- `policy_id` 和策略内容 SHA-256；
- 所绑定的 `model_id`；
- `T_keep`、`T_exclude`；
- 保留集审计的事件定义、样本量、事件率门、单侧置信上限和区间方法；
- 最低测试指标、最低自动覆盖率和审计失败后的恢复条件；
- 决策依据、冻结时间和适用批次边界。

调整阈值只能创建新 `policy_id`，不得重新训练模型、覆盖旧策略或改写已完成运行。策略必须满足：

```text
p_unrelated <= T_keep             -> auto_keep
T_keep < p_unrelated < T_exclude  -> manual_review
p_unrelated >= T_exclude          -> auto_exclude
```

边界等号不得由实现自行改变。`auto_exclude` 只作用于派生发布状态。

初始全量与未来新增批次共用独立推理入口。入口只允许加载一个已冻结模型和一个与其兼容的阈值策略，不得调用任何训练或校准方法。目标批次必须先完成结构门和同版规范化。

- `inference_run_id`、`model_id`、`policy_id`、目标批次 ID；

- `p_unrelated`；
- 原始路由动作与是否因降级状态转人工；
- 人工任务引用、最终决定来源和最终决定；

## 7. 人工证据与最终决定

人工灰区、未来新增人工结果和保留集审计各自使用独立的任务 CSV、完成 CSV 与 manifest，不复用同一任务身份。人工结果覆盖模型建议：

## 8. 保留集审计与降级状态机

保留集审计从最终保留人口进行全局随机抽样，不设平台配额。事件定义、样本量、事件率门、单侧置信上限和恢复条件目前均为 `UNSET`。自动排除人口不执行常规随机审计。

未来实现至少包含以下状态：

1. `policy_unset`：允许打分；所有未有人工作答的记录转人工。
2. `automatic_routing_enabled`：三个区间按冻结策略执行。
3. `auto_keep_suspended`：保留集审计失败后，模型继续打分；原 `auto_keep` 转人工，`manual_review` 维持人工，`auto_exclude` 继续执行。
4. `recovered_with_new_policy`：只有新阈值策略满足冻结的恢复门后才可恢复自动保留；旧策略和旧运行保持不可变。

审计失败不得通过换 seed、删除不利样本或改写旧策略来消除。正式可靠性声明只覆盖最终保留语料的残留无关风险；过度删除仅由锁定测试集总体表现间接评估，不能表述为已做部署期排除人口审计。

## 9. 失败语义

以下情况一律停止自动决定并写出机器可读失败原因：参考 CSV 或 manifest 哈希不符、身份或文本不一致、泄漏分组跨集合、测试集被用于调参、模型或策略 artifact 不完整、概率非有限、阈值非法、推理尝试调用训练、人工结果冲突、源库出现写操作、审计门未设或审计失败后仍执行自动保留。

失败不删除中间证据，不覆盖既有运行。可恢复问题通过新的运行 ID 重试；改变阈值必须创建新策略，改变模型必须形成新的模型 artifact 和独立决策记录。
