# 数据清洗工程方案

- 科研协议：`3.2`
- 标签手册：`text-cleaning-v1.2`
- 主配置：`configs/cleaning-v3.2.yaml`
- 派生 schema：`32`

## 1. 工程边界

正式采集库始终只读。系统先创建 SQLite 快照，再把规范化文本、抽样、人工证据、模型、帖子决定、终验和发布记录写入派生库。清洗阶段不读取或筛选媒体文件，也不回写原始 UGC。

正式人工任务只有 `tourism_label`。`structure_status` 仅存在于全量确定性处理结果和候选构建门禁中，不导出为人工字段；任何非 `usable` 记录都会使正式候选决定构建失败，等待上游隔离并重新冻结快照。

## 2. 配置

```yaml
protocol_version: "3.2"
text_label_guide_version: "text-cleaning-v1.2"
algorithm_versions:
  derived_schema: 32
annotation:
  initial_probability_size: 500
  probability_min_per_platform: 80
  initial_targeted_size: 200
  periodic_increment_posts: 2000
  periodic_probability_size: 100
```

已删除 `initial_recheck_size`、`minimum_recheck_interval_days`、一致率/κ 门槛和补充复检配置。旧配置不能冒充 v3.2 运行。

## 3. 活动数据契约

### 3.1 人工任务 CSV

```text
task_id,sample_run_id,source_post_id,source_version,platform_key,normalized_model_text,tourism_label,reason_codes,annotator_hash,annotated_at_utc
```

导入端接受 `related | unrelated | uncertain`，并明确拒绝含 `structure_label`、`review_round` 或 `commercial_label` 的旧模板。`uncertain` 不要求出现。

### 3.2 派生表

- `text_deterministic_results.structure_status`：全量自动结构门证据；
- `text_sampling_runs` / `text_sample_members`：冻结概率、定向或新增窗口样本及纳入概率；
- `text_post_annotations`：一次性人工相关性记录；
- `text_post_adjudications`：不确定项、模型边界项或其他显式最终确认；
- `text_model_runs` / `text_model_predictions`：不可变模型运行与候选动作；
- `post_decision_builds` / `post_decisions`：候选和最终帖子决定；
- `text_keep_audit_*`：自动保留候选的冻结概率终验；
- `analysis_release_*`：最终发布与验收证明。

schema 32 不再创建延时复检、补充复检或一致性评估表；活动人工表和帖子决定表也不保存结构标签。

## 4. 运行顺序

所有 Python 命令使用 `.venv/bin/python`。

```bash
.venv/bin/python scripts/cleaning_snapshot_source.py \
  --source-db <SOURCE_DB> --snapshot-dir <SNAPSHOT_DIR> \
  --derived-db <DERIVED_DB> --config configs/cleaning-v3.2.yaml \
  --run-id <RUN_ID> --code-version <GIT_SHA>

.venv/bin/python scripts/cleaning_discover_increment.py \
  --source-db <SNAPSHOT_DB> --derived-db <DERIVED_DB> \
  --config configs/cleaning-v3.2.yaml --run-id <RUN_ID>

.venv/bin/python scripts/cleaning_process_text.py \
  --derived-db <DERIVED_DB> --config configs/cleaning-v3.2.yaml \
  --run-id <RUN_ID>

.venv/bin/python scripts/annotation_export_tasks.py \
  --derived-db <DERIVED_DB> --config configs/cleaning-v3.2.yaml \
  create-initial --candidate-build-id <BUILD_ID>

.venv/bin/python scripts/annotation_export_tasks.py \
  --derived-db <DERIVED_DB> --config configs/cleaning-v3.2.yaml \
  export-post --sample-run-id <SAMPLE_RUN_ID> --output <TASKS.csv>

.venv/bin/python scripts/annotation_import_annotations.py \
  --derived-db <DERIVED_DB> --config configs/cleaning-v3.2.yaml \
  --input <COMPLETED.csv> --imported-by-hash <HASH> post-reviews
```

随后按显式 ID 清单构建泄漏分组、训练相关性模型、完成模型边界项最终确认、冻结候选决定、执行保留集审计、构建最终决定和发布包。任何步骤不得使用“最新一条标签”之类的隐式选择。

## 5. 关键不变量

1. 正式候选决定必须被同一快照的一帖一条确定性结果完整覆盖，且全部为 `usable`。
2. 概率样本保存纳入概率和权重；定向样本没有总体权重。
3. 同一抽样运行中的同一帖子版本只能有一条原始人工相关性记录。
4. 模型只产生 `high_risk_review`、`manual_review` 或 `low_risk_keep_candidate`，永不直接产生排除。
5. 人工证据优先于模型；冲突或不确定均进入 `review`。
6. 低风险自动保留必须通过正式运行、切分隔离、阈值、逐平台抽审和保留集终验。
7. 候选决定与最终决定分开封存，最终决定绑定实际通过的审计 ID。
8. 样本、标签、模型、决定和发布成员均追加式或封存后不可变。

## 6. 验收输出

最终验收包至少包含：

- 配置摘要、代码版本、运行环境和源快照 manifest；
- 五个平台的源数量和全量结构门计数；
- 概率/定向/新增监测样本计数与标签分布；
- 独立测试集总体和逐平台指标；
- 模型高风险、边界、低风险及人工最终确认数量；
- 保留集终验样本、事件数、点估计、单侧上限与平台切片；
- 最终 keep/review/exclude 数量及分析发布 manifest；
- 未执行的证据必须明确标为未执行，不得由测试通过状态代替。

## 7. 迁移说明

v3.2 是破坏性派生 schema 变更。正式数据尚未按旧人工契约生产，因此不迁移或伪造旧结构字段；应从只读源快照重新建立派生库。若本地存在 v31 开发库，只作历史调试材料，不可与 v32 正式运行混用。
