# 数据清洗工程方案

## 1. 版本与边界

- 方案版本：`3.1`
- 派生 schema：`31`
- 文本标签手册：`text-cleaning-v1.1`
- 主配置：`configs/cleaning-v3.1.yaml`
- 人工方法：`docs/protocols/文本数据清洗人工审核方法.md`
- 运行环境：CPython 3.13.5，统一使用 `.venv/bin/python`

科研方案、人工方法和工程方案共享版本。标签、抽样、阈值、算法或决定状态改变时，
三者必须在同一 commit/PR 中同步更新。

本流程只处理帖子结构可用性、旅游相关性和文本重复关系。清洗阶段不读取媒体文件，
不创建逐条城市、商业属性或视觉质量标签，也不回写正式采集数据库。

## 2. 输入与不可变快照

源库只读。正式运行先验证必需表和字段、青岛范围契约、SQLite 完整性与外键，再用
只读 URI 和 backup API 建立一致性快照。快照记录：

- 源文件复制前后 SHA-256 与快照 SHA-256；
- 帖子计数和主键 manifest；
- 配置摘要、代码版本和环境版本；
- 输入契约的验收状态。

复制期间源文件变化、必需结构缺失或范围契约失败时，运行记为 `input_rejected`。

## 3. 版本锁

主配置的关键契约为：

```yaml
protocol_version: "3.1"
text_label_guide_version: "text-cleaning-v1.1"
random_seed: 20260728

annotation:
  initial_probability_size: 500
  probability_min_per_platform: 80
  initial_targeted_size: 200
  initial_recheck_size: 200
  minimum_recheck_interval_days: 14
  minimum_recheck_raw_agreement: 0.80
  minimum_recheck_cohen_kappa: 0.70
  additional_recheck_size: 100

algorithm_versions:
  derived_schema: 31
```

规范化规则文件和文本运行时均绑定版本摘要。共享配置不得包含令牌、绝对路径、源库
路径、派生库路径或真实身份。

## 4. 任务图与增量语义

```text
只读快照 → 确定性文本处理 → 候选语料
         → 抽样与人工审核 → 最终审核参考集
         → 泄漏组与文本模型 → 候选清洗决定
         → 保留人口审计 → final 决定 → 确认重复关系 → 分析去重 → 发布
```

帖子阶段任务为：

```text
text_deterministic → text_relevance → finalize
```

标题、正文、状态或来源类型变化时三阶段重跑；作者身份变化影响泄漏分组及其下游；
互动量、URL 等分析字段变化只登记新版本。任务 ID 由运行、阶段、对象、源版本和有效
算法版本稳定计算。读取动作不得隐式重试失败任务。

## 5. 确定性文本处理

规范化依次执行 Unicode NFKC、不可见格式字符处理、换行/空白统一以及标题—正文
结构化组合。输出保存规范文本、结构状态、理由代码、规范 SHA-256、精确文本哈希、
运行时摘要和规则摘要。

确定性规则只排除双空、明确系统占位或不可恢复损坏。边界对象进入人工审核，短、
口语、广告式或普通表达不会被确定性规则直接排除。字符 n-gram 相似度只生成近重复
候选，不能直接合并或删除帖子。

## 6. 抽样、审核与稳定性

### 6.1 数据契约

公开 CSV 使用 `review_round` 表示初审或复核，数据库历史字段
`assignment_slot` 只承担轮次存储，不承担人数语义。导入器执行：

- 样本成员和帖子版本核验；
- 结构—旅游标签条件约束；
- 受控枚举、身份哈希和带时区 UTC 时间校验；
- 第二轮必须已被抽中，且相应第一轮存在；
- 第二轮时间不得早于第一轮加 `minimum_recheck_interval_days`；
- 记录只追加，重复文件按内容哈希幂等复用。

身份哈希只用于谱系；轮次资格由抽样、时间间隔和证据完整性约束。最终审核 CSV 使用
`final_review_id`、`reviewer_hash`、`evidence_review_ids` 和 `reviewed_at_utc`。

### 6.2 稳定性评估

结构轴对全部完整复核对计算，旅游轴排除结构不适用对。结果包含原始一致率、
Cohen's κ、完整对数量、门槛状态和指标 manifest。门槛未通过时创建固定 100 条的
补充复核运行；补充成员和状态一经封存不可修改。

该指标在方法报告中解释为时间稳定性，不生成或声称跨审核者一致性。

## 7. 最终审核参考集与模型

两轮分歧、`uncertain`、近重复边界或模型边界对象通过追加式最终审核确认。训练入口
只接收显式 `reference_review_ids` 清单，拒绝隐式选择“最新”记录。

字符 n-gram TF-IDF + LinearSVC 基线先按作者、精确重复和人工确认近重复建立泄漏
分量，再做时间/平台约束切分。正式与 smoke 模式严格分离；smoke 受核心 API 硬上限
限制，不能冒充正式模型。模型只形成候选动作与人工复核队列，不覆盖人工证据。

## 8. 决定、审计与发布

最终概念条件为 `usable + related`。决定顺序不可绕过：

```text
候选决定 → 候选 keep 人口 → 至少 300 条概率审计 → final 决定
```

审计报告总体残余错误率及单侧 95% Wilson 上限。失败时必须修订规则或模型并重新
冻结人口；不得把失败状态直接改为通过。

发布集合只有：

- `analysis_posts_eligible`：final 决定为 keep 的全部帖子版本；
- `analysis_posts_deduplicated`：确认重复分量中的稳定代表。

formal 发布必须显式绑定 `run_id`、`release_id`、源快照、配置、代码、人工证据、
审计评估和成员 manifest。不存在随数据库状态变化的“最新发布”。

## 9. Schema 兼容说明

schema v31 新增复核间隔与中性公开契约。为避免在同一版本改造中破坏既有 SQLite
谱系，部分底层表名仍含 `annotation`、`adjudication`、`double_label` 或 `gold` 等
历史名称；这些名称不构成研究设计声明。对外 CLI、CSV、配置和方法报告统一使用
审核、复核、最终确认与参考集语义。旧派生库不得就地解释为 v31，须从只读快照重建。

## 10. 主要命令

```bash
.venv/bin/python scripts/cleaning_snapshot_source.py \
  --source-db <SOURCE_DB> --derived-db <DERIVED_DB> \
  --config configs/cleaning-v3.1.yaml --run-id <RUN_ID>

.venv/bin/python scripts/annotation_export_tasks.py \
  --derived-db <DERIVED_DB> --config configs/cleaning-v3.1.yaml \
  create-initial --candidate-build-id <BUILD_ID>

.venv/bin/python scripts/annotation_export_tasks.py \
  --derived-db <DERIVED_DB> --config configs/cleaning-v3.1.yaml \
  export-post --sample-run-id <SAMPLE_RUN_ID> \
  --review-round 1 --output <ROUND_1.csv>

.venv/bin/python scripts/annotation_export_tasks.py \
  --derived-db <DERIVED_DB> --config configs/cleaning-v3.1.yaml \
  export-post --sample-run-id <SAMPLE_RUN_ID> \
  --review-round 2 --output <ROUND_2.csv>

.venv/bin/python scripts/annotation_import_annotations.py \
  --derived-db <DERIVED_DB> --input <FILLED.csv> \
  --config configs/cleaning-v3.1.yaml --imported-by-hash <HASH> \
  post-reviews

.venv/bin/python scripts/annotation_adjudicate.py \
  --derived-db <DERIVED_DB> --config configs/cleaning-v3.1.yaml \
  stability --sample-run-id <SAMPLE_RUN_ID>

.venv/bin/python scripts/text_train_relevance.py \
  --derived-db <DERIVED_DB> --candidate-build-id <BUILD_ID> \
  --leakage-build-id <LEAKAGE_BUILD_ID> \
  --reference-review-ids <REFERENCE_ID_FILE> \
  --artifact-directory <ARTIFACT_DIR> \
  --config configs/cleaning-v3.1.yaml formal --execute-formal-training
```

命令只输出去敏 ID、状态、计数和哈希；异常不得输出正文、作者标识、源路径或凭据。

## 11. 验证与报告边界

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m compileall -q src scripts tests
git diff --check
```

只有正式审核、延时复核、最终确认、模型评估、保留集审计和 formal 发布验收完成后，
才能报告真实清洗比例、稳定性指标、模型指标和最终样本量。工程回归与合成记录只证明
接口和约束可运行。
