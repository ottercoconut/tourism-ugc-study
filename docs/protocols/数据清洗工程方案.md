## 1. 工程边界

1. 正式采集数据库始终只读。`exclude` 只表示不进入派生分析发布，不得删除或覆盖源记录。
2. 模型输入只有按冻结规则生成的规范化文本。`platform_key` 只保留为来源谱系字段，不得进入特征、切分、阈值、审计配额或性能门。
3. 训练、阈值策略和推理是三个解耦阶段：训练产出不可变模型与校准器；阈值策略独立冻结；初始全量和未来新增批次调用同一冻结模型。
4. 已有人工标签以完成 CSV 与 manifest 为权威源，不复制到 `text_post_annotations`。
5. 人工处理结果优先于模型路由；任何自动动作都必须能追溯到模型、策略、输入批次和输出 manifest。

配置解析必须拒绝未知字段、缺失字段、非有限概率和不满足 `0 <= T_keep < T_exclude <= 1` 的策略。任一阈值或正式门仍为 `UNSET` 时，只允许输出概率并把所有未有人工作答的记录路由到人工处理，不允许自动保留或自动排除。

## 4. 训练与校准契约

### 4.1 泄漏分组和测试冻结

作者、精确重复和最终确认的近重复关系通过传递闭包组成泄漏分量。全体参考记录按时间选择最后 20% 为测试候选，再扩展到候选连接的完整泄漏分量。扩展后的测试集一次冻结，最终比例允许高于 20%。剩余数据进行全局分组分层训练/验证切分；平台不参与任何名额分配。

测试集不得用于词表拟合、特征选择、超参数搜索、Sigmoid 校准、阈值选择或失败后的反复调参。训练输出必须保存测试成员 manifest 和跨集合泄漏检查结果。

### 4.2 折外校准

首个正式模型为字符 TF-IDF 加固定 `C=1.0`、`class_weight=balanced` 的线性 SVM。训练部分内部最多使用五折相同泄漏分组交叉验证；如分量结构不能支持五折，实现在不低于两折且每个拟合端、留出端都含双类的范围内下降折数，否则失败关闭。每条训练记录只获得其未参与拟合的一个折外决策分数；无正则一维 Sigmoid 校准器只以这些折外分数和训练标签拟合。随后以完整训练部分拟合最终向量器和 SVM，冻结向量器、分类器、校准器、规范化规则和依赖环境。该 baseline 不执行 C 搜索，避免在尚未定义模型选择门时引入隐式调参。

校准器输出 `p_unrelated`，其值必须为 `[0, 1]` 内有限数。训练运行包保存训练折外概率和验证集概率；验证报告包括总体 Precision、Recall、F1、PR-AUC、混淆矩阵、Brier score 和 log loss，其中 `0.5` 只用于诊断分类指标，不是路由阈值。训练阶段的测试集状态固定为 `locked_not_opened`，不生成测试概率或测试指标。阈值策略冻结后，测试报告再包括总体指标、阈值表现、自动覆盖率和时间切片，不生成平台分类指标。

### 4.3 不可变模型 artifact

模型运行包至少保存：

- `model_id`、artifact SHA-256 与创建时间；
- 参考 CSV、参考 manifest、源快照和成员 manifest 的哈希；
- 规范化规则、字符 TF-IDF、线性 SVM、Sigmoid 校准器及其参数；
- 泄漏分组、训练/验证/测试成员与随机种子；
- Git SHA、Python 与关键依赖版本；
- 总体测试输出和机器可读验收状态。

artifact 一旦冻结不得原地覆盖。新增记录的到来不触发 `fit`，也不替换 artifact。

## 5. 独立阈值策略契约

阈值策略是与模型分离、不可变并可哈希的 artifact，至少保存：

- `policy_id` 和策略内容 SHA-256；
- 所绑定的 `model_id`；
- `T_keep`、`T_exclude`；
- 保留集审计的事件定义、样本量、事件率门、单侧置信上限和区间方法；
- 最低测试指标、最低自动覆盖率和审计失败后的恢复条件；
- 决策依据、冻结时间和适用批次边界。

调整阈值只能创建新 `policy_id`，不得重新训练模型、覆盖旧策略或改写已完成运行。策略必须满足：

```text
p_unrelated <= T_keep             -> auto_keep
T_keep < p_unrelated < T_exclude  -> manual_review
p_unrelated >= T_exclude          -> auto_exclude
```

边界等号不得由实现自行改变。`auto_exclude` 只作用于派生发布状态。

## 6. 推理运行与预测契约

初始全量与未来新增批次共用独立推理入口。入口只允许加载一个已冻结模型和一个与其兼容的阈值策略，不得调用任何训练或校准方法。目标批次必须先完成结构门和同版规范化。

推理前以冻结身份集合排除已有人工标签的 700 条记录；这些记录不生成模型路由，最终决定直接来自权威 CSV。其余记录逐条保存：

- `inference_run_id`、`model_id`、`policy_id`、目标批次 ID；
- 冻结帖子身份与规范化输入哈希；
- `p_unrelated`；
- 原始路由动作与是否因降级状态转人工；
- 人工任务引用、最终决定来源和最终决定；
- 输入、预测和输出 manifest 哈希。

同一目标身份、模型和策略的重复运行应得到相同概率与路由。任何输入不兼容、模型哈希不符、策略未冻结或输出不完整都必须失败关闭。

## 7. 人工证据与最终决定

人工灰区、未来新增人工结果和保留集审计各自使用独立的任务 CSV、完成 CSV 与 manifest，不复用同一任务身份。人工结果覆盖模型建议：

- `related`：最终保留；
- `unrelated`：从派生分析发布中排除；
- `uncertain`：维持待处理，不进入正式发布。

人工标签仍由对应完成 CSV 与 manifest 保存。数据库只保存最终帖子决定，以及完成 CSV SHA-256、任务 ID、模型 ID、策略 ID、推理运行 ID 等证据引用；不得把 CSV 标签再批量复制到 `text_post_annotations`。源库始终只读。

## 8. 保留集审计与降级状态机

保留集审计从最终保留人口进行全局随机抽样，不设平台配额。事件定义、样本量、事件率门、单侧置信上限和恢复条件目前均为 `UNSET`。自动排除人口不执行常规随机审计。

未来实现至少包含以下状态：

1. `policy_unset`：允许打分；所有未有人工作答的记录转人工。
2. `automatic_routing_enabled`：三个区间按冻结策略执行。
3. `auto_keep_suspended`：保留集审计失败后，模型继续打分；原 `auto_keep` 转人工，`manual_review` 维持人工，`auto_exclude` 继续执行。
4. `recovered_with_new_policy`：只有新阈值策略满足冻结的恢复门后才可恢复自动保留；旧策略和旧运行保持不可变。

审计失败不得通过换 seed、删除不利样本或改写旧策略来消除。正式可靠性声明只覆盖最终保留语料的残留无关风险；过度删除仅由锁定测试集总体表现间接评估，不能表述为已做部署期排除人口审计。

## 9. 失败语义

以下情况一律停止自动决定并写出机器可读失败原因：参考 CSV 或 manifest 哈希不符、身份或文本不一致、泄漏分组跨集合、测试集被用于调参、模型或策略 artifact 不完整、概率非有限、阈值非法、推理尝试调用训练、人工结果冲突、源库出现写操作、审计门未设或审计失败后仍执行自动保留。

失败不删除中间证据，不覆盖既有运行。可恢复问题通过新的运行 ID 重试；改变阈值必须创建新策略，改变模型必须形成新的模型 artifact 和独立决策记录。

## 10. 实现顺序与验收

稳定配置、参考 CSV/manifest 校验器、500/200 样本迁移 manifest、独立内部 schema，以及训练/折外校准/不可变 baseline 运行包代码已经完成。后续按以下顺序进行：

1. 用现有候选构建封存作者、精确重复和最终确认近重复组成的泄漏分组；
2. 显式执行首次 baseline 训练，封存模型、校准器、切分、开发概率与验证指标；
3. 基于训练折外与验证证据讨论并冻结独立阈值策略、测试指标门、自动覆盖率门和审计门；
4. 冻结策略后只开启一次锁定测试集并完成模型/策略验收；
5. 实现不含 `fit` 的全量/增量推理入口及预测 manifest；
6. 完成人工覆盖、最终决定谱系和保留集审计状态机；
7. 运行完整测试、发布验收并统一正式化四份核心文档。

验收必须证明：700 条权威标签完整一致且不进入推理池；平台字段不进入模型决策链；全局时间测试与泄漏分组正确；折外校准不接触测试集；三个概率边界动作精确；增量推理不会调用 `fit`；人工结果覆盖模型建议；排除不删除源数据；保留集审计失败会暂停自动保留；恢复绑定新策略；HTML 可解析、Markdown 链接有效、`git diff --check` 和完整测试通过。

全部实现、阈值和验收完成后，本文件与科研方案、人工审核方法和简明指南统一改为 `CURRENT / FORMAL`。在此之前不存在可执行的正式自动清洗流程。
