# 文本数据清洗人工审核方法

> **状态**：`FRAMEWORK_FROZEN / THRESHOLD_PENDING / IMPLEMENTATION_PENDING`
>
> **稳定契约名**：`tourism-relevance-cleaning`
>
> **标签手册**：`text-cleaning-v1.5`
>
> **适用对象**：已经通过确定性结构门的帖子文本

本文件规定人工标签的语义、权威载体和后续人工任务。质量证据来自固定定义、冻结输入、可追溯任务、独立测试和保留集审计。

## 1. 人工任务只有一个判断

人工审核只回答：**这条文本是否以青岛的旅游活动、旅游体验、旅游资源或旅游决策为主要内容？**

任务表只使用一个标签字段 `tourism_label`：

| 值 | 含义 | 最终处理 |
|---|---|---|
| `related` | 主要内容直接涉及青岛旅游 | 保留 |
| `unrelated` | 主体不是青岛旅游 | 从派生分析发布中排除；不删除源数据 |
| `uncertain` | 可见文本不足以稳定判断，或文本存在影响判断的拼接污染 | 保持待处理，不直接进入正式发布 |

`uncertain` 是完成阅读后的明确判断，不设置最低数量，也不要求必须出现。空白只表示尚未完成，不是一种标签。任何校验、统计或后续处理都不得把空白与 `uncertain` 合并。

人工任务不增加结构标签、原因码、自由文本备注、逐行人员标识或人工操作时间。结构可用性由全量确定性规则记录；轮次完成时间、任务身份、成员清单和文件哈希由 manifest 保存。

## 2. 判断边界

### 2.1 标为 `related`

- 到访青岛的游览、度假、行程、攻略、路线或出行决策；
- 青岛的景区、海滨、博物馆、历史街区等被作为游览或体验对象；
- 住宿、餐饮、交通、购物等被放在青岛旅行或目的地体验中讨论；
- 对青岛目的地体验、服务、价格、拥挤、氛围或重游意愿作评价；
- 面向游客或公众开放的展览、节庆、演出、市集、赛事观赏等城市休闲活动，文本将其作为到访、游览或体验对象；
- 青岛旅拍、旅行摄影或其他明确服务于目的地体验与出行决策的内容。

### 2.2 标为 `unrelated`

- 地名只是背景，主体是日常生活、社会新闻、招聘、房产、金融或其他非旅游事项；
- 仅包含抓取关键词，但没有旅游活动、体验、资源或决策语义；
- 店铺或商品宣传没有可识别的旅游或目的地体验语境；
- 其他城市或目的地的旅游内容，未实际讨论青岛旅游；
- 面向商家招商、展会参展或渠道销售的推广，即使活动地点在青岛；
- 行业会议、供应链展销、产品发布或企业经营活动中，青岛仅是会址且文本不讨论游客体验；
- “青岛”等词指向品牌、机构或其他同名实体，而非旅游目的地。

### 2.3 标为 `uncertain`

- 文本虽已通过结构门，但上下文仍不足以确认地名或活动的真实指向；
- 同时存在旅游和非旅游解释，且没有一种明显占主导；
- 只有猜测作者意图才能二分；
- 可见文本由不连贯来源、主题或句段异常拼接而成，无法确定一个可审核的主要语义对象。

文本短、口语化、包含表情或观点普通，都不是单独判为 `unrelated` 或 `uncertain` 的理由。

## 4. 后续人工任务

冻结策略的完整路由为：`p_unrelated <= T_keep` 自动保留，`T_keep < p_unrelated < T_exclude` 进入人工处理，`p_unrelated >= T_exclude` 从派生分析发布中自动排除。人工结果始终优先于模型路由，自动排除不删除源数据。

### 4.1 人工灰区

当冻结阈值生效后，满足 `T_keep < p_unrelated < T_exclude` 的记录进入人工灰区。阈值尚为 `UNSET` 时，所有未有人工作答的记录都进入人工处理。任务选择过程可记录模型与策略身份，但作业表不展示模型概率或建议动作，避免这些信息成为判断依据。

灰区任务使用独立任务 ID、完成 CSV 和 manifest。完成标签覆盖模型建议：`related` 保留，`unrelated` 排除，`uncertain` 保持待处理。

### 4.2 最终保留集审计

达到正式自动路由条件后，从最终保留人口进行独立的全局随机抽样审计，不设置平台名额。审计任务与灰区任务使用不同任务 ID 和 manifest，作业表不展示记录是人工保留还是自动保留，也不展示模型概率或路由。

保留集审计的事件定义、样本量、最大事件率、单侧置信上限、区间方法和恢复条件目前全部为 `UNSET`。这些项目冻结前不得宣称审计通过。自动排除人口不执行常规随机审计。

### 4.3 未来新增记录

新增记录完成结构门和规范化后，使用同一个冻结模型直接推理，不因新批次而重新训练。进入人工灰区的新增记录及其保留集审计结果继续使用独立完成 CSV 与 manifest。数据库只保存最终决定和对应 CSV 哈希、任务身份、模型与策略引用，不成为人工标签的新权威副本。

## 5. 作业与封存规则

1. 只根据导出表中的 `normalized_model_text` 判断，不把平台、作者、热度或模型输出作为决策依据。
2. 每行只填写 `related`、`unrelated` 或 `uncertain`；不确定时使用明确的退避值，不猜测补全。
3. 保存后先校验字段、值域、身份唯一性、文本哈希和完整性，再生成不可变的完成 CSV 与 manifest。
4. 完成 CSV 一旦封存不得原地覆盖。需要更正时生成带独立任务身份的新证据，并在 manifest 中引用被更正的记录。
5. 不执行“标签导入”来制造数据库副本。后续训练或决定过程按哈希直接引用完成 CSV。
6. 人工标签优先于模型建议；`auto_exclude` 仅影响派生发布，源库始终只读。

## 6. 质量保障与失败降级

人工证据的质量依据包括：固定标签定义、冻结规范化文本、完成 CSV 与 manifest 哈希、700 条身份和样本成员校验、概率样本的已知纳入概率、困难边界覆盖、作者及重复关系的泄漏隔离、锁定测试集总体指标，以及正式化后的全局保留集审计。

平台不进入模型、切分、阈值或审计配额。人工审核也不按平台建立性能判断。平台字段如为谱系需要保留，只用于来源识别与构成披露。

保留集审计失败时，模型仍可输出 `p_unrelated`，但自动保留暂停，原自动保留区间转入人工处理；人工灰区和自动排除仍按冻结策略运行。恢复自动保留必须绑定新的阈值策略和已冻结的恢复门，不能改写旧任务或更换抽样结果以追求通过。

由于不常规抽审自动排除人口，正式可靠性声明只能表述为“最终保留语料的残留无关风险受控”。避免过度删除的证据来自锁定测试集的总体 Precision、Recall、F1、PR-AUC、混淆矩阵和阈值表现；论文必须明确这不是部署期排除人口的直接审计。

## 7. 报告要求

论文和运行摘要至少报告：候选人口及来源构成、结构门结果、700 条完成标签的实际计数、500 条概率样本与 200 条定向样本的不同用途、泄漏分组与全局时间测试方法、总体模型和校准结果、冻结阈值策略、三个路由的人口数量、人工处理结果、保留集审计结果、失败降级记录及最终纳入/排除数量。

平台只报告来源数量和样本构成，不报告清洗分类性能或稳定性差异。阈值和审计门如未冻结，必须原样报告为 `UNSET`，不得用测试通过或主观判断替代。

## 8. 正式化条件

当前 `T_keep`、`T_exclude`、保留集审计事件与样本量、事件率和置信门、模型最低测试指标、最低自动覆盖率及恢复门全部为 `UNSET`。代码框架、稳定配置、阈值策略和全部验收完成后，本文件与其余三份清洗核心文档统一改为 `CURRENT / FORMAL`；在此之前只允许人工决定或研究性概率输出。
