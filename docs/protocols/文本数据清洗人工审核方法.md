## 1. 人工任务只有一个判断

人工审核只回答：**这条文本是否以青岛的旅游活动、旅游体验、旅游资源或旅游决策为主要内容？**

任务表只使用一个标签字段 `tourism_label`：

| 值 | 含义 | 最终处理 |
|---|---|---|
| `related` | 主要内容直接涉及青岛旅游 | 保留 |
| `unrelated` | 主体不是青岛旅游 | 从派生分析发布中排除；不删除源数据 |
| `uncertain` | 可见文本不足以稳定判断，或文本存在影响判断的拼接污染 | 保持待处理，不直接进入正式发布 |

`uncertain` 是完成阅读后的明确判断，不设置最低数量，也不要求必须出现。空白只表示尚未完成，不是一种标签。任何校验、统计或后续处理都不得把空白与 `uncertain` 合并。

人工任务不增加结构标签、原因码、自由文本备注、逐行人员标识或人工操作时间。结构可用性由全量确定性规则记录；轮次完成时间、任务身份、成员清单和文件哈希由 manifest 保存。

## 2. 判断边界

### 2.1 标为 `related`

- 到访青岛的游览、度假、行程、攻略、路线或出行决策；
- 青岛的景区、海滨、博物馆、历史街区等被作为游览或体验对象；
- 住宿、餐饮、交通、购物等被放在青岛旅行或目的地体验中讨论；
- 对青岛目的地体验、服务、价格、拥挤、氛围或重游意愿作评价；
- 面向游客或公众开放的展览、节庆、演出、市集、赛事观赏等城市休闲活动，文本将其作为到访、游览或体验对象；
- 青岛旅拍、旅行摄影或其他明确服务于目的地体验与出行决策的内容；
- 文本能够识别出游客或新人自己的到访、拍摄、消费、路线调整、现场互动或事后评价。即使结尾推荐商家，只要主体仍是连贯的第一人称体验，也不因推荐语本身改判为广告。

### 2.2 标为 `unrelated`

- 地名只是背景，主体是日常生活、社会新闻、招聘、房产、金融或其他非旅游事项；
- 仅包含抓取关键词，但没有旅游活动、体验、资源或决策语义；
- 店铺、摄影机构、酒店、票务、租车或商品的纯宣传，没有可识别的游客本人到访或目的地体验；榜单、机构推荐、价格套餐、限时折扣、预订号召和“避坑指南”等外壳不能单独构成 UGC 体验；
- 其他城市或目的地的旅游内容，未实际讨论青岛旅游；
- 面向商家招商、展会参展或渠道销售的推广，即使活动地点在青岛；
- 行业会议、供应链展销、产品发布或企业经营活动中，青岛仅是会址且文本不讨论游客体验；
- “青岛”等词指向品牌、机构或其他同名实体，而非旅游目的地。

### 2.3 标为 `uncertain`

- 文本虽已通过结构门，但上下文仍不足以确认地名或活动的真实指向；
- 同时存在旅游和非旅游解释，且没有一种明显占主导；
- 只有猜测作者意图才能二分；
- 可见文本由不连贯来源、主题或句段异常拼接而成，无法确定一个可审核的主要语义对象。

文本短、口语化、包含表情或观点普通，都不是单独判为 `unrelated` 或 `uncertain` 的理由。

“像广告”不能只凭语气判断。审核必须寻找可核对的游客经历链，例如出发或到访、场景选择、过程互动、临时变化、消费使用和事后感受；只有机构自述、榜单推介、套餐报价或购买号召而没有经历链时，才按纯广告标为 `unrelated`。作业表不得显示平台或作者身份，因此这里的“游客身份”只由文本内容证明。

## 3. 最终700条不重复建模参考集

稳定契约名为 `final-nonduplicate-model-reference`。只有一份恰好700条的最终 CSV 和其唯一配对 `finalized` manifest 是最初参考集的权威标签证据。旧完成 CSV、旧 manifest、重复候选、人工决定、候补队列和补充标注只用于生成谱系；训练不能直接读取它们。旧模型自动化状态为 `LOCKED_TEST_FAILED_MANUAL_ONLY`，不改变最终参考证据的权威性。新周期另将final 700、Wave A 240和Wave B 360封存为1,300条训练快照，不物理改写原700条CSV。

重复复核与旅游相关性标注是两项独立判断。重复复核只比较两端 `normalized_model_text` 是否表达同一份可建模内容，不查看或推断 `tourism_label`。精确规范哈希相同自动成组；字符3–5 gram TF-IDF相似度 `>=0.80` 只产生候选，不能自动删除。人工明确识别的低于0.80关系可以显式补入。所有确认边形成稳定连通分量；组内标签冲突必须另行最终确认。

人工判断采用“同一文本载荷”标准：只有近复制、转载、编辑或删节形成的同一份主体文本，且差异仅为格式、时间戳、计数、链接、广告、少量开头结尾或其他非实质附属内容，才填 `duplicate`。独立撰写的文本即使报道同一事件、陈述同一事实、列出相似地点或清单主题，也填 `not_duplicate`；主要行程、事件、观点、对象或信息集合不同当然也填 `not_duplicate`。同一地点、主题、模板、固定栏目、大量通用措辞或高相似度均不能单独证明复制关系。这一口径与近重复网页研究对“小而无关差异”的定义一致；内容抽取研究也表明元数据与附属结构会显著干扰重复检测（[Manku et al., 2007](https://doi.org/10.1145/1242572.1242592)；[Gibson et al., 2008](https://aclanthology.org/2008.wac-1.5/)）。因此0.80是本语料的候选召回门，不是论文给出的通用语义判定线。

进入复核前，正文必须先从冻结源快照重投影。Quill Delta JSON 只保留字符串 `insert` 的顺序文本；格式属性、图片和截断节点不得出现。若作业表仍出现 `"attributes"`、`"insert"` 或 `"ops"` 结构片段，应停止标注并报告 artifact 身份，不能把结构污染当作正文继续判断。

初始700条的每个确认重复分量只保留一个建模代表，被排除成员仍保留在源库和谱系。全部成员优先选择规范化文本更完整者，再按稳定源身份决胜；样本框、平台与旅游标签均不参与代表选择。由此产生的 probability/targeted 缺口交给后续候补调度恢复。仅由候补组成的确认重复分量沿用同一代表规则；与既有代表确认重复的候补不得计数，且不会重新抽样既有代表。

去重缺口通过读取标签前冻结的全局候补队列补足。候补在人工旅游相关性标注前，必须与初始700条全部谱系成员（包括已排除的重复成员）和同轮候补完成相同重复检查；候补若连接任一历史成员，就沿初始确认分量传播到其建模代表。每次扩展冻结前缀后，还必须把既有代表标签与累积候补标签投影到新的确认重复分量；出现 `related`/`unrelated` 冲突时失败关闭并要求人工最终确认。前轮标签只随同一帖子身份携带，不能因确认重复而自动转移给新代表；新代表必须单独完成旅游相关性标注，除非人工冲突确认已显式给出该分量最终标签。结构不可用、确认重复、重复候选待决定、空白或 `uncertain` 标签均不能计入700条，继续按冻结秩处理。最终框身份仍为500条 `probability` 和200条 `targeted`。

若概率框发生补样，替换项不得沿用被替换记录的纳入概率或权重。只有证明冻结补样设计的联合纳入概率后才能用于总体估计；无法证明时 manifest 必须明确标记总体估计不可用。所有记录仍留在完整候选人口和派生库，不得回写或删除源记录。

## 4. 后续人工任务

冻结策略的完整路由为：`p_unrelated <= T_keep` 自动保留，`T_keep < p_unrelated < T_exclude` 进入人工处理，`p_unrelated >= T_exclude` 从派生分析发布中自动排除。人工结果始终优先于模型路由，自动排除不删除源数据。

## 5. 作业与封存规则

1. 重复复核只比较两段规范化文本，填写 `duplicate` 或 `not_duplicate`；不能从旅游标签、平台、作者或模型输出来推断重复。
2. 补充旅游相关性标注只根据 `normalized_model_text` 填写。能够二分时填写 `related` 或 `unrelated`；确已阅读但不能稳定二分时可把该任务以 `uncertain` 封存为生成谱系，但它不得计入最终参考集，下一轮继续按原冻结队列扩展候补。空白任务不得封存。
3. 每个待处理CSV必须与manifest绑定；先制作独立可写工作副本，完成后另行校验和封存完成表。四列表没有逐行`finalized`字段，不得擅加列；完成状态由配对manifest记录。旧参考集的补充候选不能直接成为训练标签源。
4. 所有 artifact 内容寻址、不可变且可幂等复用；同一身份出现不同内容时失败关闭，不得原地覆盖。
5. 不执行标签导入来制造数据库副本。最终700条由训练入口按哈希直接读取；源库始终只读。

## 6. 质量保障与失败降级

人工证据的质量依据包括：固定标签定义、冻结规范化文本、244,650个完整无序对、人工最终重复决定、稳定连通分量与代表、确定性候补队列、最终 CSV/manifest 哈希、700条唯一身份、500/200框、明确的概率估计状态，以及训练前作者 leakage build。

平台不进入模型、切分、阈值或审计配额。人工审核也不按平台建立性能判断。平台字段如为谱系需要保留，只用于来源识别与构成披露。

任一尾部审计失败时，原策略的对应自动动作暂停并转入人工处理；不能改写旧任务、
换seed、更换样本或追加样本来稀释失败。当前0.31/0.96没有修改旧策略，而是以新
策略ID、选择后风险披露和研究者接受依据形成新谱系；该例外只适用于精确绑定的
当前策略，不能推断其他阈值也获授权。

正式报告分别披露“自动保留人口的残留无关风险”和“自动排除人口的UGC误删
风险”。当前0.31/0.96的Wave B OOF保留端为14/141原始不利事件、设计加权
3.28%，排除端0/89；最后300条对应子样本为9/144与0/150。不得把0事件写成
总体误差为0，也不得把选择后结果写成独立验证或外推到未来批次。

## 7. 报告要求

论文和运行摘要至少报告：候选人口及来源构成、结构门结果、完整全对数、阈值候选数、精确与人工确认重复分量、补样数量、最终700条标签和500/200框、概率估计有效性、作者 leakage build、全局时间测试、总体模型与校准结果，以及后续路由和审计结果。

平台只报告来源数量和样本构成，不报告清洗分类性能或稳定性差异。审计按两个动作尾部抽样，不设置平台配额；不得用平台分层结果替代全局尾部判读。
