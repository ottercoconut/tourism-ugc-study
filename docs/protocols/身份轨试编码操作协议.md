# 身份轨试编码操作协议

> 适用对象：第一次参加本项目的两位编码员及研究负责人
> 对齐标准：编码表 v3.16.0；角色规则：role-pilot-v0.2-draft
> 协议版本：v1.0；编写日期：2026年9月7日
> 用途：25名作者共同校准的独立操作说明，先做5名再讨论。当前仍为试点，不表示身份规则已经完成正式验证。

## 1. 先了解这项任务

我们要根据一个账号在指定时期留下的资料，判断它怎样持续参与旅游内容创作。这项工作叫“身份编码”。你只需要阅读发下来的材料、按规则选择答案，不需要写程序、判断作者是否出名或猜研究者期待的结果。

一名作者的一套固定资料是一个任务。即使资料中有五篇帖子，也只完成一份作者判断，不算五名作者。当前身份任务只包括小红书和知乎。

你会依次回答七组问题：谁在运营账号、主要写什么、有无专业权威、有无消费者经验与同伴导向、是否持续创作、证据是否充分、最终属于哪种角色。前面的分项和最后的总体角色都由你填写，表格不替你算答案。

**工作顺序：读完整套作者材料 → 逐项填值和证据编号 → 拿不准才标? → 完成本批并交表 → 保存双人原始答案后讨论 → 按统一说明做下一批。**

### 开始前应拿到什么

- 本协议、自己独立的作者工作簿及本批任务编号。
- 每个任务对应的作者证据包，包含材料编号、日期和可阅读的内容。
- 编码簿、允许使用的材料说明、交表位置、截止时间与负责人联系方式。

检查工作簿的基础版本是否为v3.16.0，是否有EA和CE总体判断、持续创作、证据状态及最终角色，是否采用可选疑问标记。若缺字段、材料打不开或只发了空模板，先联系负责人，不自行修表或补搜材料。

同批交表前，只看自己的答案。材料打不开、不会操作可以问负责人；具体标签先独立判断。规则澄清必须由负责人同时发给两位编码员。

## 2. 读材料时守住哪些边界

**只看发下来的作者证据包。** 包中的主页和历史内容是本次判断依据；不要搜索新帖子、登录作者主页补资料，也不使用AI建议。主页链接只作来源定位，不能因为看见链接就自行打开实时网页扩充材料。

**粉丝与互动不用于推断角色。** 高粉丝不能单独证明KOL型，低粉丝不能证明KOC型。不要查看文本或图片轨答案、目标帖互动量和模型结果。若包中意外显示这些信息，报告负责人统一处理，不抄入判断依据。

**读同一作者的全部材料，再下结论。** 不凭第一篇帖子的文风、昵称中的“专家”或单次旅行体验决定角色。同名或头像相似的账号不自行合并。

**分清内容日期与抓取日期。** 来源的原始发布时间和负责人收集资料的日期不是一回事。按包中说明使用指定时期和获准材料；标为排除或仅作敏感性参考的资料，不拿来单独支持主判断。遇到日期缺失、账号身份前后冲突或资料超出窗口，报告具体编号，不自行推定时间。

这项任务通常把作者证据称为T0，把后续研究的目标帖子称为T1。你无需计算窗口或时间差；负责人应预先说明哪些材料可用。关键时间关系无法确认时，相关判断可以保留未知，不能把现在的主页状态当成作者过去一直如此。

### 常见答案的意思

| 表中答案 | 怎样理解和使用 |
|---|---|
| 1 | 这个字段有满足定义的证据 |
| 0 | 这个字段适用，且有足够材料支持“该特征未成立”；不是“没看到就填0” |
| UNK | 应当判断，但材料或关键条件不足以给出确定答案；只用于允许该值的字段 |
| NA | 不适用；例如机构或多人账号不适用个人角色分类 |
| 标签格空白 | 尚未完成，不作为未知答案 |
| 疑问栏空白 | 没有主动疑问，正常保留空白 |

不是所有字段都能填以上所有值。主体、内容方向、证据状态和最终角色各有自己的选项。身份最终角色没有UNRESOLVED；不要照搬图片或文本试编码的临时答案，也不要自行新增“其他角色”。

## 3. 按七步完成一名作者

### 第一步 谁在运营账号

在主体性质actor_scope中，选择单一自然人PERSONAL_CREATOR、机构ORGANIZATION、多人运营MULTI_AUTHOR或主体不清UNCLEAR。营销语气本身不能证明是机构；用第一人称也不一定证明是单一自然人。

机构和多人账号的最终角色填NA，证据状态填OUT_OF_SCOPE；主体不清时最终角色填UNK。其余字段按工作表明确的适用规则填写，不能为填满表格而编造EA或CE证据。如果不适用字段没有对应的合法填写方式，标明问题交负责人统一处理，不自行造代码。

### 第二步 账号主要持续写什么

根据整包内容判断，不用一篇偶然的旅游帖子代表整个账号。

| 选项和代码 | 普通话理解 |
|---|---|
| 旅行 TRAVEL | 旅行、目的地或旅游决策是持续主线 |
| 美食 FOOD | 餐饮、探店或烹饪是主线，旅游不是主导 |
| 生活方式 LIFESTYLE | 生活方式是主线，旅行只是其中一部分 |
| 综合 GENERAL | 多领域并列，没有稳定主导领域 |
| 其他 OTHER | 有稳定主线，但不属于上面几类 |
| 未知 UNK | 可用内容不足以判断 |

### 第三步 判断专业权威EA

逐项核对下面五类证据，并填写总体EA。相关领域限旅游、旅行、目的地体验及直接服务旅行决策的本地餐饮、亲子、户外和生活方式内容。

| 证据类别及代码 | 看什么 |
|---|---|
| 资历 EA_CREDENTIAL | 有与相关领域匹配、可核对的资历或资格资料 |
| 职业 EA_DOMAIN_OCCUPATION | 资料显示从事相关领域职业 |
| 领域认证 EA_DOMAIN_VERIFICATION | 认证具体指向相关领域身份，不是一般平台等级或普通认证 |
| 机构关联 EA_INSTITUTION_AFFILIATION | 有与相关专业机构的可核对关联 |
| 持续专业内容 EA_SPECIALIST_HISTORY | 多条历史材料持续体现相关领域专业内容，不能只凭单篇“写得专业” |

前五类任一有满足定义的证据，才支持总体EA=1。原子证据和总体值都要人工填写；多个阳性代码可并存。只有材料覆盖达到第4节条件、且确实支持没有发现专业权威时，才使用EA_NONE并填总体EA=0。不能判断时使用EA_UNK和总体EA=UNK。EA_NONE、EA_UNK不能与阳性代码混填。

这些短句帮助你查找材料，不替代编码簿的边界说明。职业是否属于相关领域、持续专业内容是否成立仍拿不准时，标?说明具体困难。

### 第四步 判断消费者经验与同伴导向CE

分别回答两个问题：一是有没有至少两个不同日期、不同来源中的第一手旅行或消费经历，对应CE_FIRSTHAND_REPEAT；二是有没有持续向其他普通用户提供经验或建议，对应CE_PEER_ORIENTATION。

两项都成立才支持总体CE=1。转述别人经历不等于第一手经验；单篇中说“我每年都来”不等于包内已有两个不同日期的来源。一篇很长的攻略也不拆成多次独立经历。

仅发现其中一项时，保留实际成立的条件，继续判断另一项；不能自动把总体CE填1，也不能仅因没找到另一项就填0。材料覆盖充分且支持CE未成立时才填0；关键材料不足时填UNK。CE_NONE、CE_UNK与阳性代码不能混填，具体代码位置按工作表使用。

### 第五步 判断持续创作SC

人工核对旅游相关来源的日期和数量。SC=1要求至少3个不同日期的旅游相关来源，最早与最晚相隔至少30天。不同文件如果其实是同一来源，不重复计数；同一天发三篇不满足三个日期。

日期或历史覆盖不足时，不能凭印象补足持续创作。根据允许值保留UNK；只有有充分材料支持不成立时才填0。软件预填的日期只是阅读材料，SC答案仍由你填写。

### 第六步 判断证据是否充分

证据状态evidence_status选择：足以完成关键角色判断的SUFFICIENT；关键身份、日期或材料不足的INSUFFICIENT；机构或多人账号等不适用个人角色比较的OUT_OF_SCOPE。

有简介、有三篇帖不自动等于充分。应检查是否能说明主体、EA、CE、SC以及相关时间关系。无法确认账号连续性、时间冲突或关键判断仍未解决时，不把证据状态写成充分。

### 第七步 直接填写最终角色

先完成上面各项，再参考下表人工填写creator_role_manual。前四类共同要求：单一自然人、证据充分、SC=1。

| 最终角色 | 前四类的EA与CE组合 | 含义或处理 |
|---|---|---|
| KOL_TYPE | EA=1，CE=0 | 专业权威成立，消费者同伴导向不成立 |
| KOC_TYPE | EA=0，CE=1 | 专业权威不成立，消费者同伴导向成立 |
| HYBRID | EA=1，CE=1 | 两种取向都成立 |
| ORDINARY | EA=0，CE=0 | 只表示未落入前三种型别，不等于“普通游客” |
| UNK | 不使用上述组合归类 | 主体不清、关键证据不足、SC=0或关键组件未决 |
| NA | 不适用个人角色分类 | 机构或多人账号 |

不为凑齐类别改变答案。如果总体角色与前面的分项矛盾，先回看原证据；仍无法解决时标疑问。不能让程序或另一位编码员替你改成“应有的答案”。

## 4. 怎样记录证据和疑问

### 每个判断都能找到对应材料

在工作表对应的证据位置填来源编号，例如E01；多个编号使用英文半角竖线连接，例如`E01|E03`。可以重复引用同一证据支持相关字段，不需要重复复制整段正文。

同一个作者包可能有不同证据支持不同字段。不要整行只填一个笼统的“见材料”；应让负责人知道每项依据在哪里。无相关材料时不编造来源编号，按表格的缺失方式记录，并说明缺口。

正常判断只填必要标签及证据编号。拿不准时在对应字段标?，本行疑问说明写“字段＋困难”，例如“EA：简介自称专家，包内没有可核对的资历”。多项疑问可以用同一栏中的几个短句，不另填独立问题表。若有合理备选答案，写进简短说明即可。

### 填0前特别检查一次

EA_NONE或CE_NONE只在证据包覆盖至少3个不同日期、跨度至少30天，并含可用主页或等价身份材料时才允许考虑。达到这个材料门后，仍要阅读内容才能判断；它不自动产生0或证据充分。

材料达不到覆盖要求时，相关缺失不能当作阴性证据。阴性判断可以引用支持覆盖情况的实际材料编号，不需要捏造一句“作者没有专业资质”作为反证。

**例子：** 包内只有一段简介和一篇旅行帖，未见相关职业。不能因此填写EA_NONE、CE_NONE或ORDINARY；关键证据不足时，按字段填写未知，最终角色用UNK，并说明“历史来源不足”。

### 这些内容不用填写

不逐项打1—5级置信度，不为每个正常答案写解释，不手写JSON、文件哈希或时间差，不逐条计时。社群关系community_relation_status固定为UNAVAILABLE，保持原样；缺少社群关系资料本身不使本轮角色证据变成不足。

触达规模reach_tier与角色分开。角色主表锁定前不查看或填写粉丝档位；若后续安排触达记录，由负责人另发材料，不能回头改变已锁定的角色判断。

## 5. 用四种情况检查自己是否理解

以下均为虚构教学情况，不是真实待编码作者，也不预先提供试编码样本答案。

| 材料情况 | 可作出的判断 | 为什么 |
|---|---|---|
| 只有一篇旅行体验，其余历史缺失 | 不能仅凭该帖判KOC型；关键证据不足时最终角色UNK | 第一手经历、重复经历、持续创作是不同条件 |
| 个人账号有明确相关职业，也持续分享自己的消费经验和同伴建议；其他证据充分、SC=1 | 若EA与CE均成立，最终角色HYBRID | 专业权威和消费者导向可以同时存在 |
| 资料明确是景区官方机构账号 | 主体ORGANIZATION；证据状态OUT_OF_SCOPE；最终角色NA | 不适用个人角色分类，不是资料未知 |
| 个人账号材料充分，SC=1，EA与CE都能据充分材料判0 | 最终角色ORDINARY | 这是本研究的剩余类型，不证明作者是普通游客 |

**日期练习：** 三条相关、独立来源分别发表于6月1日、6月18日和7月5日，满足三个日期和至少30天跨度；只有6月1日同一天的三条来源则不满足。这个练习只检查SC的日期条件，不直接决定EA、CE或最终角色。

发现规则尚不能支持唯一判断是本次试做的重要结果。身份表仍按自己的合法值填写；最终角色无从确定时用UNK并说明，不能把UNRESOLVED作为新角色加入。

## 6. 交表和讨论怎么做

### 交表前自查

- 本批作者均已处理，必需的人工分项、总体判断、证据状态和最终角色没有漏填。
- 各项证据编号能在对应作者包中找到；没有用缺失资料强行填0。
- 每个?有对应的短句说明；没有疑问的栏目保持空白。
- 原有编号、日期和版本未改动，没有看另一人的答案。

文件另存为提交副本，例如身份_第1批_编码员A_20260907_首次提交.xlsx，交到指定位置。不要覆盖旧答案。发一条短消息即可：“编码员A，第1批，已处理5名；材料问题编号：无。”有打不开或缺材料的任务，换成实际编号。

负责人先保存两份独立原始文件，再展示分歧。讨论从原始材料出发，依次说明“看到什么、怎样理解规则、哪里不能解决”。优先处理真实分歧和已有疑问，不逐个要求编码员复述所有正常答案。

讨论结果另行记录，原始答案不改成一致。涉及最终角色、反复出现的概念边界或需要改规则的分歧，按现行规范交第三人裁决；负责人保留逐字段裁决记录。关键问题未解决时保留未决，最终角色按规则为UNK；机构或多人账号仍为NA。

同批过程中不边讨论边互改答案。下一批开始前，负责人把生效规则同时发给两人。如果只澄清表达，写明澄清内容；如果改变判断边界，负责人明确哪些已做任务受影响，编码员按安排处理。

## 7. 负责人执行安排

本节由负责人使用。编码员不负责抽样、版本管理、数据库处理或制作作者证据包。

### 先准备合规材料

从小红书和知乎中，通过最低材料可用门的作者抽取25名：15名历史丰富、5名边界、5名从其余可用作者随机抽取。最低材料门只要求稳定作者键及可审计主页或等价身份材料，不要求预先达到3日期／30天，不按预期角色或预判证据充分性筛样。

每名作者最多展示5篇历史内容，超过时按既有最早、最晚和时间分位点规则选取。作者与同轮文本任务作者互斥，T0身份来源与T1研究目标帖不重叠。保留材料不足和边界作者，不为了凑角色组删掉未知情况。

旧v3.13.0双任务包不能只改版本号发出。须复核平台范围、重新抽取身份样本并准备符合v3.16.0的两份作者工作簿，确保原子证据、EA／CE总体值、SC、证据状态和最终角色都可人工填写。

发包前明确共同的证据窗口、目标期和时间使用规则；来源须有编号，发布日期与抓取日期分开。技术检查、材料去重、禁止信息遮蔽和可用来源标识由负责人完成，不能交给编码员临时决定。日期条件未明确时可识别材料缺口，但不能把未审定材料当成已满足主分析条件。

### 分批推进

| 阶段 | 数量或安排 | 负责人做什么 |
|---|---|---|
| 入门演示 | 使用本协议虚构情况 | 演示查选项、填证据编号、标疑问，不展示待独立编码作者的参考答案 |
| 第一批 | 从计划内25名中先做5名 | 尽量包含历史较丰富和边界情况，两人完成同一批后保存原始文件并讨论 |
| 后续批次 | 剩余20名，可按每批5名安排 | 按真实工作量调整；规则澄清统一发出，原始文件不覆盖 |
| 共同校准收尾 | 总计25名 | 汇总重复边界、材料缺口和裁决结果，保留规则修订记录 |

第一批包含在25名之内，不额外加样。若某批耗时较长，按实际进度继续，不通过漏填字段或减少必要证据节省时间。过程记录沿用现有问题清单，编码员不重复填写行政表。

### 后续阶段与交付边界

共同校准不计算正式信度。负责人按既有安排核读并完善15—25篇聚焦文献矩阵，区分文献依据与本研究自定义规则，结合校准结果修订并冻结role-pilot-v0.2。之后另取50名未讨论作者开展独立盲试标；本协议不把该后续任务并入当前25名工作量。

正式角色比较仍按编码表执行平台内证据、信度和组别支持要求；达到最少人数不自动证明分析充分。本文不重设计这些条件，也不把完成操作协议当成人工编码已经通过。

负责人保存的最少交付包括：本轮材料与版本清单、A和B独立原始答案、问题与修订记录、逐字段裁决记录。原始UGC、作者真实标识、数据库及受限证据包只保存在指定受控位置，不提交公开仓库。
